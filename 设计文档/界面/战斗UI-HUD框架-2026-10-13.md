# 战斗 UI/HUD 框架 v0.1

> **2026-10-13 修订提示**：主方案 R1～R3 取消了时间预算和"结束行动窗口"，并把格挡、闪避、防守改为无前后摇、整段生效。本文中涉及预算栏、账本等式、条件退款、结束窗口和反应固定区间的内容均已作废。屏幕结构与反应表达以 [HUD v0.3](战斗UI-HUD框架-v0.3.md) 为准；§4 暂停契约与 §5 多草稿仍然有效。

日期：2026-10-13。范围：正常游玩与主场景共用的战斗界面设计；本轮交付框架、交互规则和可操作草案，不修改战斗规则或现有场景。

用户已确认：**实时推进＋随时战术暂停，暂停时可规划**。这是新的产品交互要求；当前代码还没有实现战术暂停规划。本文件中的新增能力均为待实现设计，不以已有自动化测试作为完成证据。

## 1. 先解决什么

玩家随时应能回答：谁拥有当前行动窗口？我能为谁下令？还有多少预算？已经安排了哪些动作？哪个动作何时命中？时间现在有没有推进？我为何不能执行某项操作？

现有主场景通过了接入、确定性和回放验收，但正常游玩的可理解性和可操作性没有相应覆盖，应单独建立产品验收。

| 现象 | 当前实现依据 | 设计处理 |
|---|---|---|
| 无法整理两条以上指令 | `BattlePresentationView.SelectAction` 清掉前一草稿；`DraftAction` 每次只构建一个 Add 操作 | 动作配置器与多条草稿队列分开。添加第二条保留第一条；一次应用多个编辑 |
| 不知道是否已提交、是否还能改 | 点击确认清掉本地草稿；排程行只有 ID、状态和起止 Tick | 明确区分草稿、待采纳、可编辑、执行中与终态；反馈权威接受结果 |
| 看不出指令的时序 | `TimelinePlanView` 是按钮列表，拖动以 4px/Tick 隐式换算 | 共用时间刻度、单位分轨、动作阶段、命中标记、当前时刻线；拖动有吸附和精确值 |
| 单位不动但 Tick 一直增加 | `UnityBattleDriver.Advance` 按未缩放帧时间持续调用 Step；当前窗口不会因玩家没有点击而自动停止 | 战斗时钟用秒显示，并明确“进行中／等待行动／战术暂停”；Tick 收入诊断层。暂停时权威时钟停止 |
| 暂停后不能安排动作 | Model、CommandFactory、LogicPort 与按钮均以 IsPaused 禁止编辑/输入 | 系统暂停与战术暂停分型；后者允许本地规划，恢复时才进入下一权威 Step |
| 资源和权限难理解 | 当前状态文本混排 HP、预算、肾上腺素；并发仅一个英文按钮 | 当前窗口共享预算、个人肾上腺素、并发授权分区显示，并直接说明不可用原因 |

旧 `Game_Design_Final.md` 已完整归档至[重整前设计文档](../历史/游戏设计文档-重整前-2026-10-13.md)，其中专注点、自由拖拽格挡等描述与已冻结重构规则不同。当前玩法摘要见[游戏设计文档](../游戏设计文档.md)。本设计以优化主方案 0.1～0.5 及当前 Logic 为规则依据，只引入用户刚确认的暂停规划交互。

## 2. 不变的玩法语义

- **同一窗口安排多个指令**：支持。普通动作从同一窗口账本预留预算。默认同一单位在自身 ActorLane 上串行排列，第二条接在第一条后摇结束之后；两条不代表同时执行。
- **真正同时执行**：不同单位的动作轨道可以重叠。主角在他人窗口发起普通动作，需要先获得并发授权；消耗的是该窗口的共享预算。并发能力不使同一单位获得第二条轨道。
- **预算与经过时间不同**：预算是动作成本总额，不是三秒倒计时。玩家思考不按墙钟扣预算；战斗时间在实时模式仍会推进。重叠动作的预算按各动作成本相加，不能用时间轴占用宽度代替。
- **关闭窗口与动作完成不同**：关闭仅停止新增普通动作及当前并发授权，已接受计划照常跨窗口执行。下一窗口不等待旧计划完成。
- **反应与普通防御不同**：防守 Guard 是花时间预算、可提前安排的普通动作；格挡 Block／闪避 Dodge 只能绑定已公开威胁，花个人肾上腺素，触发时刻由 Logic 决定。
- **可见性**：自己的草稿/计划可见；他人的 Editable 队列不可见。敌方仅展示已公开动作及机会。正常 HUD 不读取全量快照来泄露未来攻击。
- **只读界面**：费用、路径、起止时刻、可编辑性、反应截止、拒绝原因由权威预览和决策投影提供；UI 不自行授予权限、修改状态或移动单位。

## 3. 屏幕框架

采用当前 uGUI 体系。主场景直接使用这一套正常战斗 HUD，诊断信息作为可折叠附加层。1920×1080 为布局参考，1366×768 必须仍能完成全部操作。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 战斗目标 / 当前行动窗口 / 权限       战斗时间 00:12.40  [战术暂停] │
├────────────┬───────────────────────────────────┬───────────────────┤
│ 我方单位   │                                   │ 当前选择          │
│ 头像/HP    │        战场 / 选中单位 / 朝向      │ 名称、HP、状态    │
│ 当前状态   │        路径、作用范围、威胁预告    │ 可用普通动作      │
│ 执行中动作 │                                   │ 目标/朝向/落点    │
│ 可控/可令  │        世界空间 HP 与命中反馈      │ [添加至草稿]      │
├────────────┴───────────────────────────────────┴───────────────────┤
│ 当前窗口预算：可用 / 已预留 / 已消费      肾上腺素 / 并发资源      │
│ 共用连续时间轴：过去 ← 当前时刻 → 未来；每单位一条轨道             │
│ 我方：      [移动][攻击前摇 ◆命中 后摇] [未来草稿...]               │
│ 敌方：      [仅公开攻击...]  ◆命中 ← 反应机会绑定                   │
│ 草稿：①移动 → ②轻斩   [逐项编辑/移除] [应用排程] [结束行动窗口]   │
└────────────────────────────────────────────────────────────────────┘
```

| 模块 | 常驻内容与操作 | 展开内容 |
|---|---|---|
| 顶部战斗栏 | 胜利目标、当前窗口拥有者、受控单位是否可下普通指令、战斗秒数、进行/暂停状态 | 系统菜单。系统暂停期间不能编辑/提交 |
| 我方单位栏 | 名称、HP、状态、当前动作；点击选择受控单位 | 增益/控制剩余时间、单位动作轨道聚焦。阵营与控制权分别表达 |
| 战场 | 选中轮廓、真实朝向、路径/目的格、攻击范围、公开威胁 | 选目标/落点、方向选择；预览图用虚线，实际已接受计划用实线 |
| 动作配置器 | 攻击／移动／防守；选中动作的费用、前摇/生效/后摇、目标与朝向；添加草稿 | 详细伤害、动量、范围和预览失败原因。未选目标时不能添加 |
| 预算栏 | 当前窗口总额、可用、已预留、已消费、草稿预计占用与应用后余额 | 按单位拆分该窗口共享预算；历史窗口预留独立显示 |
| 时间轴 | 单位轨道、当前线、绝对战斗秒刻度、动作阶段、命中/生效标记、状态 | 拖动 Editable 计划、精确起始时间、选中计划详情、删除。禁用原因始终可见 |
| 草稿队列 | 多条动作按顺序编号、目标/落点、起止时间、费用、局部冲突；应用/丢弃 | 编辑任一项不丢其他项；默认追加，插入/重排需预览依赖闭包 |
| 反应区 | 有机会时固定出现：攻击者、攻击名称、受威胁单位、距命中和各选项截止、费用 | 格挡/闪避/不响应；闪避选择合法落点，说明可能取消的未来移动及条件退款 |
| 事件反馈 | 命中、抵抗、拼刀、击退、控制、计划延期/中止、预算释放、单位生成 | 可折叠战斗记录，按因果解释；不把开发错误码当主要文案 |
| 战斗结果 | 胜/负/平局，最后一次交互原因，重新开局/退出 | 结束后收起输入，保留可检查的动作历史 |

缩小时优先保留战场、暂停入口、当前窗口/预算、时间轴与草稿。单位详情/战斗记录转为抽屉；反应不能被动作抽屉遮住。时间轴可缩放/平移，默认“跟随当前时间”；手动查看未来时明确显示“返回当前时刻”。

## 4. 时间与暂停：可实施的交互契约

**只保留一个权威战斗时钟。** `BattleTime = 已提交逻辑 Tick / 60`；视觉插值可以平滑显示，但不能越过当前已提交快照，不另造一个与 Tick 脱节的游戏时间。左上角不再把递增 Tick 当主要信息。诊断折叠层才显示 Tick、锁定线、修订号、模式及队列状态。

| 状态 | 权威 Step / AI / 截止计时 | UI 能做什么 | 屏幕表达 |
|---|---|---|---|
| 实时进行 | 继续推进 | 多条本地草稿、实时预览、提交；预览随快照更新 | “进行中”；若无正在执行动作，显示“等待行动，时间仍在推进” |
| 战术暂停 | 完整 Tick 边界停止，不补暂停期间的 Tick | 选择、追加/编辑草稿、预览、确认待提交排程、选择反应 | “战术暂停·可规划”；时钟/执行进度/截止全停止 |
| 系统暂停 | 停止 | 设置、继续、退出；战斗输入禁用 | “系统暂停”；恢复回此前实时或战术状态 |
| 已结束 | 不再推进 | 查看结果/记录、重开/退出 | 明确结束状态，禁用所有战斗命令 |

暂停入口独立常驻，Space 默认切换战术暂停；输入框聚焦时不抢占按键。关闭动作面板不改变暂停状态或草稿。暂停冻结单位运动、动作进度和倒计时；提示渐变和 UI 动效可以继续。命中反馈队列保持顺序，恢复时不重复触发。暂停/恢复清掉积累器中的暂停墙钟时间，允许保留暂停前尚未满一个 Tick 的余量。

**暂停确认不等于已经生效：**

1. 暂停时以快照 T 进行本地预览。玩家可反复添加、修改、删除多个操作。
2. 点“应用排程”封存本地操作列表，显示“待恢复提交”，权威预算和单位位置保持不变。已有待恢复列表仍可重新进入编辑；不能另建一份相互忽略预算的队列。
3. 点“继续时间”时，若存在未确认草稿，呈现三个选项：应用并继续、保留未提交草稿并继续、返回规划。不能暗中提交或丢弃。
4. 恢复入口重验原快照/窗口/修订后，将一组普通操作通过现有命令工厂生成一个事务；合法反应仍是独立机会命令。仅在下一正常 Step T+1 采纳。费用与权限仍由 Logic 校验。
5. 界面分别收到网关排队结果和权威接受/拒绝结果；接受后才从“待采纳”转为正式计划、更新真实预留。失败保留用户意图并标出原因，不自动按另一条排程重试。

战术暂停不能用“只停动画而让 Tick 继续”实现；也不能为确认草稿偷偷 Step。它不暂停一边、继续另一边。暂停是展示/驱动门控；上述恢复命令仍使用普通入口，恢复后的实际 Step 和结果照常进入回放。

当前 IsPaused 的广泛拒绝不能直接删掉：需要显式拆分 TacticalPlanning 与 SystemPaused，并保留系统暂停禁止投递的测试。暂停期间本地预览不要求开放权威写入口。

## 5. 多指令规划与时间轴

### 默认操作

选择单位 → 选择动作 → 配置目标/落点/朝向 → “添加至草稿” → 再选动作 → 添加第二条 → 预览整组 → “应用排程”。在实时或暂停中均能建立多条草稿；实时预览发生过期时保留列表，指出需重算的项。

默认追加到该单位最早合法 Lane 尾端，完整含后摇。同一单位两个普通动作不能画成重叠；若用户拖至非法区间，显示冲突及可选合法位置，不能静默平移。批量预览允许依据权威排程规则计算合法后续位置。

示意：窗口预算 3.00 秒，移动费用 0.60 秒＋轻斩费用 0.80 秒。两条草稿占用 1.40 秒，预计剩余 1.60 秒；动作依次执行。该组费用只用于草案，实际费用必须读取 `SchedulePlanPreview`，不能写死 UI 数值。

### 表达规范

| 状态 | 表达 | 可操作范围 |
|---|---|---|
| 草稿 | 虚线/“草稿”字样、序号、预计起止/费用 | 编辑、删、重排；尚未占权威预算 |
| 待恢复提交／待采纳 | 专门状态标签，不使用“已安排” | 前者可重新编辑；后者等待回执，不重复发送 |
| Editable | 实线/“已安排·可修改” | 权限/锁定门禁允许的修改；窗口已关时不增加其预算 |
| Locked/Running | 锁定/“前摇、移动中、生效、后摇”文本及进度 | 查看；不能普通删除或拖动 |
| 系统延期 | 原位置与新位置差异、“因控制延后至…” | 仅依据真实修订刷新，不按视觉状态猜测 |
| 完成/中止 | 完成标记或中止原因；历史降强调 | 查看。不能冒充删除成功或可退款 |

时间轴同一坐标映射用于绘制、拖动、光标与精确输入；默认 0.5 秒大刻度，实际落点吸附到一个 Tick，详情显示到足以区分相邻 Tick 的精度。动作块分出前摇/有效期/后摇，攻击有单个命中标记；短块使用序号，完整名称/时刻/阶段在选中详情和草稿列表显示，不能缩到无法读。

当前线和“可编辑边界”分别表达。不能把 `CurrentTick+1` 整片涂成已经锁定：T+1 的命令先进入冻结批次和启动门禁，再由 Logic 决定计划是否可编辑。跨窗口计划仍保留在同一轨道；标注来源窗口，不按新窗口把整条时间轴清空。

“应用排程”只提交计划；“结束行动窗口”只关闭当前普通动作提交权。两者必须是不同按钮及反馈。结束存在未提交草稿时询问应用后结束／丢弃后结束／返回，复用正常权威命令处理顺序；不能先关窗口再提交动作。共享并发窗口中只有窗口拥有者可结束，其他参与者显示说明。

## 6. 资源、并发与反应

预算栏始终满足 `总额 = 可用 + 已预留 + 已消费`。草稿预计占用另行显示，不重复计入真实账本。例：“可用 1.60 / 预留 1.40 / 消费 0.00 秒”；执行启动后预留转消费，不能同时扣两次。移动距离不是动作费用，必须根据真实路径边权显示。

肾上腺素显示所选受控单位的“可用 / 反应预留”；提示“下次自身窗口打开时可用值清零，已接受预留履约”。切换受控单位切换个人资源，当前窗口共享预算保持一致。

并发区显示能力名称、局外资源名称/余额/真实费用、授权当前窗口/主体、当前是否已激活。自己窗口解释“当前已有行动权”；他人窗口没有授权时解释“普通动作需并发授权；格挡/闪避仍可响应已公开威胁”。授权确认前不让普通预览假定已获权。暂停中点激活先显示待恢复请求；恢复后等权威授权回执，玩家可以再次暂停规划。首版不伪造“激活＋依赖授权动作”的跨命令原子事务。若需要一步完成须单独设计复合预览/协议。

反应出现时显示选项各自的截止时刻，不能把命中倒计时当输入截止。选项不足资源、Lane 固定区间冲突、落点非法、不可格挡等均直接说明；拒绝提示可读原因，详细代码收入诊断。

格挡和闪避不提供自由时间拖动。闪避用独立落点配置；提示“成功换位可能使 N 条未来移动失效；预算按来源窗口条件释放”，不能在确认时提前把条件退款加到可用余额。未公开攻击不显示反应按钮；多次公开机会按截止和稳定 ID 排序，不自动选择或花资源。

## 7. 输入与反馈

- 左键：选择单位/目标/落点/计划；时间轴可编辑计划提供显式编辑与删除按钮，右键仅作快捷入口。
- Space：战术暂停/继续；Esc：先取消当前未完成目标/拖动，再关闭详情，最后打开系统菜单。
- Enter：配置器完整时添加至草稿；应用排程使用显式按钮/独立快捷键，避免一次 Enter 隐式执行整个窗口。
- 方向选择：战场方向轮或选中单位箭头，支持 12 向，显示攻击/防守影响；不只有一个“Turn”盲转按钮。
- 操作反馈：一次手势只提交一次；暂不可用的按钮保留标签与原因，不让点击看似无反应；成功也有队列/权威结果反馈。
- 伤害/抵抗/击退/拼刀使用空间反馈与简短事件条，计划中止明确对应单位及动作。世界 HUD 与所选详情读取同一快照。
- 不通过颜色单独表达权限/状态。中文玩家文案有状态文字与图形辅助，关键信息不依赖悬停；支持字号与对比度设置。

## 8. UI 数据与职责

保留 `BattleRuntimeBootstrap → UnityBattleDriver → Logic` 唯一推进链。沿用当前 read-only port 和 command ingress；HUD 自身不运行模拟。

| 组件职责 | 需要的数据/交互 |
|---|---|
| BattleHudPresenter | 汇总控制者决策、真实接受/拒绝结果、窗口/资源/公开反应；转换玩家文案 |
| BattleClockController（驱动侧门控） | 运行/战术暂停/系统暂停/结束状态与恢复入口，单一 Tick 边界 |
| SelectionModel | 受控单位、观察单位、动作、目标、方向、落点；观察敌人不切换自身下令主体 |
| ScheduleDraftModel | 多条稳定本地操作 ID、基础修订/窗口、预览、封存待恢复列表、提交中状态、过期原因 |
| TimelinePresenter | 相同的轴坐标、单位轨道、阶段/标记/锁定门禁、跨窗口历史；只看允许公开的数据 |
| ReactionPresenter | 按机会/选项截止排序，固定触发区间、资源/落点/条件取消预览 |
| Unit/Resource/Feedback presenters | 只读投影、资源归属、有限反馈队列；诊断 UI 订阅独立显示面 |

目前的 DecisionSnapshot 不包含所有 HUD 所需内容，需要增加控制者过滤的只读投影：并发主体/窗口/费用与余额、玩家动作显示名、角色显示名、动作阶段/门禁说明、窗口可提交权限、对应来源窗口账本。不得退回从 Legacy 组件取值。

优先使用 LayoutGroup/CanvasScaler 和独立区域 Prefab；将当前 `BattlePresentationView` 的选择、排程、反应、状态文本职责逐步拆开。此处是责任划分，不要求照名字立即创建所有类或引入新的 UI 框架。

## 9. 落地次序与产品验收

1. **时间控制和多草稿（首个可玩版本）**：战术暂停/系统暂停分型，暂停预览与恢复采纳，多操作原子编辑，保留失败意图与回执；独立应用/结束按钮。
2. **核心 HUD**：单位选择与资源归属、权限原因、共享预算、阶段时间轴、命中点、路径/范围/方向、正常中文文案。
3. **反应与并发**：公开机会、各选项截止/费用/原因，闪避条件失效，真实并发资源与授权回执。
4. **全战斗体验**：动态单位加入、控制/延期/中止、胜负/重开、大小屏/输入焦点/可访问性，以及诊断折叠层。

| 必须实际演示的玩家流程 | 验收点 |
|---|---|
| 一个窗口安排移动＋攻击 | 第一条不消失；两条起止/费用可读；一次确认；实际按同一 Lane 依次执行 |
| 安排两条，删除其中一条 | 其余意图保留；预览整体重算；真实预算未被草稿扣掉 |
| 暂停十秒进行规划 | 权威 Tick/动画进度/反应截止全停止；多条草稿可增删；无 AI 暗中消耗预算 |
| 暂停应用后检查状态 | 显示待恢复提交；权威计划/位置/预算不变，不能显示已生效 |
| 恢复执行 | 下一正常 Step 仅采纳一次；无补跑暂停十秒；真实回执决定 HUD 状态 |
| 实时草稿过期 | 保留意图、标注过期原因，禁止以旧修订静默重试 |
| 关闭窗口时攻击尚未命中 | 下一窗口出现；旧攻击留在时间轴继续命中，无动画/计划清空 |
| 他人窗口尝试普通攻击 | 明确权限原因；真实并发激活后共享预算；未授权不能绕过 |
| 他人窗口响应攻击 | 未激活并发也可用合法格挡/闪避；截止、Lane/资源限制正确显示 |
| 闪避使未来移动失效 | 条件取消与退款先预告、真实事件后更新；历史窗口释放不注入当前可用预算 |
| 已公开与未公开敌方计划 | 未公开计划不泄露；公开时轴与战场威胁同步出现 |
| 战斗终态/重新开始 | 不再推进或提交；结果可读；冷启动资源/草稿/暂停/反馈状态正确复位 |
| 1366×768 与动态单位 | 关键按钮不遮挡、短动作仍能选读；新单位可选择/资源归属与轨道正确 |

逻辑/回放测试继续作为底层依据；以上还需要真正使用鼠标/键盘经过完整 HUD 操作的验收。运行时实现改变源文件后，原 Shadow 收口证据指纹应重新生成并复验，不能沿用旧指纹声明通过。
