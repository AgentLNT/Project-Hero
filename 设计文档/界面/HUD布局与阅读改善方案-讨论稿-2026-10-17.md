# HUD 布局与阅读改善方案（讨论稿）

> **已被用户纠偏后的[常规界面与介入界面分层方案](HUD常规界面与介入界面分层方案-讨论稿-2026-10-17.md)替代。** 下文把时间轴当成常规主界面的组织方式不再适用；两种空间布局仅保留为介入层的历史候选，不作为常规 HUD 实施依据。

日期：2026-10-17。状态：规划讨论稿，尚未实施，也不替代现行 HUD v0.3 和暂停/草稿契约。

用户已明确本轮优先解决：**信息太挤、战场太小，先改善布局与阅读。** 推荐先评审“侧栏工作区”布局，再按下文分阶段实施。本文中的尺寸、信息层级与验收目标是提案；交互草图使用示意数据，不代表正式 Logic 的预测结果。

## 1. 当前依据与问题

- [HUD v0.3](战斗UI-HUD框架-v0.3.md)已有战场优先、多单位共用时间轴、接触点联动的设计目标。
- [2026-10-17 补验记录](../../优化任务/执行记录/M2-M4-补验完成-2026-10-17.md)已完成 M2～M4 真实操作和独立 Windows Player 补验。本轮以此为交互基线。
- [现有 1366×768 规划画面](../../优化任务/执行记录/M2-M4-输入补验修正-2026-10-16/M4-space-native-1366x768.png)显示：左侧单位信息、右侧多个面板、独立草稿区和全宽控制条共同挤压战场；大量按钮权重接近。
- `BattlePresentationView.SetHudBattleViewport` 当前规划相机矩形宽 42%、高 45%，相当于屏幕面积的 **18.9%**，约 574×346 像素。这是相机视口面积，尚未扣除叠加控件，也不等于实际棋盘大小。
- `M3ReactionView` 的反应卡区域覆盖屏幕 x=29%～70%、y=48%～89%，与规划战场高度重叠；反应时尤其容易遮住选点位置。
- `M1HudView`、`M2TimelineView`、`M3ReactionView`、`M4SpatialView` 分别定位自己的区域。改善布局时需要统一区域分配，以免一个面板扩展后遮住另一个。

## 2. 本轮目标

1. 玩家首先看清战场，再沿“接触点 → 时间轴 → 当前动作详情”读取信息。
2. 同一条信息只设一个主要展示位置；需要决策时才展开详细参数。
3. 保留精确排程能力，以收起、展开、就近说明减少常驻文字。
4. 常用控件位置稳定：暂停/继续、应用排程、时间游标、主选轨道不因普通内容变化而跳动。
5. 1366×768 可完成全部操作；字号放大后通过布局调整容纳内容。

## 3. 两种空间方案

| 方案 | 结构 | 优点 | 代价 |
|---|---|---|---|
| **侧栏工作区（推荐）** | 战场在上方左侧，右侧为当前工作区；底部时间轴横跨全宽 | 时间轴更长，方便命中对齐；动作、结果和反应详情有固定位置；反应卡不遮战场 | 配置器打开时占用右侧宽度 |
| 上下工作台（备选） | 上方为通栏战场；时间轴与工作区并排放在下方 | 战场横向最宽，上方结构简洁 | 时间轴变窄；下方工作区较矮，反应警告、选点与精确参数更容易需要展开 |

推荐“侧栏工作区”：项目的精确排程依赖横向时间空间，完整时间轴与稳定的反应详情位置有明确价值。“上下工作台”留作比较，以实际阅读与操作体验决定是否采用。

### 3.1 推荐布局的尺寸预算

1366×768、字号 100%、战术暂停且工作区打开时的初始预算：

| 区域 | 位置与大小 | 内容 |
|---|---|---|
| 屏幕边距 | 16px；区域间距 12px | 保持边缘可读，避免贴边 |
| 顶栏 | x=16，y=16，1334×48 | 当前窗口、暂停原因、战斗时钟、设置入口 |
| 战场视口 | x=16，y=76，1010×348 | 单位、相关路径、范围、接触标记 |
| 右侧工作区 | x=1038，y=76，312×348 | 当前动作或选中威胁的详情 |
| 时间轴 | x=16，y=436，1334×248 | 共用窗口/刻度，主选轨道与紧凑轨道 |
| 底部操作栏 | x=16，y=696，1334×56 | 草稿摘要、应用排程、继续时间、条件性介入 |

此时相机视口面积约为屏幕的 **33.5%**，约为当前规划视口的 **1.77 倍**。这是布局预算，并非已经实现的效果。单位、格子是否更容易辨认，还须结合相机取景和相同战斗状态的截图验证。

时间轴初始分配为标题/刻度 56px、主选 64px、4 条紧凑轨道各 32px；更多轨道沿用垂直滚动、溢出数量和主选滚入视野。长名称与字号放大时允许增加行高，重新计算可见轨道数。

时间流动且没有展开工作区时，战场预算为 1334×476，时间轴收为 120px，高度分配来自时钟事实。进入选点、拖动、警告阅读期间禁止自动折叠正在使用的区域。

### 3.2 战场与相机

- 取消左侧常驻大块单位列表；单位快捷选择入口放到时间轴标题区，已选单位的 HP、肾上腺素与名称继续显示在轨道标题。
- 未选单位仍可通过战场点击或单位选择入口访问；保留 Ctrl 多选和 Tab 切主选。
- 战场只常驻必要姓名/血量与正在相关的威胁。高密度标签先避让，再合并为可展开的关联列表。
- 全网格降低视觉权重；当前路径、合法落点、选中范围提高权重。不能只靠颜色表达敌我、选中或危险。
- 布局切换时保持当前关注单位/接触点处于可见位置。必须用真实场景检查格子和单位的屏幕尺寸，避免“视口扩大但棋盘反而缩小”。
- HUD 的矩形变化、相机视口和世界标签投影在同次布局刷新中生效；战场射线只在有效视口内处理，UI 点击不穿透到战场。

## 4. 信息分配

| 信息 | 主要展示位置 | 详细内容何时出现 |
|---|---|---|
| 时钟、当前窗口、暂停原因 | 顶栏一至两行 | 超长原因展开；窗口区间仍画在时间轴 |
| 单位 HP、公开肾上腺素、主选标识 | 轨道标题 | 选中单位时在工作区查看详细属性 |
| 动作时序、计划状态、命中点 | 时间轴动作块 | 选中动作后在工作区查看精确参数 |
| 当前动作与预计结果 | 右侧工作区 | 首屏显示结果和必要警告，公式/精确时刻放在“时序详情” |
| 未应用草稿 | 时间轴虚线动作块＋底栏数量/状态 | 点击草稿摘要展开批量编辑/移除清单 |
| 威胁 | 战场标记＋工作区顶部紧凑队列 | 选中的威胁展开格挡/闪避及起点放置条 |
| 快捷键 | 对应按钮文字或局部提示 | 完整快捷键表在帮助中 |
| 自动暂停、字号、高对比 | 设置入口 | 展开时可操作；紧急威胁提示仍在更高可见层 |
| 诊断、回放 | 开发菜单/F3 | 以独立开发入口访问 |

草稿清单折叠后，拒绝原因、过期提醒和待恢复提交状态仍然可见。精确时间沿用现有量化与规则，底层 Tick 不受显示小数位影响。

默认摘要使用相对时间，如“0.8 秒后命中”。所有轨道仍共用同一时间基准与刻度。详细时序保留绝对战斗秒、精确起点及命中时刻；禁止在同一未标注刻度里混用绝对与相对时间。

## 5. 状态与工作区规则

布局继续由现有“时钟 × 提交权限 × 威胁”事实推导。工作区查看哪一个对象属于本地选择状态，不授予任何动作权限。

| 情况 | 战场与时间轴 | 工作区与主要操作 |
|---|---|---|
| 时间流动 | 战场扩大，已选轨道精简；威胁汇总保留 | 显示暂停入口；已有运行中配置能力仍可主动展开，展开后保持稳定 |
| 战术暂停，有普通提交权 | 完整时间轴，保留游标与窗口可放区 | 当前动作详情；草稿未应用时突出“应用排程” |
| 战术暂停，有威胁 | 受威胁对象、来源攻击和关联轨道可见 | 工作区展开当前反应；普通动作配置通过明确入口返回，已有草稿保留 |
| 多个威胁 | 按截止排序的紧凑队列；显示总数及最紧迫未处理项 | 一张反应卡展开；其他条目保留攻击者、受击者、截止和处理状态，不因收起而消失 |
| 他方窗口，无普通提交权 | 允许查看公开计划与时间游标 | 原因说明及可用时的“介入”；反应资格单独判断 |
| 系统暂停或已结束 | 现有覆盖层 | 沿用现有交互门禁 |

补充约束：

- 自动暂停与自动选择时机沿用既有契约；布局刷新不得额外清空选择、草稿或反应落点。
- 反应起点放置条、提前消耗警告、肾上腺素费用/清零提示、输入截止和闪避移动链失效提示，必须能在当前反应详情中读到。
- 多威胁时使用紧凑队列加单卡详情，取代大卡片层叠；此项是对 v0.3 反应卡展示形式的提案，信息与权限要求继续成立。
- 单卡内容超过工作区高度时，只滚动详情正文；威胁队列摘要、关键警告与确认入口保留可见。没有空间时扩大工作区或收起非关键说明。
- 设置抽屉和普通详情不得覆盖正在使用的反应确认、输入截止或关键警告。系统暂停则遵循其禁止投递规则。
- 工作区切换不得造成无提示的选点丢失或重复提交；若现有取消配置行为会丢弃尚未形成草稿的意图，须先明确提示/保留策略再实施。

## 6. 文字与操作强调

- 正文目标 16px、辅助文字至少 14px、关键状态约 20px，均指 1366×768 上实际显示大小；最终以可读性和字号 130% 验收为准。
- 攻击、防守、格挡、闪避继续使用文字名称；形状、线型、颜色共同表达状态。
- 草稿虚线、待恢复提交、待采纳、已接受、锁定/执行、完成/中止仍分别表达，不合并为一个含糊的“完成”。
- “应用排程”在暂停时只封存草稿；“继续时间”恢复后才由正常 Tick 处理。两项操作保持独立。
- 未应用草稿时“应用排程”最突出；待恢复提交后状态文字就地反馈，“继续时间”获得主要强调。按钮位置固定。
- 点击继续且仍有未应用草稿时，沿用“应用并继续／保留草稿并继续／返回规划”。
- 精确输入、窗口末尾放置、缩放/平移、回到当前、时间游标、B/D/Enter/Esc 等现有能力仍可到达；收起面板不会改变快捷键门禁。

## 7. 实施拆分建议

| 阶段 | 交付内容 | 主要修改边界 | 通过条件 |
|---|---|---|---|
| P0：空间布局 | 顶栏、战场、统一工作区、全宽时间轴、底栏；迁移大块固定区域 | `BattlePresentationView`、M1～M4 布局接入；集中管理区域矩形 | 同一暂停画面战场视口达到预算；已有输入和选点无错位；两分辨率无遮挡 |
| P1：阅读层级 | 草稿摘要、紧凑威胁队列与单卡、相对时间摘要、关键警告、设置入口 | M1 草稿状态、M2 轨道标题、M3 反应呈现、M4 标签与工具入口 | 新用户能指出暂停原因、受威胁者和下一步操作；所有必要告警可见 |
| P2：交互与可读性回归 | 超长名称、多轨道、多威胁、无权限、字号放大、拒绝回执、真实输入与 Player | 保留现有 Model/命令/预览端口，补充变化相关的验证 | 下方验收矩阵通过后更新当前设计与验收记录 |

建议抽出一个小的纯布局计算器，由视口尺寸、文字缩放和 HUD 事实输出区域矩形；各 Presenter 使用相同结果。是否需要新文件以实际实施时的职责边界决定。Logic、规则、回放格式和命令协议不属于本次布局工作的修改目标；必要的新只读展示字段须另行说明。

## 8. 验收矩阵

| 范围 | 验收方法 |
|---|---|
| 战场面积 | 1366×768、100% 字号、工作区打开时，相机矩形至少约 1010×348；记录矩形及实际无遮挡区域。用同一战斗状态比较单位、格子与范围可读性 |
| 两分辨率 | 1366×768、1920×1080 分别检查流动、规划、反应、只读、系统暂停、结束 |
| 字号放大 | 100% 与 130% 下，输入截止、警告、应用/继续和当前反应确认均不裁切；允许减少同时可见的轨道数 |
| 时间轴 | 一主选加四紧凑轨道的默认预算；多轨道滚动、主选切换、关闭合拢、跨轨道命中对齐和吸附线可操作 |
| 草稿与回执 | 多草稿、编辑/移除、重验、应用、恢复选择、待采纳、拒绝原因及意图保留；折叠清单不隐藏错误 |
| 反应 | 多公开威胁、不可用原因、提前消耗、格挡起点、闪避选点与移动失效警告；B/D/Enter/Esc 的输入框与暂停门禁 |
| 空间只读 | 拖动游标、查看未来范围、选中接触点不推进 Tick、不消费资源；缩放/布局变化后 UI 射线与战场选点一致 |
| 公开信息 | 敌方未知计划不泄露；预测仅取现有 Logic 只读预览；公开肾上腺素与反应能力正确展示 |
| 真人阅读验证 | 建议 3～5 位未读设计稿的玩家，在三个截图/场景中指出暂停原因、受威胁者和下一步操作；目标每题约 5 秒内，记录犹豫与误解。该目标尚未实测 |
| Player | 在最终独立 Player 上复核布局变化相关的鼠标/键盘流程与画面；历史补验只作为基线，不能替代本轮证据 |

本轮布局验证包含拖动和展开时是否明显卡顿；正式性能、分配、GC 验收仍按独立事项记录。

## 9. 当前决策状态

- 已确认优先级：先改善布局与阅读，解决拥挤与战场过小。
- 推荐待评审：采用“侧栏工作区”；草稿清单默认收起；反应采用紧凑队列与单卡详情。
- 后续细化：根据两版交互草图的反馈，确定侧栏宽度、时间轴高度以及各状态首屏内容，再更新为实施版本。

本讨论稿不把原型草图、尺寸预算或建议验收目标记为已经实现或通过。
