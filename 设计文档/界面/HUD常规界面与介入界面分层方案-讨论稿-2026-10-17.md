## 1. 已明确的设计边界

1. 常规战斗是默认界面，也是优先设计与验收的主界面。
2. 完整时间轴、精确排程及附属编辑工具是“介入”时的专用界面；常规预览区内的只读时间位置条始终可用。
3. 普通暂停、我方窗口开启、公开威胁出现，本身都不足以启用时间轴。
4. 底层战斗仍可用连续 Tick、窗口、计划与预览服务；底层模型不决定常规 HUD 必须展示这些结构。
5. 常规界面应独立完成正常游玩流程。玩家不应为了查看单位或使用普通行动，被迫进入时间编辑界面。
6. “信息太挤、战场太小”的首要改法，是将介入工具移出常规界面，而后再调整尺寸与视觉层级。
7. 普通行动采用用户已确认的流程：选择动作与目标，先加入简短行动队列，再统一确认。
8. 常规规划与介入规划使用相同的动作、时序和结果规则；常规模式自动把每个后续动作的起点接到上一动作的末尾。上一稿“队列只表达先后、不含时刻”修订为“不手动编辑时间，但必须能读到时间后果”。
9. 每个动作加入前，除预期伤害/结果，还必须预览该动作在时间区间中的占用位置，包括起点和末尾。末尾越过当前时间区间时，必须提供非阻断、非插入式的危险提示。
10. 介入是核心战斗功能，入口位于底部主操作区，与当前角色和普通动作建立直接联系。隐藏未启用的精确工具不等于降低入口的重要性；不再采用右上角辅助功能式入口。两层界面保留同一位置，状态变化用明确文字和神器识别表现。
11. （2026-10-26 确定）介入分为两层。**介入**是怀表的“预知”时间视图，任何窗口都能打开，打开或关闭都不授予、不撤销任何权限。**并发授权**（游戏设计文档 §5.3 的 ConcurrentGrant，旧稿亦称“介入”）是在他方窗口打开介入后，另行付费申请的普通动作提交权，仍由 Logic 校验并回执。两者共用底部同一入口，状态分开显示：权限状态写“我的窗口 / 他人窗口·可申请授权 / 已授权 / 无”，视图状态写“介入中”。时间视图本身暂定无代价，待规则确认；并发授权的费用沿用现有配置。
12. （2026-10-26 确定）常规只读位置条叠加公开受击标记：已知视界内、指向本单位的公开命中画在同一刻度上；结果预览补一行“期间受到 X；届时无法格挡/闪避（原因）”。标记只读，不提供编辑或游标，不显示视界外和未公开的计划。
13. （2026-10-26 试行）常规层可为攻击选择相对时机（尽早、拼刀、抓后摇），界面换算为起点并显示由此留下的等待；默认仍首尾衔接，见 §3.7。

## 2. 两层界面的职责

| 功能/信息 | 常规战斗 | 玩家选择介入后 |
|---|---|---|
| 战场、选中单位、当前行动者、目标 | 主要内容 | 保留，和计划联动 |
| HP、状态、公开肾上腺素 | 紧凑状态区；其他单位按选择/查看展示 | 可同时投影到相关轨道标题 |
| 普通动作菜单/快捷栏 | 常用操作入口 | 作为排程配置入口 |
| 当前行动的移动范围、路径、攻击范围与目标预览 | 可显示，支持直接战术决策 | 同时与未来计划/时间游标联动 |
| 单位行动顺序 | 可选的紧凑头像序列，只表达先后 | 进一步显示连续窗口区间 |
| 连续秒数刻度、多单位轨道、窗口可放区 | 不显示、不交互、不预留空白占位 | 显示 |
| 动作块拖动、命中吸附线、跨轨道接触连线 | 不启用 | 启用 |
| 时间游标、未来残影、按未来时刻查看公开范围 | 不启用 | 启用 |
| 精确起点输入、窗口末尾放置、时序详情 | 不启用 | 启用 |
| 简短行动队列、统一确认 | 起点自动衔接，显示动作、目标、预计结束位置及风险 | 同一计划的精确编辑视图；不复制出另一份独立队列 |
| 加入前的伤害/结果与时间后果预览 | 必须显示；用只读位置条表达本次动作的起止、已排部分、窗口边界，以及已知视界内指向本单位的公开受击标记 | 使用同一预览结果，同时投影到轨道 |
| 末尾越过窗口的危险提示 | 就地显示，保留加入/确认操作，不弹窗 | 同一风险语义，并标记对应动作块 |
| 精确排程草稿、应用排程、重验时序 | 以普通队列呈现同一规划，自动求值、重验 | 展开精确时序配置并沿用提交契约 |
| 反应起点放置条、提前消耗时序分析、未来移动链失效分析 | 不作为常驻控件 | 按相关反应展开 |
| 基础威胁提示 | 简短说明受威胁者与来源 | 展开为反应/时序工作区 |
| 格挡/闪避的普通操作入口 | 提案：常规反应卡（§3.6），默认起点放在命中时刻，不需要时间轴；不能因隐藏时间轴就删除原有反应能力 | 详细起点配置与预览可在此呈现 |
| 介入入口 | 底部主操作区的核心功能，具有明确视觉重点；任何窗口都可打开时间视图（暂定无代价），不改变权限 | 原位置显示“介入中”及返回入口；展开同一计划的时间编辑工具；在他方窗口内另行提供“申请并发授权”及费用、回执 |
| 权限状态 | 上缘紧凑区显示“我的窗口 / 他人窗口·可申请授权 / 已授权 / 无” | 同样显示；与“介入中”视图状态分开，不互相替代 |
| 设置、帮助 | 独立低频入口 | 同样可达 |
| 开发诊断、回放 | 开发入口 | 开发入口 |

“行动顺序头像”与连续时间轴在本提案中是两个独立控件：前者不含秒数、行动持续区间或可拖动计划，也不加载时间编辑器。当前及预计先后仍从正式公开投影获取；未来顺序有变化可能时注明预计。

## 3. 常规界面：先把日常战斗做好

### 3.1 阅读与操作顺序

**当前由谁行动 → 选择动作 → 指定目标/落点 → 查看伤害/结果、动作占用位置与风险 → 加入行动队列 → 继续添加或调整 → 统一确认。**

“先加入简短行动队列，再统一确认”已由用户确定。常规队列是同一排程的自动衔接操作方式，例如“移动至石阶 → 攻击守卫 → 防守”。时间后果是常规规划的必要反馈；多轨道时间编辑、命中对齐和手动精确起点仍仅属于介入界面。

建议的基本交互如下，属于本轮待评审细化：

- 队列贴近底部动作栏，显示序号、动作名、目标/落点。空队列仅保留一行提示；较长队列用摘要与展开查看控制占用，不压缩文字或持续抬高面板。
- 选择目标后点击“加入队列”；加入只修改待确认意图，不正式下令或消耗资源。“取消选择”只清除当前选择，不清空已加入的行动。
- 确认前可移除条目；修改目标可通过移除后重新加入完成。排序调整是否需要直接拖动，留到原型评审；不把拖动自动解释成时间编辑。
- “确认行动（N）”是队列的统一提交入口，空队列不可确认。提交前基于当前公开状态重新检查；失败须定位到具体条目并说明原因，不静默丢弃条目或重复提交。
- 提交语义的现有实现（2026-10-26 二次核对源码）：普通动作队列本身是一次排程事务，任一条目失败即整批回滚（[ScheduleEditor](../../Assets/Scripts/Logic/Timeline/ScheduleEditor.cs) 类注释）。但暂停中确认只做预览，恢复时钟后按“并发授权 → 普通排程 → 逐条反应”分别提交，各是独立命令；某步失败即停止并重新暂停，已提交的不撤回（[BattlePresentationModel](../../Assets/Scripts/UnityView/BattlePresentationModel.cs) 的 `SubmitOnResume`）。因此“同一个按钮确认”不等于整体一起成功或一起回滚。确认、部分提交、条目状态与失败展示，见[提交、时机与切换状态表](常规队列提交时机与切换状态表-2026-10-26.md) §2。常规队列直接复用 `ScheduleDraftModel`（每个视图一条队列）和既有预览服务，不另建队列模型。
- 选择第二个及后续行动时，移动范围、路径和目标可用性应考虑前序待确认行动；按顺序预览行动结果仍属于常规战术反馈，不提供任意未来时间游标，也不泄露未公开行动。实际计算继续使用正式预览服务。
- 建议首先呈现当前可操作单位的队列，明确显示所属单位；跨单位队列、条目数量限制与执行遇阻策略尚未确定，不从“简短”推导出固定三个动作或额外 AP 规则。
- 切换介入界面本身不提交、清空或执行队列；同一计划切换呈现方式。介入中精确编辑产生空隙或固定起点后，返回常规界面不得静默压紧原计划。此时后续追加的基点及可编辑范围，在介入生命周期阶段明确。

后续动作自动衔接前项末尾已经确定；首项仍需按当前时刻、已有占用和权限取得合法起点。常规界面不要求玩家填写秒数。

按现有实现，暂停中“确认”不会恢复时钟。建议常规层与介入层只保留一个主操作“确认并继续（行动 N · 反应 M）”：只有反应时也可确认；没有暂存内容时显示“▶ 继续”；并发授权单独申请（状态表 §2.1、§2.4，待用户确认 D1）。

### 3.2 自动衔接与时间后果预览

本稿将用户所说的“时间区间”对应为当前行动窗口。两种界面使用同一计划数据、Logic 时序求值、公开预览及提交规则；常规界面只自动选择相邻动作起点，不另做一套时长估算。

- 后续项 `StartTick[i] = EndTick[i-1]`；末尾指完整动作占用结束，包含后摇/恢复，不以命中点代替。首项由正式规则给出可用基点，不能固定从窗口开始或忽略正在执行的动作。这是默认的“尽早”时机；玩家选择相对时机时见 §3.7（试行）。拼刀等**预计的提前终止不改变计划末尾**：排程按完整区间占用，终止后也不自动前移后续项，所以下一项仍从计划末尾衔接。自动衔接、相对时机与精确起点混用时的规则，见状态表 §3。
- 选好动作与目标、尚未加入时，就按“现有计划 + 候选动作”预览。更换动作/目标/路径、移除前项或状态变化后，重算受影响后续项的起止、伤害/结果、合法性与越界风险。
- 界面用相对本窗口的位置，例如“本次占用：1.2–2.4 秒 / 窗口 3.0 秒”，或者“本次占用：2.0–3.4 秒；越界 0.4 秒”。（待定 D4：建议常规层与介入层统一使用战斗时钟时间，写作“占用 7.2–8.4 s / 窗口 6.0–9.0 s”，见状态表 §6。）必须表达该动作从哪里开始、到哪里结束，不能只给一个累计百分比。加入队列或统一确认本身不等于时钟已推进到该处。
- 位置条嵌入已有伤害/结果预览区，作为可复用的小组件；不为它另开常驻大面板。建议约 180–260 px 宽、6–10 px 条高，随容器自适应；文字跟随全局字号。用低强调填充表示已排部分、高强调填充表示候选动作，清楚标出区间末尾，越界部分用警示色及斜纹表示。
- 位置条只读，不提供拖动、选时刻、缩放、多轨道或未来游标，不触发介入。它显示预计占用位置，不像执行进度条一样自行前进。文字和数值始终可见，不只靠颜色或悬停；超长动作也须保留可辨识的边界及越界量，不能裁掉越界后只显示“满条”。
- 用整数 Tick 比较边界，再格式化显示；恰好结束在窗口边界不算越界。少于显示精度的溢出也必须如实提示，例如“越界不足 0.1 秒”，不能舍入成零而隐藏风险。
- **公开受击标记**（2026-10-26 确定）：本游戏的结果取决于精确时序，常规玩家必须看到哪些公开攻击会落在候选动作期间。位置条在同一刻度上，用小三角标出已知视界内、指向当前单位的公开命中时刻。数据来自经控制者过滤的公开投影；视界外只在条尾标“之后未知”，不推测未公开计划或反应。标记只读，不可点击跳转到时间轴，也不替代反应卡。
- 有受击落在候选动作占用期间时，结果预览补一行，例如“期间受到：重击 5.4 s，预计 24”。若该占用会导致届时无法格挡/闪避，例如反应与自身已有计划冲突时会被拒绝（游戏设计文档 §5.1 反应接受校验；只校验起点到命中点的硬占用段），同一行注明“届时无法格挡（被本动作占用）”。这一行使用 §3.3 的固定提示槽，与越界提示并列，不弹窗。

### 3.3 越界提示：可见、持续、不打断

依现有规则，普通动作起点须在窗口内，动作末尾可以越过窗口。危险提示表达的是窗口交接后的行动暴露，不是新增一个“时长预算不足”限制。

| 情形 | 提示与行为 |
|---|---|
| 结束在窗口内 | 显示预计结束位置及剩余区间 |
| 恰好在窗口边界结束 | 显示“到达窗口末尾”，不标为越界 |
| 起点合法，末尾越界 | 显示“⚠ 超出区间 0.4 秒；窗口结束时动作尚未完成”；候选部分越界段用警示色/纹理，仍可加入并统一确认 |
| 后续项自动衔接后，起点已在窗口外 | 按既有起点规则显示就地不可用原因；不要与“末尾越界但允许”的警告混同，也不自动迁移到下一窗口 |
| 占用期间有公开受击 | 位置条显示受击标记；提示槽写明来源、时刻与预计结果，届时无法反应时注明原因；仍可加入并确认 |

- 提示位置固定在已有预览区，预留固定高度的提示槽，在原位替换文字；长文案或放大字号时给该槽统一留足行数。正常/越界状态切换不让按钮移位。不插入横幅挤动布局、抢焦点、打开弹窗、要求二次确认、强制跳转介入，或只靠一闪而过的 toast。
- 加入后，对应队列项保留“越界”标记，队列摘要保留预计末尾与风险；修改计划使其不再越界时同步消除。确认按钮不因末尾越界而禁用，也不额外增加“仍要继续”步骤。
- 不把越界等同于“必定受击/被打断”。具体威胁只来自 §3.2 的公开受击标记；没有公开依据时只说明动作跨越窗口交接。
- 越界提示只适用于普通动作。格挡/闪避不受窗口限制，不显示“越窗”，见 §3.6。
- 草图采用示意窗口与时长，正式版本读取动作配置和 Logic 预览；普通预览仅计算，不推动权威时钟。

常规状态可把尚未展开的区域用于战场，但必须预先定义介入后头像、队列、结果区的收缩/迁移和相机让位，保证完整多轨道与反应详情有足够容量。即时范围预览、攻击目标、状态文字遵守已公开信息边界；已公开的敌方时序与范围属于应保留的信息，不可一律排除。

### 3.6 常规反应卡（提案，2026-10-26，待原型评审）

威胁自动暂停在常规界面同样会触发，因此常规界面必须能直接完成格挡/闪避，不能要求先进入介入。依据已确认的规则（游戏设计文档 §4.2.1、§5.1）：

- Block/Dodge 只能针对指向本单位的公开攻击放置，消耗个人肾上腺素；没有前后摇，持续时长由动作定义（默认 Block 1.0 s、Dodge 0.5 s），持续区间须覆盖来源命中 Tick；输入截止为命中 Tick 减输入提前量；不受窗口限制。
- 与自身已有计划冲突时，反应会被拒绝，不顺延，也不自动重排普通计划。
- 可用肾上腺素在单位自身窗口打开时清零，已接受的反应预留照常履约（游戏设计文档 §3.1）。

由此推出的使用场景（2026-10-26 核对，见状态表 §5）：

- **反应卡的主要场景是他人窗口。** 威胁在他人窗口里公开，此时肾上腺素尚未清零。若命中落在你即将开启的窗口里，提示“开窗时可用值清零，已接受的格挡照常履约”。
- **在自身窗口里，反应卡通常不可用。** 能威胁你的只有开窗前已起手的攻击，而开窗时可用值为 0。卡片应写明“肾上腺素 0（开窗清零）”，并把玩家引向拼刀（§3.7）、防守或移动。
- **“与自身计划冲突”只在他人窗口里出现。** 这需要主角凭并发授权排了普通动作。

提案内容：

- **默认起点放在命中时刻**（M3 已实现的默认值）。这样硬占用只有命中那一 Tick，除同 Tick 外不会被更早的合格命中抢先消耗，常规界面因此不需要起点拖动或时间轴。
- 反应卡按输入截止排序列出威胁（沿用 M3）。每项显示来源 → 目标、命中时刻、输入截止和预计伤害。
- 操作为“格挡 / 闪避 / 不响应”，并显示费用与当前可用肾上腺素。闪避在战场上点选落点并预览，触发时再校验；同时提示可能取消的未来移动链。
- 不可用时就地说明原因：肾上腺素不足、已过截止、动作集不含该反应、与自身计划冲突。冲突时指明是哪一项计划；若该项仍未锁定，提供“移除该项并格挡”，作为玩家主动执行的一步，不自动重排。
- 选中的反应进入暂存，与常规队列一起统一确认，沿用现有的暂存反应提交流程。
- 需要偏离默认起点时（例如提前到更早的命中之前，或利用软占用段接反击），从反应卡进入介入编辑；常规卡不提供秒数输入。
- 没有可行选项时不自动暂停，只给不打断的提示并说明原因（沿用已确认规则）。

### 3.7 相对时机（试行，2026-10-26）

背景：按 §3.1～§3.6，常规层只让玩家决定“做什么、打谁”，时间只以风险提示出现，玩起来接近常规回合制。用户的初衷是融合回合制与即时制，但不引入 QTE，也避免 ATB 式的手忙脚乱。本节尝试把动作游戏里的时机判断做成常规层的选项。先以示意图试行（[v5 图 2](示意图/2026-10-26-v5/README.md)；v4 图 5 的情境不可达，已停用），用户看过质感后再决定是否转正。

选好攻击目标后，详情卡列出几种时机。每种都相对一个已公开的对方动作，并直接显示 Logic 预览出的结果：

| 时机 | 换算方式 | 预览要说明的内容 |
|---|---|---|
| 尽早 | 现行默认，接在上一动作末尾（§3.2） | 是否打断对方；对方命中时自己是否空闲、能否反应 |
| 拼刀 | 本次命中与对方命中落在同一 Tick | 双方攻击是否终止；残余冲击及是否致硬直；肾上腺素收益 |
| 抓后摇 | 本次命中落在对方后摇的第一个 Tick | 对方命中时自己是否在前摇、会不会被打断；对方能否反应 |

- **只列合法项。** 起点须在窗口内，并且不早于自身轨道可用的时刻。赶不及的时机置灰并说明原因，例如“赶不及：最早命中 2.6 s”。界面不标“推荐”，由玩家比较结果自行选择。
- **换算为起点。** 界面把所选时机换算成 `AddOrdinaryPlanOperation.RequestedStartTick`，走同一套预览和整批提交，Logic 不需要新接口。锚点用介入时间轴吸附的同一组关键点（对方起点、命中、末尾），见 `TimelineSnap`（[TrackSelectionModel.cs](../../Assets/Scripts/UnityView/TrackSelectionModel.cs)）。
- **加入时固定为绝对 Tick。** 队列项保留时机名称用于显示，例如“② 快斩 · 拼刀”。锚点动作在执行前终止或改变时，不自动重排；队列项标“时机已失效”并重新预览，处理方式与其他风险标记相同。条目要记录来源（自动衔接、相对时机、精确）和锚点；界面为每一项显式发送起点，以免混用空起点时被求值器静默改序。各种编辑事件下的处理见状态表 §3。
- **与自动衔接的关系。** 选“尽早”以外的时机，会在前一项之后留下空隙，位置条和队列显示为“等待 X s”。这放宽了 §1 第 8 条“后项起点自动接前项末尾”：默认仍首尾衔接，只有玩家明确选了时机才留空隙。常规层仍不提供秒数输入，其他起点走介入。
- **拼刀不提前释放轨道。** 位置条同时画出“计划占用到 X”和“预计在 Y 拼刀终止”；下一项从计划末尾 X 衔接，不承诺从 Y 接上（§3.2）。
- **信息边界。** 锚点只取经控制者过滤的公开计划；已知视界外的动作和未公开计划不提供时机选项。
- **首版范围只做攻击。** 移动（例如“在命中前离开范围”）和防守的时机选项，待原型后再评估。格挡/闪避保持 §3.6 的默认命中时刻。

规则观察（待讨论，本稿不改规则）：

- 对方的攻击从起点到末尾一直占用其轨道，所以前摇和后摇期间对方同样不能格挡或闪避。只有同一 Tick 命中才拼刀，而命中落在前摇里还可能打断对方（冲击达到硬直阈值时）。因此按现行规则，“抓后摇”只在赶不及抢先、或抢先会被对方命中时才有意义，本身没有额外收益。
- 在自身窗口里，敌方不能起手新攻击；延续威胁至多一个，来自上一个窗口的拥有者。因此“看到起手再抢先打断”做不到，抢先打断只能作为预先承诺：在窗口末尾起手，命中落在对方开窗之后。三类局面的可达性见状态表 §5，原型须按合法快照逐一验证，而不是增加更多选项。
- 按 v0.5 候选时序（快斩前摇 0.5 s、后摇 0.5 s），“先格挡、再抓后摇”会落空 1～2 Tick：格挡在对方命中的 Tick 生效，快斩最早下一 Tick 起手，命中已在对方后摇结束之后。若希望“防住再反击”成为可用套路，需要前摇短于默认后摇的动作，或给后摇命中额外收益。这属于[人物属性与战斗数值 v0.5](../战斗测试/人物属性与战斗数值完整方案-v0.5-2026-10-23.md)的数值问题。

## 4. 介入界面：特殊能力的操作空间

进入介入后，才出现完整时间维度：窗口条、多单位轨道、动作块、命中点、吸附、游标、未来残影、精确输入及排程草稿。

完整能力以 v0.3 §3～§6 与 M2～M4 实现为核对清单：多单位同轴、窗口可放区、已知视界、公开肾上腺素、动作阶段与硬软占用、跨轨道接触、反应截止/费用/冲突、草稿及授权回执都须有明确位置。不得用一条个人动作条代替完整介入界面。介入时普通控制与详情区共同重排，不能仅在所有常规控件上方叠加新面板。

上一版两种草图仍可用于这一层的布局比较：

| 布局候选 | 用于介入时的价值 | 待验证问题 |
|---|---|---|
| 侧栏工作区 | 全宽时间轴便于多单位命中对齐，反应详情位置固定 | 战场横向空间与详情宽度的平衡 |
| 上下工作台 | 上方保持通栏战场；下方容纳时间轴和配置器 | 轨道较窄，反应警告与精确配置可能拥挤 |

用户在上一轮草图中查看了“上下工作台”；该交互记录不等于已确认最终布局。本轮不继续将两者当作常规 HUD 的二选一。

介入层要能让玩家清楚辨认进入/退出：显示“介入中”，时序工具集中展开。打开时间视图本身不等于取得普通命令权限，编辑能力取决于当前权限：

- 我的窗口：可编辑本方普通计划与反应。
- 他人窗口、尚未授权：普通计划只读，反应仍按反应机会可编辑；同时显示“申请并发授权”、费用与余额。
- 申请中、被拒绝、余额不足、窗口已过期时，给出明确回执与原因，界面不先行解锁编辑。

## 5. 介入与时钟、权限的关系

### 5.1 已确认的必要条件

时间编辑工具启用必须存在玩家的主动介入选择。仅有暂停、普通提交权限或公开威胁，不满足条件。介入本身只打开视图，不产生或扩大权限（§1 第 11 条）。

### 5.2 协议：已定与待定

2026-10-26 按两层语义与现有源码更新。下表前四行已有结论，其余仍待明确。

| 事项 | 结论或待明确的原因 |
|---|---|
| 点击介入后何时展开 | **已定**：时间视图立即展开，不需要权威回执，因为它不授予权限；在他方窗口申请并发授权须等回执成功后才解锁普通计划编辑 |
| 是否只能在他方窗口选择介入 | **已定**：任何窗口都能打开介入；只有并发授权限于他方窗口 |
| 返回常规界面后，授权是否仍持续 | **已定**：并发授权是权威状态，持续到该窗口关闭（游戏设计文档 §5.3）；关闭视图不撤销授权、不退款，也不取消已接受计划 |
| 常规队列的批量提交 | **已定（沿用实现）**：普通动作队列是整批事务，任一失败即整批回滚。授权、普通排程、反应在恢复时分别提交，可能部分提交；展示方式见状态表 §2.3 |
| 时间视图本身是否有代价 | 暂定无。概念稿中“神器介入”消耗熵值；若以后收费，就要重新评估常规界面的信息量，因为公开时序不应变成付费信息 |
| 窗口关闭/授权失效后，界面怎样收束 | 视图可保持打开；须同时处理编辑权回收、未提交草稿、系统暂停与已接受计划 |
| 常规格挡/闪避怎样确认 | 已有提案（§3.6），待原型评审 |
| 常规队列的其余提交问题 | 提案见状态表 §2：主操作合并为“确认并继续”（D1）、权威拒绝时自动暂停（D2），待用户确认。执行遇阻策略仍待定 |
| 精确编辑后返回常规界面 | 提案见状态表 §3.2：新项接在轨道所有计划的最大末尾之后，空隙保留、不压紧；填空隙需进入介入 |
| 常规态的等待/延后 | 试行方案见 §3.7：等待以相对时机（拼刀、抓后摇）的形式出现，不填秒数；用户看过示意图后决定是否转正 |

可先制作界面分层草图，在上述语义明确之前不实现依赖它们的战斗控制。草图中的“介入/返回”只演示界面切换，不模拟代价、授权、命令执行或退出结算。

### 5.3 技术约束（规划）

- 现有 `HudLayoutResolver` 仅依据 Clock、Permission、HasThreat，无法完整表达新的显式介入入口；设计中需要单独的介入界面生命周期输入（视图开/关），与 Permission 正交。
- 现有 `HudSubmissionPermission.CanIntervene` / `Intervened` 的含义保持为“可申请 / 已取得并发授权”；界面文案改称“可申请授权 / 已授权”，避免与“介入中”混淆。v0.3 与游戏设计文档中的“可介入 / 已介入”指并发授权，等本稿冻结后再同步改名。
- 该 UI 生命周期与权威的 ConcurrentGrant/CommandAuthority 分开校验。显示工具不能产生或扩大权限。
- 普通界面和介入界面共用计划数据、权威快照、命令入口与 Logic 预览；只切换起点编辑方式与信息呈现，不创建第二个战斗模拟或独立待确认副本。
- 未启用的时间轴及附属组件应同时停止射线、快捷键、拖动与相关预览刷新；仅将 Canvas 设为不可见不算完成。
- 普通暂停与系统暂停仍按各自输入门禁处理。普通暂停不得自动切到介入界面。
- 返回常规界面时恢复此前选中单位、镜头关注点和普通操作上下文；草稿与授权的处理取决于上述协议，不能用销毁 UI 代替处理。

## 6. 调整后的工作顺序

布局约束补充：CanvasScaler 参考尺寸为 1920×1080、匹配 0.5 时，1366×768 下的缩放约为 0.7，32 单位的紧凑轨道约为 22–23 px。字号放大到 130% 时，行高必须随字号增加，不能只放大文字。2026-10-26 评审确认，v4 在 1366×768 下只证明了“放得进画布”，没有证明“能舒适阅读”。小屏应改为重排布局、轨道滚动和详情展开，同时保留截止、费用和不可用原因，不能继续整体等比缩小。现有场景的参考尺寸写作 1980×1080（`CombatSampleScene.unity`），疑似 1920 的笔误，进入 P4 前核对。

## 7. 必须加入的验收项

1. 启动战斗、我方窗口开启、普通暂停、敌方攻击公开时，未选择介入就不显示也不能操作完整时间轴及其编辑工具；常规动作的只读时间位置预览保持可用。
2. 常规界面可完成“动作/目标→加入短队列→调整→统一确认”；没有时间轴空槽、精确排程编辑器、游标工具栏或起点时刻输入。添加/移除本身不正式下令、不消耗资源；取消当前选择不清空队列。
3. 如提供行动顺序头像，它只展示公开先后；不能通过点击/快捷键偷偷打开未介入的时间编辑器。
4. 普通范围、伤害/结果与预计结束位置在加入前可用；只读窗口位置摘要不启用未来时间游标、残影和命中对齐工具。
5. 时间工具隐藏时，鼠标射线、快捷键、焦点导航、刷新逻辑均不能触发它们。
6. 并发授权申请被拒绝、资源不足或窗口过期时，显示清楚原因，不取得未授权的编辑权；时间视图照常打开，按 §5.2 已定协议验证。
7. 介入返回、窗口切换、系统暂停和战斗结束时，草稿、授权与已接受计划按确认后的协议处理，没有无提示取消、退款或重复提交。
8. 两种分辨率、字号 100%/130%、长名称与多单位场景下，单位、目标、当前动作与关键告警可读；常规无遮挡战场比例与可点击格子实际测量。
9. HUD 只读操作不推进 Tick、不改资源；现有确定性和信息权限继续成立。
10. 本轮真实输入与独立 Player 重新验收。此前 M1～M4 补验是旧实现基线，不能作为新界面已经通过的证据。
11. 空队列不能确认；待确认条目失效时有对应原因，处理方式符合确认后的提交契约。确认防重入，介入往返不重复提交。移动后攻击等序列的范围/目标反馈考虑前序行动，并遵守公开信息边界。
12. 相同动作、目标、起点与快照下，常规自动衔接与介入排程产生一致的时序和结果；动作末尾包含完整占用，前项修改后重新预览后续项。
13. 加入每一项之前都能看到该动作起止位置；窗口内、恰好边界、越界一 Tick 和明显越界均正确表达。起点合法而末尾越界时警告持续可见，加入/确认仍可用；起点非法按既有规则处理。移动、攻击、防守等各类动作均使用这个预览组件。
14. 风险提示不弹窗、不插入布局、不抢焦点、不增加确认次数、不自动进入介入；队列项和摘要在加入后保留风险，回到窗口内时清除。
15. 只读位置条显示已知视界内、指向当前单位的公开命中；视界外只标“之后未知”，不显示未公开计划或推测反应。候选动作占用期间有受击时，提示槽写明来源、时刻与预计结果；该占用使届时无法格挡/闪避时注明原因。
16. 常规界面不进入介入即可完成格挡/闪避：默认起点为命中 Tick；费用、余额与不可用原因可见；自身计划冲突时指明冲突项，未锁定项可经玩家确认后移除；格挡/闪避不显示“越窗”提示。
17. 任何窗口都能打开介入；打开或关闭介入不改变权限、不消耗资源（时间视图代价未定前）。他方窗口未授权时，普通计划只读、反应仍可编辑；申请并发授权的回执与拒绝原因可见；关闭视图不撤销授权、不退款。权限状态与“介入中”分开显示。
18. 主操作按确认后的方案（D1）提交，计数分开显示行动与反应，只有反应时也能确认。普通排程整批失败时定位到具体条目、不出现部分写入；授权、普通排程、反应之间若部分提交，逐条显示“已提交 / 未提交：原因”，不宣称整体成功。
19. （相对时机转正后）每种时机换算出的起点，与在介入中把同一动作吸附到相同关键点得到的起点一致，预览结果也一致。只列已知视界内的公开锚点，不合法项置灰并说明原因。由时机留下的空隙在位置条和队列中显示为等待；锚点失效时标“时机已失效”，不自动重排。
20. 拼刀等预计提前终止时，位置条同时显示计划末尾与预计终止点，下一项从计划末尾衔接；队列混用自动衔接、相对时机与精确起点时，求值结果不改变队列顺序，与请求不一致时按状态表 §3.1 标出。

## 8. 当前状态

- 已确定：常规战斗为主界面；完整时间轴及其编辑工具只在玩家主动选择介入后启用，常规保留只读时间位置预览。介入入口本身属于底部主操作区，是叙事和战斗的核心功能。
- 已确定：本轮首先改善布局与阅读，常规界面参考成熟回合制战术游戏。
- 已确定：普通行动先加入简短行动队列，再统一确认；与介入规划采用同一规则，后项起点自动衔接前项末尾。
- 已确定：加入前提供预期伤害/结果及动作占用位置；末尾越界必须就地提示，不弹窗、不插入打断。
- 已确定（2026-10-26）：介入拆为两层，介入是任何窗口都能打开的时间视图，并发授权在他方窗口另行付费申请；常规只读位置条叠加公开受击标记。
- 已定基线（沿用实现）：普通动作队列整批事务提交；授权、普通排程、反应在恢复时分别提交，可能部分提交。
- 提案（2026-10-26，状态表）：提交契约、条目来源与锚点、编辑事件规则、切换处理、合法快照约束；D1～D4 待用户确认。
- 待评审：只读窗口位置条、固定风险提示槽、紧凑队列的具体布局、移除/修改交互与较长队列的展示；常规反应卡提案（§3.6）。

## 9. 动作质感：后续方向（2026-10-26 讨论）

用户评审 v4 后认为，常规层的“信息流”作战很舒服，但质感过于接近常规回合制，动作元素被削弱。用户明确不引入 QTE 类即时操作。讨论后各方向的定位如下：

| 方向 | 用户判断 | 去向 |
|---|---|---|
| 把时机做成常规层选项 | 可以试行 | §3.7 与 v4 图 5 |
| 让玩家在不确定中决策 | 难点不在信息层，而在 NPC AI 的设计 | 见下方“AI 现状”；在战斗测试中展开 |
| 减少停表（例如窗口打开时慢放而非完全暂停） | 可作为高难度下的挑战；中低难度须避免，设计之初就尽量避免 ATB 式的手忙脚乱 | 作为难度选项记录，不进入默认体验 |
| 表现层（命中顿帧、拼刀慢动作、击退手感） | 必要，但需要大量额外工作与调教经验，暂时难以承担 | 暂缓 |

AI 现状（2026-10-26 核对源码）：AI 下普通动作时不指定起点（`AiCommandRequestBuilder` 中 `RequestedStartTick` 为空），一律接在自身轨道末尾尽早出手，不会主动选择拼刀、等待或抓后摇；反应起点固定取命中时刻（`AiReactionCandidateBuilder`）。玩家能否在常规层感到时机压力，取决于 AI 是否也会读玩家的公开计划、选择时机。§3.7 的时机词汇（尽早、拼刀、抓后摇）可以同时作为 AI 决策与测试的共同语言，具体在[基础战斗与 AI 测试方案](../战斗测试/基础战斗与AI测试方案-v0.1-2026-10-21.md)中展开。

环境时序危险（2026-10-26，搁置）：环境在单个窗口内多次变化，是不依赖 AI 的时机压力来源。界面上，环境在介入时间轴中单独成行，在常规位置条上用独立符号标出。用户把它定为搁置的正式内容，近期不加入，因此不进入本方案的阶段与验收；设计与示意图见[环境时序危险](../灵感/环境时序危险-灵感稿-2026-10-26.md)。本方案调整布局时，介入工作区要能再容纳一行（约 34 个 Canvas 单位），不要把高度用尽。

本稿记录用户方向及下一步规划，不宣称功能已实施。
