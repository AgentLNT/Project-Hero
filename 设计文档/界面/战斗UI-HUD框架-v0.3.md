# 战斗 UI/HUD 框架 v0.3

日期：2026-10-13。本文替代 [v0.2](战斗UI-HUD框架-v0.2-玩法驱动.md) 的屏幕结构，并按同日确认的规则修订（主方案 R1～R4）更新 [v0.1](战斗UI-HUD框架-2026-10-13.md) 中的资源与反应表达。分工如下：暂停、草稿、权限的交互契约仍以 v0.1 §4、§5 为准；规则语义以主方案为准；屏幕结构以本文为准。

本文描述设计目标。R1～R4 规则迁移已完成；M1 时钟、窗口与多草稿已实现，原生与操作证据见 [M1 记录](../../优化任务/执行记录/M1-HUD验收-2026-10-15.md)，其物理键盘实操已由用户复核通过。M2～M4 已实现，2026-10-17 完成真实操作补验及完整 Windows Player 构建、独立战斗和回放验证，范围与证据见 [补验完成记录](../../优化任务/执行记录/M2-M4-补验完成-2026-10-17.md)；正式性能验收仍延期。2026-10-15 的[实施纠偏方案](../../优化任务/方案/交互保真与迁移脚手架退出方案-2026-10-15.md)明确仅接入旧时间轴吸附线，其他沿用 M1～M3 标准，并新增 Shadow 退出要求；真实输入和生产程序集隔离分别提供证据。

## 1. 规则对 HUD 的要求

| 玩法事实 | 来源 | 对 HUD 的要求 |
|---|---|---|
| **A. 回合制外壳、实时底层。** 每个单位轮流获得固定时长的窗口，普通动作的起点必须落在窗口内，动作可以伸出窗口；没有费用预算，也不能提前结束窗口 | R1 | 窗口要画成时间轴上的一段区间，而不是一个数字；鼓励铺满轨道，所以拖放与吸附必须顺手 |
| **B. 他方截至下一窗口的行动，在其窗口关闭时已全部公开** | R1 第 7 条 | 可以给出精确预测。已知视界就是"下一个他方窗口打开"的时刻，视界以外标注未知 |
| **C. 胜负发生在接触瞬间**：拼刀对齐命中帧、拦截与逃脱看移动起止、防御看持续区间是否覆盖命中 | 主方案 0.4 | 核心信息单元是**接触点 ◆ = 何时 × 何地 × 谁打谁 × 预计结果** |
| **D. 防守、格挡、闪避都无前后摇、整段生效**；格挡和闪避在第一个合格接触生效一次就终止，防守按额度多次生效 | R2 | 这三种动作块要画成整段，并预告"会在哪个 ◆ 生效"；被更早命中抢先消耗时必须警告 |
| **E. 格挡和闪避是反应式**：只能针对已公开的攻击放置，花肾上腺素，起点不晚于命中点；命中前硬占用，命中后软占用 | R2 第 3、8 条 | 反应要醒目、就近、可快速完成；默认把起点放在命中点；"格挡后紧接反击"要能直接排出来 |
| **G. 所有单位的肾上腺素公开** | R4 | 每条轨道都显示肾上腺素；我方攻击能否被对方反应，可以确定地预告 |
| **F. 空间精细**：动作的 12 向方向参数、Footprint、击退停止格 | 主方案 0.4.6 | 时间轴和战场必须联动；攻击通过鼠标指向显示范围，点击战场同时选定方向与目标，不引入手动旋转按钮 |

## 2. 屏幕状态：三个独立事实

v0.2 用"观察 / 规划 / 反应"三个互斥模式组织屏幕，但最常见的情况恰恰落在模式之间。例如"我方窗口开着、时间在流动"，又如"规划时出现了新威胁"。本文改为由三个相互独立的事实共同决定布局：

| 事实 | 取值 | 来源 |
|---|---|---|
| 时钟 | 流动 / 战术暂停 / 系统暂停 / 已结束 | `BattleClockController` |
| 提交权限 | 我的窗口（剩余时长）/ 他人窗口·可介入 / 已介入 / 无 | 已提交快照中的窗口与并发授权 |
| 威胁 | 无 / 有指向我方可控单位的已公开攻击（按截止排序） | 已提交快照中的反应机会 |

布局由这三个事实推出，不维护单独的模式状态：

| 时钟 | 提交权限 | 威胁 | 布局 |
|---|---|---|---|
| 流动 | 任意 | 任意 | **战场优先**：精简时间轴（已选单位的轨道），顶栏显示窗口拥有者和剩余时长；我的窗口时常驻"暂停并规划"，他人窗口时显示"介入"按钮；有威胁时，受威胁单位旁显示威胁标记 |
| 战术暂停 | 我的窗口 / 已介入 | 任意 | **规划布局**：时间轴展开，配置器出现，画出窗口区间；有威胁时威胁卡浮在战场上层 |
| 战术暂停 | 他人窗口 / 无 | 有 | **反应布局**：威胁卡为主，时间轴聚焦来源攻击 |
| 战术暂停 | 他人窗口 / 无 | 无 | 只能查看：时间轴可拖动查看，配置器隐藏，并说明"当前不能下普通指令" |
| 系统暂停 / 已结束 | — | — | 覆盖层 |

`HudLayoutResolver` 是一个纯函数：输入三个事实，输出各区域的显隐与优先级。它不保存状态，因此不会出现模式卡住、或两个模式互相覆盖的问题。

### 2.1 自动暂停

| 触发 | 默认 | 说明 |
|---|---|---|
| 玩家可控单位的窗口打开 | 开（已确认） | 窗口有固定时长，不暂停的话，思考时窗口会流走。关闭后即为"主动模式" |
| 已公开攻击指向玩家可控单位 | 开（已确认） | 只在机会**新出现**、且至少有一个选项可行时触发一次（已确认）。可行是指肾上腺素足够、未过截止，并且硬占用段空闲；若硬占用段只与我方仍可编辑的计划冲突，也算可行，卡片提示"需先调整轻斩"。没有可行选项时，只显示不打断的提示，例如"重击 0.8 秒后命中 · 无可用反应：肾上腺素不足" |
| 我方计划被系统终止（含"延期超出来源窗口"） | 关 | 打开后便于理解失败原因 |

同一 Tick 触发多个时只暂停一次，其余机会按截止排在威胁列表里，不替玩家花资源。

自动暂停时，相关单位自动加入选择（见 §3.3）。

## 3. 时间轴：多单位轨道

### 3.1 共用一套刻度

每个单位一条轨道，所有轨道共用同一套刻度、缩放、游标、窗口区间和已知视界线。只有这样，不同单位的命中点才能上下对齐，而读出对齐正是这个玩法的核心。

```text
┌──────────┬───────────────────────────────────────────────────────────────┐
│ 窗口     │[████████ 艾伦的窗口 · 剩余 1.60s ████████][ 狼骑兵的窗口 ……  │ ← 窗口条
│          │ 0s       0.5       1.0       1.5       2.0 ┆视界   2.5   3.0  │ ← 刻度
├──────────┼──────────────────────────────────────────────┼────────────────┤
│▌艾伦 ★  │ [移动──][轻斩 前摇──◆后摇] [重击 前摇──────────◆──后摇──]    │ 主选 64px
│ HP ▮▮▮▯  │ ░░░░░░ 起点可放区（窗口内）░░░░░░░░░░░░░░│                   │
│ 肾上 3   │                       ┃                  ┆                   │
├──────────┼───────────────────────╂──────────────────┼───────────────────┤
│ 瑟兰     │ [防守 ═══════ ▮▮]     ┃                  ┆                   │ 紧凑 32px
╞══════════╪═══════════════════════╪══════════════════╪═══════════════════╡ ← 阵营分隔
│ 敌·狼骑兵│ [突刺 前摇───────────◆]                   ┆ ？？？            │ 紧凑 32px
│ 肾上 2   │                                           ┆                   │
└──────────┴───────────────────────────────────────────┴───────────────────┘
  ┃ = 同一接触点，跨轨道连线      ┆ = 已知视界（下一个他方窗口打开）
```

- **窗口条**：刻度上方的一行，按 Logic 提供的窗口顺序投影画出当前窗口和后续窗口，例如"艾伦 → 狼骑兵 → 艾伦"。未来窗口因单位死亡、动态生成等可能变化，画成浅色并标注"预计"。
- **起点可放区**：有提交权限的轨道上（我的窗口时是我方单位，介入后是主角），用浅底色标出当前窗口区间。拖放时，起点吸附在区内；动作块可以伸出区外。起点越界时块变红，并说明"起点必须在艾伦的窗口内"。
- **已知视界线**：位置是下一个他方窗口打开的 Tick。视界内的他方轨道是完整、精确的；视界外显示"？"。我方接触点 ◆ 落在视界外时画成空心，表示对方可能还没出手。视界内只剩一种不确定：对方可能对我方已公开的攻击作出格挡或闪避。由于肾上腺素公开（R4），对方能否反应可以由 Logic 预览确定，◆ 的角标据此分三种：
  - 不带角标：对方无法反应，结果确定。
  - "可被格挡 / 可被闪避"：对方能用的选项，附对方肾上腺素，例如"对方 2，够格挡，不够闪避"。
  - "对方届时在后摇"：说明对方因硬占用冲突无法反应，提示这是好时机。
- **默认缩放**：显示当前窗口加上后面一个窗口的长度（约 6 秒），轨道区可以缩放和平移，"回到当前"常驻。

### 3.2 排列顺序：固定排序，与点击先后无关

| 规则 | 说明 |
|---|---|
| 按阵营分组 | 我方可控 → 友方 → 中立 → 敌方，组间有分隔线。我方在上、敌方在下，接触点连线都会穿过分隔线，谁打谁一眼可读 |
| 组内按出场槽位顺序 | 动态生成的单位按 SpawnId 排在后面。不用窗口顺序，以免轨道随顺序变化而跳动 |
| 位置稳定 | 新增的轨道插入它在排序中的位置；取消选择后，该轨道收起，其余轨道合拢；主选只高亮不移动 |

### 3.3 选择规则

| 操作 | 结果 |
|---|---|
| 单击未选中的单位 | 只选中它（替换当前选择），并设为主选 |
| Ctrl + 单击未选中的单位 | 加入选择，并设为主选 |
| 单击已选中的单位（按不按 Ctrl 都一样） | 取消选择它。若它是主选，主选交给选择历史中最近的单位 |
| Tab / Shift+Tab | 在已选单位之间按轨道顺序正向/反向切换主选，不改变选择集合 |
| 单击轨道标题 | 设为主选（Tab 的鼠标替代） |
| 轨道标题上的 ✕ | 取消选择 |
| 单击空地 | 无效果，防止误点清空 |
| 配置器正在等选目标或落点 | 左键用来选目标，不改变选择；Tab 不响应；Esc 退出选目标 |
| 输入框有焦点 | Tab 留给输入框 |

- **主选**：配置器的下令主体，肾上腺素与单位详情跟随主选。主选轨道展开（64px），显示动作阶段、◆ 的文字和草稿行；其他轨道紧凑显示（32px），只画动作块和 ◆。
- **自动选择**：
  - 我方窗口自动暂停时，窗口拥有者加入选择并成为主选。
  - 威胁自动暂停时，受威胁单位成为主选，攻击者作为**临时轨道**加入，标题用虚线边。威胁结算后，临时轨道自动移除，除非玩家点过它。
- **未选中的接触对象**：跨轨道的 ◆ 若对方未被选中，就在 ◆ 旁显示对方名字的小标签，点击标签等于 Ctrl + 单击把对方加入。
- **什么都没选时**：只显示窗口条、刻度和一行"指向我方的已公开威胁"汇总，保证威胁不会因为没选人而看不见。

### 3.4 空间不足时

1366×768 下，轨道区约 200px，可放下 1 条主选轨道加 4 条紧凑轨道。超出后轨道区可垂直滚动，窗口条、刻度、游标和视界线保持固定；滚出视野的已选单位以"+2 ▾"标签留在边缘；主选轨道始终自动滚入视野。已选数量不设上限。

## 4. 动作块与接触点

| 动作 | 轨道画法 | 附加信息 |
|---|---|---|
| 攻击 | 三段：前摇 ─ ◆ ─ 后摇 | ◆ 的形状和文字表明预计结果：命中 / 拼刀 / 被格挡 / 被闪避 / 被拦截 / 逃脱，不只靠颜色区分。后摇段标"对方可反击"，提示天然的反击时机 |
| 移动 | 一段，按路径边分隔 | 战场同步画路径和终点朝向 |
| 防守 | 整段实心，右端画额度格 ▮▮（剩余可生效次数 = 剩余额度 ÷ 配置比例，向下取整） | 视界内落在区间里的已知 ◆ 逐个标注"抵 50%"；预计额度用完的位置之后，画成虚线并标注"额度耗尽" |
| 格挡 / 闪避 | 硬占用段（起点到来源命中点）画成实心；软占用段（命中之后）画成斜纹，表示普通动作可以放进来。在预计生效的 ◆ 处收束，之后画成虚线（表示届时终止、轨道空出）；若有普通动作的起点落在软占用段里，从该起点起画成虚线，并标注"在此让出轨道" | 若会被更早的合格命中抢先消耗，整条变成警告色并写"将被轻斩先消耗，重击未被挡住"；闪避在战场显示落点，并提示新格是否仍被覆盖、会使几条未来移动失效 |

状态表达沿用 v0.1 §5：草稿为虚线加序号，待恢复提交、待采纳单独标注，Editable 为实线，锁定/执行中加锁标识和阶段进度，系统延期显示原位置与新位置，完成/中止降强调。新增两个终止原因要写成玩家看得懂的文字：

- "延期超出窗口，已取消"
- "已生效"或"未遇到命中，已结束"（格挡与闪避）

接触点 ◆ 是同一个对象，在三处显示并联动：时间轴、战场目标格（附距命中秒数）、跨轨道连线。在任一处选中，其余两处同步高亮。

## 5. 反应卡

```text
            敌·狼骑兵 ──重击──▶ ◆ 艾伦
          ┌──────────────────────────────────────────┐
          │ 重击 · 0.80s 后命中 · 输入截止 0.78s       │
          │                                          │
          │ [格挡]  肾上腺素 2 · 持续 1.0s              │
          │ [闪避]  肾上腺素 3 · 持续 0.5s  → 战场选落点 │
          │         成功换位将使 1 条未来移动失效       │
          │ [不响应]                                  │
          │                                          │
          │ 起点  ├──────────────────●┤ 命中           │
          │       现在               默认=命中点       │
          │ ⚠ 0.40s 处有轻斩，起点早于它会被先消耗     │
          └──────────────────────────────────────────┘
```

- **放置条**：显示允许的起点范围（从下一 Tick 到命中点），默认停在命中点；拖动时，时间轴同步显示该格挡块。起点范围内若有更早的合格接触，在条上标出，并警告越过它的起点。
- **截止**：显示输入截止，而不只是命中倒计时。截止过后选项置灰并写明原因。
- **不可用的选项**保留按钮，并写明原因，例如"肾上腺素不足（需 3，有 2）""0.80s 处艾伦正在攻击后摇"。轨道冲突时提供"跳到冲突计划"，方便玩家改动尚未锁定的普通计划。
- **多张卡片**按截止排序叠放，任何抽屉都不能遮挡。
- **肾上腺素提示**：卡片角落显示"下次自身窗口打开时，可用肾上腺素清零"，以及距那时的秒数，鼓励玩家用掉。

## 6. 战场联动与时间游标

沿用 v0.2 §4，做两处调整：

- 游标默认跟随当前时刻。在规划或反应布局中，拖动游标，战场显示该时刻的残影：我方按计划所处的位置与朝向，以及已公开攻击的作用范围。首版范围不变（已确认）：击退落点、伤害数值等结果预览只放在配置器里，读取 Logic 预览，UI 不自行计算。
- 视界内的他方单位按其已启动的计划投影，视界外保持当前位置并标注"未知"。

## 7. 三种典型屏幕

1920×1080 为参考，1366×768 必须能完成全部操作。

**时间流动（我的窗口）**

```text
│                                                                │
│                         战  场                                 │
│              ◆ 0.8s ← 狼骑兵·突刺（已公开）                     │

```

## 8. 技术框架

沿用唯一推进链 `BattleRuntimeBootstrap → UnityBattleDriver → Logic`，以及 v0.1 §8 的组件职责。相对 v0.2 §7 的变化如下：

```text
Logic 快照 ──▶ HudProjection（按控制者过滤的只读投影，每个已提交快照一份）
                 │
   ┌─────────────┼──────────────────┬───────────────────────┐
   ▼             ▼                  ▼                       ▼
HudFacts      TimeCursor       TrackSelectionModel     ScheduleDraftModel
时钟/权限/威胁  跟随或指定 Tick   选择集合 / 主选 / 历史   （见 v0.1 §8）
   │                                │
   ▼                                ▼
HudLayoutResolver（纯函数）     TrackLayoutModel（排序、展开/紧凑、滚动）
   ▼
各区域 Presenter ──▶ Canvas 分层：WorldOverlay → ScreenHud → PromptLayer（反应卡/确认框）→ DiagnosticLayer
   │
玩家意图 ──▶ ScheduleDraftModel ──▶ ViewCommandFactory ──▶ 命令入口
```

| 组件 | 变化 |
|---|---|
| `HudModeMachine`（v0.2） | 删除，由 `HudFacts` 加 `HudLayoutResolver` 替代 |
| `TrackSelectionModel` | 新增。管理选择集合、主选、选择历史，以及自动选择加入的临时轨道；只是 UI 状态，不进入命令或回放 |
| `TrackLayoutModel` | 新增。按阵营、槽位、SpawnId 排序，处理展开/紧凑与滚动 |
| `HudProjection` 需要 Logic 新增的只读数据 | 当前与后续窗口的区间及顺序投影；已知视界 Tick；Guard 剩余额度；格挡/闪避的预计生效接触、硬/软占用分界与预计让出点（基于公开信息的预览）；反应选项的起点范围、输入截止与可行性；所有单位的肾上腺素可用值与预留（R4）；"对方能否反应"预览；新增终止原因 |
| v0.1 预算相关的投影 | 删除 |

约束不变：HUD 只能请求暂停或恢复，不能 Step；自动暂停在 Tick 边界根据已提交快照中的事件判定，不看动画状态。HUD 不运行第二个模拟，不自行计算预测结果。旧 `TimelineEditorUI` 仅保留关键帧吸附及吸附线这一项功能，按纠偏方案 C1 接入 M2 多单位轨道；其余布局、样式、草稿及反应交互按本文 M1～M3 标准实施。旧 Player/Observed 双轨与新方案冲突，不保留；幽灵插入交互继续搁置，不列入本轮实施或验收。不要求恢复旧 Canvas 或重新启用旧写入组件；Logic 的受限向右避让规则不因搁置该 UI 而改变。
