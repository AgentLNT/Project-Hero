<a id="定位"></a>
## 1. 项目定位与体验目标

游戏的产品方向是叙事驱动的小队战术 RPG。玩家扮演农场青年艾伦，在时间异常的时漏城担任卫兵，与具有意识的时间神器克罗诺斯共同经历选择、代价与责任。世界观、人物与叙事主题见[概念设计](概念/游戏概念文档.md)及[叙事写作](概念/游戏概念写作_v2.md)；这些原始概念材料中的旧战斗描述不覆盖本文。

战斗的核心体验是在同一条连续时间轴上，利用轮到自己的行动窗口、个人反应资源和精确空间关系，塑造对自己有利的接触时刻。玩家既要决定做什么，也要决定何时命中、站在哪里、承受哪些风险。

| 设计支柱 | 玩家体验 | 规则约束 |
|---|---|---|
| 回合窗口与连续时间轴 | 单位轮流获得固定时长的行动窗口，在窗口内尽量铺满自己的轨道；已经安排的动作继续执行 | 起点须落在窗口内；窗口切换不取消、截断、加速或重排动作 |
| 时间与空间联合规划 | 对齐命中时刻、覆盖防守有效期、改变落点 | 时间使用整数 Tick，空间使用逻辑网格 |
| 主动规划与威胁反应 | 攻击、移动、防守负责布局；格挡、闪避应对公开威胁 | 两类动作的权限和费用分别校验 |
| 可解释的确定性 | 相同条件下结果可复现，失败有明确原因 | 相同规则、配置、输入、种子及兼容环境下重演一致 |
| 表现服务规则 | 动画、音效、命中反馈帮助理解结果 | 动画播放、顿帧和镜头不能改变战斗判定 |

“确定性”不等于所有敌方未来都可见。自己的可编辑计划和他人的已公开攻击属于不同的信息权限；所有单位的肾上腺素公开。预测必须说明所依据的公开信息。AI 如使用随机决策，须使用被记录的确定性种子与状态，不能引入随机伤害浮动。

### 1.1 产品循环与非战斗系统方向

| 层级 | 保留的产品方向 | 仍需明确的内容 |
|---|---|---|
| 单次任务 | 巡逻、调查、对话、战斗，解决城市中的具体问题 | 任务模板、失败后果、调查与战斗的衔接 |
| 队伍与城市管理 | 分配队员任务、处理城市事件，承担资源配置责任 | 队伍控制方式、管理周期、技能和城市状态数值 |
| 主线与长期选择 | 推动势力变化、人物关系和结局 | 分支条件、长期资源、关系阈值和可验证的状态变化 |

概念稿中的“熵值/可能性”表达使用神器的便利与凡人方式承担责任的长期差别。其名称、收支、成长及结局阈值尚需单独冻结，**不直接等同于当前并发行动的局外货币**，也不在战斗中恢复法力、专注或体力。世界晶化、关系变化、时间视觉调查等保留为内容方向，尚不作为已实现功能。

对话与调查拟通过角色技能、哲学选择和与神器的关系改变信息与选项。完整养成可以生成战斗次要属性，但不得绕开已冻结的定义构建、ActionSet、权限和费用契约。现有战斗原型不代表城市管理或叙事系统已经落地。

### 1.2 叙事结构与人物职责

三幕方向保留为“艾伦进城并追问英雄是什么 → 集体失忆调查与英雄代价 → 势力冲突中的最终承担”。艾伦承载玩家选择，瑟兰呈现被他人期待塑造的困境，艾利斯塔·Tempus体现秩序与控制的代价，瑞文体现破坏性自由，克罗诺斯不断追问便利的代价。

结局由长期行为、关键支线和人物/神器关系共同构成；原概念稿中的固定比例与“真结局”条件属于旧提案。当前不为其补设新阈值，不将战斗胜负的 VictoryDefinition 扩展成叙事结局判定。

<a id="循环"></a>
## 2. 核心循环与时间模型

产品层的循环保留“任务与对话 → 战斗与选择 → 承担后果 → 人物和世界变化”的概念方向。本轮冻结范围集中在战斗系统；叙事分支、完整养成和局外经济的内容与数值仍需独立设计。

战斗循环为：观察窗口、空间和公开威胁 → 规划普通动作或选择反应 → 预览合法性及代价 → 提交请求 → Logic 在下一正常 Tick 校验 → 启动和结算 → 根据新快照继续决策。

### 2.1 一条时钟、两种时间概念

- **逻辑时间**是整数 Tick。当前基准为每秒 60 Tick；秒用于配置录入和界面展示，进入逻辑前统一量化。
- **窗口打开时长**是逻辑时间里的一段固定区间。轮到某个单位时系统打开窗口，默认持续 180 Tick（3 秒），到期自动关闭，轮到下一个单位；具体场次读取定义。窗口不能提前结束，也没有费用预算。
- **普通动作的起点**必须落在窗口区间内，动作本身可以延伸到窗口之外。动作数量与总时长不另设限制，只受窗口区间和 ActorLane 串行约束。设计意图是让玩家尽量铺满轨道，也允许在窗口末尾安排一个很长的动作。
- **动作占用时间**由动作时序确定。同一单位的普通动作在自己的 ActorLane 排队，不同单位的动作可以重叠。
- **窗口关闭**只收回新增普通动作的权限，并结束该窗口的并发授权。下一窗口不必等待旧动作完成。

例如，A 在自己窗口的末尾安排了一次很长的重击；窗口到期后 B 获得新窗口。A 的重击仍按原定时序推进，可以与 B 的攻击、防守或反应发生交互。由于窗口关闭时 A 的计划都已启动，B 在自己的窗口里看到的就是 A 截至下一窗口的全部行动，唯一的例外是 A 对 B 的攻击作出的格挡或闪避反应。

### 2.2 战术暂停与滚动规划

已经确认的目标交互允许玩家在 Tick 边界暂停战斗、反复预览多条本地指令，恢复后再由正常 Step 采纳。暂停期间不修改权威计划、肾上腺素或位置，窗口剩余时长也不减少，也不因确认草稿偷偷推进一个 Tick。

“应用排程”在暂停时封存本地列表，显示“待恢复提交”；恢复时重验快照、窗口和排程修订，并在 T+1 的正常命令阶段接受或拒绝。未确认草稿在恢复前提供“应用并继续／保留草稿并继续／返回规划”。系统菜单暂停另行禁止战斗投递。

本地草稿不是第二套逻辑排程器。玩家可随时规划、应用、观察、再规划，不要求一次排完整个窗口。自动暂停、多草稿和暂停恢复采纳已在 M1 实现；多单位轨道、完整反应卡和时间游标残影仍待后续里程碑。

<a id="资源"></a>
## 3. 资源与属性

### 3.1 行动限制与资源

| 限制或资源 | 归属与获得 | 作用 | 清理与保留 |
|---|---|---|---|
| 行动窗口（不是资源） | 轮到该单位时系统打开，固定时长 | Attack / Guard / Move 的起点必须落在窗口内；没有费用、不计账 | 到期关闭；已接受的计划继续执行 |
| 肾上腺素 | 每个单位独立持有；实际造成/承受伤害、拼刀及成功格挡/闪避产生收益 | Block / Dodge 接受时预留，生效时消费 | 可用值跨他人窗口保留、不随时间衰减；下一次自身窗口打开时可用值清零，已接受的反应预留继续履约 |

普通动作不再有时间费用。原"时间预算"及其"可用 / 预留 / 消费"账本已按主方案 R1 取消；它是重构时引入的，不属于原始设计。

肾上腺素按实际伤害在单位/Tick 维度聚合量化，拼刀按单位/冲突组、成功反应按计划各奖励一次。个人周期上限由规则定义；成功 Block/Dodge 的奖励必须低于相应费用，防止反应自行回本。已有预留不重复计入可用余额或重复消费。

生命值是生存状态；并发行动使用的局外资源是能力授权成本。二者都不是普通战斗动作的费用。体力、专注点、护甲重量资源、体力衰竭、专注取消后摇均不属于当前战斗模型。

### 3.2 当前战斗属性

| 属性 | 作用 |
|---|---|
| Health / MaxHealth | 当前生命与上限，生命归零进入死亡流程 |
| Mass | 生成动量及抵抗控制的基础量 |
| ActionSpeed | 量化新攻击的相对前摇，不缩短固定后摇 |
| MoveSpeed | 量化新 Move 每权重单位的 Tick，不参与选路 |
| MomentumSpeed | 动量生成与控制抵抗基准；与 ActionSpeed 独立 |
| 分通道基础抵抗 | 对对应伤害通道施加被动抵抗 |
| ActionSet | 决定单位拥有的普通动作和反应能力 |

STR、DEX、CON、INT、WIS、CHA 等养成主属性及装备成长映射保留为概念方向，尚不作为当前战斗判定的另一套输入。质量可以保留，不能恢复“护甲重量影响体力”的旧资源链。

<a id="动作"></a>
## 4. 动作族、时序与排程

### 4.1 五种动作

| 动作 | 玩家名称与用途 | 权限与费用 | 有效时刻 |
|---|---|---|---|
| Attack | 攻击；创造伤害和冲击 | 起点落在当前窗口内（自身窗口或并发授权） | 速度修正前摇结束时命中一次，之后固定后摇 |
| Guard | 防守；预先覆盖一段风险时间 | 同上 | 无前后摇，整段持续都生效；每个命中 Tick 部分抵抗伤害和动量，消耗抵抗额度，额度用完即终止 |
| Move | 移动；沿合法路径调整站位 | 同上 | MovementSegment 按路径边权逐步推进逻辑位置 |
| Block | 格挡；抵抗公开攻击的合格载荷 | 有效反应机会，消耗个人肾上腺素 | 无前后摇，整段持续都生效；在第一个合格接触 Tick 完全抵抗该 Tick 全部合格载荷，随即终止 |
| Dodge | 闪避；在命中时改变位置 | 有效反应机会，消耗个人肾上腺素 | 无前后摇，整段持续都生效；在第一个合格接触 Tick 原子换位并检查新格，随即终止 |

### 4.2 攻击时序

攻击使用“前摇 → 单次命中 → 后摇”。普通计划首次进入 Editable 时按当时属性量化一次：

```text
修正前摇 = max(1, RoundHalfUp(基础前摇 Tick × 20 / ActionSpeed))
ImpactTick = StartTick + 修正前摇
EndTick = ImpactTick + 后摇 Tick
```

默认攻击后摇为 30 Tick（0.5 秒），定义可显式配置；后摇不受 ActionSpeed 或肾上腺素缩短。计划建立后的速度变化只影响之后新建的计划。移动、延期或重新排程改变绝对 Tick，不重新采样速度。首版攻击只有一个命中时刻，不包含多段伤害或弹性吟唱。

攻击的后摇是天然的反击时机：命中落在对方后摇里的攻击，对方无法用这次攻击拼刀。规则不另设"反击窗口"。

### 4.2.1 防守、格挡与闪避的时序

三者都没有前摇和后摇：`[StartTick, StartTick + 持续时长)` 整段都在生效，持续时长由动作定义固定。

| 动作 | 生效方式 | 结束 |
|---|---|---|
| Guard | 每个有合格接触的 Tick 部分抵抗伤害和动量，并扣除抵抗额度（总额 1024，同 Tick 多次接触只扣一次） | 额度用完或持续走完 |
| Block | 持续内第一个合格接触 Tick 完全抵抗该 Tick 全部合格载荷 | 生效后立即终止；未生效则持续走完后终止，无效果、不退款 |
| Dodge | 持续内第一个合格接触 Tick 原子换位，按旧格/新格表判定 | 同 Block |

Guard 不得强过 Block：配置比例必须小于 1024，额度总和为 1024，且可被 Guard 的载荷必须同样可被 Block。由此可以证明，对任意命中序列，Guard 在每种载荷上累计抵抗的量都不超过最大单个 Tick 的载荷。默认持续时长：Block 1.0 秒、Dodge 0.5 秒、Guard 1.0 秒。

### 4.3 普通计划生命周期

普通计划从创建起使用同一个稳定 ActionPlanId：**Editable → 原子锁定并启动 → Running → Completed / Terminated**。Locked 是普通计划启动事务跨过的不可变边界，不允许留下“锁定但未启动”的普通计划；固定反应接受后直接 Locked，等待自身固定时序。

Editable 计划可由排程事务增、移、删和向右避让。每次编辑都校验排程修订和当前窗口；编辑结果的起点必须仍在其来源窗口内。Locked、Running、终态和已接受的反应区间不能自由拖动或删除。

同一单位的 Lane 包含动作完整区间及后摇。一次事务在候选中同时校验时间、窗口区间、路径和空间预留，成功才提交，失败零写入。先成功接受的命令持有预留，后续命令不能用另一种优先级抢占。

### 4.4 启动门禁、延期与终态

到期普通计划先经过执行前门禁。可启动时，冻结执行字段、锁定和启动必须一起完成。

若受到具有明确结束 Tick 的硬直、倒地、起身恢复或限时空间阻塞，系统用相同排程求值器将该 Editable 计划及其后续依赖向右延期。延期后的起点仍须在来源窗口内，否则该计划按"延期超出来源窗口"终止。固定反应、Locked/Running 计划和其他 Lane 不被推走。不知道恢复时刻、目标/路径永久失效、超过延期次数或视野上限时，计划同样按明确原因终止。

自然完成、主动删除、目标失效、来源威胁取消、拼刀/拦截/控制、空间承诺破坏、防御生效或额度用完、死亡和战斗结束都经过唯一终态协调器。清理从属 Intent、移动段、空间预留和活动索引，保留历史；不回卷 ID、不撤销已提交结算、不自动前移后续计划。

<a id="反应"></a>
## 5. 威胁反应与并发行动

### 5.1 反应机会

只有攻击锁定、启动并公开后，才为实际受威胁且具有相容动作的单位创建 ReactionOpportunity。敌方 Editable 计划不会提前暴露。每个来源攻击/防御者最多一个机会，一个机会最多接受一次反应。

控制者选择格挡或闪避、起点以及闪避落点：

```text
允许的起点：T+1 ≤ StartTick ≤ 来源攻击的 ImpactTick
持续区间：[StartTick, StartTick + 持续时长)，必须覆盖 ImpactTick
输入截止：来源 ImpactTick − 输入提前量
```

HUD 默认把起点放在 ImpactTick。起点越早，越可能被更早到达的其他合格接触抢先消耗。Tick N 新公开的机会最早产生 N+1 请求，玩家和 AI 使用相同提前量。只有公开时距命中不足输入往返的攻击才会被标为不可反应。

接受前校验控制权、ActionSet、来源、截止、状态、Lane、落点和肾上腺素；与自身已有计划冲突时拒绝，不顺延反应、不自动重排普通计划。玩家可另行编辑尚未锁定的普通计划绕开冲突。反应接受后锁定，不能拖动。

反应的轨道占用分两段。从起点到来源命中点（含）为**硬占用**，不能与其他计划重叠，接受时只校验这一段。命中点之后到持续结束为**软占用**，普通计划的起点可以放进去。普通计划到达起点时，如果反应还没生效，反应就让出轨道并终止，肾上腺素不退。因此"格挡后紧接反击"可以直接排出来。

来源在触发前取消时终止绑定反应并释放目的格预留；肾上腺素只在预留仍属于当前个人周期时返还可用，跨周期只删除预留。主动取消、控制、死亡或自身落点失效不退款。系统不代替单位自动选择反应；AI 通过同一命令入口作出自己的决策。

### 5.2 格挡和闪避的结果

Block 在持续区间内第一个合格接触所在的 Tick 生效，对该 Tick 的合格可格挡伤害分量与动量完全抵抗（1024/1024），随即终止。合格接触不限于来源攻击。同 Tick 可处理多个攻击，但不终止来源攻击、不保护同一 AOE 的其他目标。绕过分量仍可能造成伤害，结果区分完全格挡、部分格挡和无效格挡；实际降低载荷才算成功反应。

Dodge 同样在第一个合格接触所在的 Tick 生效。落点在放置时预览，生效时再校验；届时不合法则失败，照样消耗。逻辑先冻结本 Tick 换位前接触，再按稳定顺序提交落点，并用最终新格检查：

| 旧格接触 | 新格接触 | 可闪避攻击 | 不可闪避攻击 |
|---|---|---|---|
| 有 | 无 | 记为避开 | 保留旧接触并作用于换位后的单位 |
| 有 | 有 | 仍被命中，只结算一次 | 仍被命中，只结算一次 |
| 无 | 有 | 新增正常命中 | 新增正常命中 |
| 无 | 无 | 没有接触 | 没有接触 |

实际换位成功与成功避伤分别记录。至少避开一个原有可闪避接触，才有一次成功闪避奖励；单纯换位、换进攻击范围或仍被 AOE 覆盖不算成功避伤。原"反击窗口"已删除（主方案 R3）。

如果 Dodge 实际改变位置，依赖旧起点的未来 Editable Move 及其传递移动链在同一原子事务中终止，并释放路径预留。其余 Attack/Guard 保留原 Tick，不自动改路、压缩或重排。接受 Dodge、预览或未换位失败都不提前取消移动链。确认前必须提示可能失效的移动数量，触发时重新求值。

### 5.3 并发行动

主角在自身窗口之外，可支付局外资源获得当前窗口的额外普通动作提交权。窗口仍属于原单位，主角的 Attack / Guard / Move 起点同样必须落在该窗口内；各自 Lane 独立，动作可以在时间上重叠。

并发授权在窗口关闭时结束，已接受计划仍继续。Block / Dodge 资格与该授权独立：未介入也能反应，已介入而没有有效机会也不能格挡或闪避。能力资格、局外货币名称、费用和余额读取配置，不在设计稿或 UI 中写死。

## 6. 网格、移动与强制位移

### 6.1 离散三角网格

三角格几何保留精细站位与 12 向朝向。逻辑采用 doubled coordinates，合法 GridPoint 满足 X+Y 为偶数；单位 Footprint、攻击区域、障碍和 Encounter 边界共同决定空间合法性。逻辑格和整数展开表是判定依据，模型 Transform 和视觉插值不能反向决定命中或占位。

| GridDirection | 方向 | 路径边权 |
|---|---|---:|
| 0 / 2 / 4 / 6 / 8 / 10 | East / NorthEast / NorthWest / West / SouthWest / SouthEast | 1 |
| 1 / 3 / 5 / 7 / 9 / 11 | EastNorth / North / WestNorth / WestSouth / South / EastSouth | 2 |

路径费用使用整数权重。MoveSpeed 只确定每权重单位 Tick，因此权重 2 的边消耗权重 1 边的两倍时长，不能用视觉距离、段数或方格“斜向成本”替代。

A* 使用固定邻居顺序与稳定平局规则，开放集按 f、h、X、Y 排序。首版上限为 4096 展开节点、256 总权重、192 路径边，等于上限仍合法；搜索范围由 Encounter 显式网格边界限定。路径失败必须有稳定原因，预览、AI 和实际提交使用同一规则。

普通移动逐段提交位置，并持有合法的时空 Reservation。编辑更早移动改变预测起点时，依赖链的路径、绝对时刻、费用和预留一起重算，但不重新采样移动速度。

### 6.2 同时强制位移

击退独立于普通 Move、寻路与普通预留竞争。同 Tick 全部位移请求在不可变网格快照和临时占位中逐格同时求解，最后一次性批量提交：

- 边界、障碍和静止单位阻挡时，停在最后合法格；首版不连锁推人。
- 多人争同一落点、交换和封闭循环全部失败，不按力量大小选赢家。
- 只允许最终通向空格的合法位移依赖链；这是同批已有位移请求的协同结果，不是碰撞后新增推人请求。
- 强制位移优先于未来 Reservation；先终止被破坏的空间计划、释放预留，再批量换位，之后提交控制状态与死亡。

停止原因和实际落点进入语义事件与预览。撞墙剩余能量转挤压伤害、碰撞台球、连续推人、投掷物和动态可破坏地形均不是当前默认规则。

## 7. 伤害、动量与多方交互

### 7.1 两种独立载荷

每次接触分别携带伤害分量和动量包。伤害通道使用稳定 ID，首版包括 physical.blunt / slash / pierce、elemental.fire / frost / lightning、arcane、true；动量包使用离散方向、整数强度及独立 ImpactProfile。相同名字的伤害通道与冲击 Profile 也必须分别配置。

伤害按“被动抵抗 → 动作抵抗”依次乘算，不把抵抗相加。Q10 的 1024 表示完全抵抗。Guard 提供合格分量的部分抵抗；Block 对可格挡载荷完全抵抗；绕过标签分别跳过对应层。true 默认同时绕过被动与动作抵抗，不能再标为可 Guard/Block 的矛盾分量。

攻击 Intent 生成时，从质量、MomentumSpeed、动作发力倍率与冲击传递系数量化一次整数动量。兼容冲击 Profile 的传递百分比为钝击 100、劈砍 60、穿刺 30，这些百分比不代表相应伤害抗性。直接冲击分量和拼刀残余冲击分量分别使用规则规定的除数 5000 与 1000，不沿用旧稿“动量 × 0.1 无视护甲”的独立公式。

### 7.2 冲突图与求解优先级

同 Tick 先冻结 Intent 和空间输入，完成到期 Dodge 的位置事务，再建立冲突图；所有相关攻击与目标纳入连通组，同时求解后统一提交。阶段顺序为：

1. Dodge：根据旧格/新格决定空间接触是否保留。
2. Block：抵抗本 Tick 合格入射载荷。
3. Clash：同时计算全部有效攻击之间的有向动量损耗。
4. Move 结束边界：拦截命中并终止该目标的移动。
5. Move 开始边界：该移动目标逃脱，相应命中失效。
6. 剩余命中：应用 Guard/被动抵抗，聚合伤害、总冲击和有向合力。

接触失效、整个动作终止和目标聚合是三种不同结果。Block/Dodge 对单个目标的成功不取消整个 AOE。参与有效 Clash 的攻击动作都在组末终止，剩余动量仅转为对直接拼刀对手的残余冲击，不让原攻击继续扫到其他目标。

AOE 定义明确选择 AllTargetsInArea 或 PrimaryTargetOnly。后者固定合法主目标，不根据容器顺序临时换目标；两者都遵守阵营关系掩码。

### 7.3 控制与击退

目标的控制抵抗基准为 `max(1, RoundHalfUp(Mass × MomentumSpeed × 100))`。总入射冲击达到该基准产生硬直，达到其 1.5 倍向上取整的阈值产生击倒；击退步数使用有向合力强度除以基准向下取整。

伤害、硬直用的总冲击、击退用的合力分别聚合。两股等强反向冲击可以造成伤害和控制而没有击退。首版是版本化的离散玩法模型，不按连续刚体物理、地面摩擦浮点公式或接触遍历顺序即时改变世界。

<a id="阵营"></a>
## 8. 单位状态、阵营、控制与胜负

### 8.1 状态与持续效果

统一状态机包含 Idle、Windup、Recovery、Moving、Guarding、Blocking、Dodging、Staggered、KnockedDown、Recovering、Dead。动作状态描述当前执行阶段；是否能新增动作仍由 Lane、权限和门禁判断，不能仅看 Idle。

控制与持续效果只在 Tick 阶段生效、到期或触发。Guarding 只按额度部分抵抗，不是免伤；Blocking/Dodging 只在第一个合格接触 Tick 生效一次，不是持续无敌。硬直/倒地/起身恢复的时长与状态链来自定义；旧稿“消耗动作时间手动起身”和体力衰竭不作为首版规则。

### 8.2 阵营与控制分开

Encounter 槽位指定稳定 FactionId，战斗中不可变。同单位为 Self，同阵营为 Allied；不同阵营显式配置对称 Allied / Neutral / Hostile 关系。攻击用 TargetRelationMask 声明可影响哪些关系，命令校验、AOE、机会生成和 AI 选目标共用同一解析器。

ControllerBinding 只决定谁有权控制单位，不决定敌我、胜负或反应资格。玩家与 AI 使用同一入口、同一费用、同一反应机会和输入提前量；一个出场槽位首版只绑定 Player 或 AI 中的一个来源。

队友控制方式仍待定。多个我方单位全手动、或主角手动且队友全 AI，均可按现有独立绑定表达；“AI 自动走位防御、玩家同时拖动该队友进攻时机”的混合控制需要新增协议，不能作为已支持功能。HUD 按玩家可控单位集合组织，AI 队友计划公开前也不向玩家泄露。

### 8.3 死亡、胜负与动态单位

生命归零通过死亡流程终止所属计划、清理资源/空间预留和占位。消灭目标读取 VictoryDefinition 中互斥的 Allied/Hostile 目标阵营集合；未列入集合的其他阵营不会阻止该目标完成。同 Tick 双方目标全灭结果为 Draw，不由遍历先后决定赢家。

战斗结束在该 Tick 完成统一清理并发布一次结束事实；此后 Step 返回 AlreadyEnded，不再推进时间或状态。

动态单位由 Encounter 的显式配置在 Step 中创建，同 Tick 按稳定 SpawnId 排序，继承或显式指定阵营及控制绑定。失败不分配 UnitId、不隐式重试。该能力已纳入非性能迁移范围，主场景默认没有定时生成配置；首版不增加玩家召唤命令或召唤 UI。

<a id="界面"></a>
## 9. 界面与反馈目标

HUD 不再按互斥的三种模式组织，而是由三个独立事实组合出布局（详见 [HUD v0.3](界面/战斗UI-HUD框架-v0.3.md)）：

| 事实 | 取值 |
|---|---|
| 时钟 | 流动 / 战术暂停 / 系统暂停 / 已结束 |
| 提交权限 | 我的窗口（剩余时长）/ 他人窗口·可介入 / 已介入 / 无 |
| 威胁 | 无 / 有指向我方的已公开攻击（按截止排序） |

已确认默认开启“玩家可控单位窗口打开”和“新公开威胁指向玩家可控单位”的自动暂停；可在设置中关闭。威胁暂停只在至少有一个可行选项时触发，否则只给不打断的提示并说明原因。多个机会按截止排序，不能自动花资源。

所有单位的肾上腺素公开（主方案 R4），玩家与 AI 同等可见。因此在我方窗口内，对方能否格挡或闪避我方已公开的攻击，可以由 Logic 预览直接给出。

时间轴按单位分轨，所有轨道共用一套刻度、游标和窗口区间；只显示已选中的单位。左键单击选择，Ctrl+单击多选，单击已选单位即取消选择，Tab 在已选单位之间切换主选。窗口区间画在时间轴上，普通动作的起点吸附在窗口内。轨道显示草稿、待恢复提交、待采纳、Editable、锁定/执行、系统延期、完成/中止；命中标记与战场接触点联动。攻击块区分前摇、命中和后摇；防守、格挡、闪避都画成整段，并预告预计生效的命中点。当前时间线与可编辑门禁边界分别表达，不能把 CurrentTick+1 所有计划画成已经锁定。

顶栏显示当前窗口的拥有者和剩余时长；肾上腺素跟随主选单位。反应卡显示输入截止，提供格挡/闪避的起点放置条（默认放在命中点）；若会被更早的合格命中抢先消耗，必须警告。闪避必须提示可能取消的未来移动链。

时间游标首版残影只显示我方路径与已公开攻击范围。击退落点和伤害等结果预览留在配置器，读取逻辑预览；未知敌方未来显示未知。不得生成随机“控制概率”或泄露 AI 未公开计划。

“应用排程”与“继续时间”是不同操作；窗口不能手动结束。拒绝保留用户意图并说明原因，不能暗中重试或平移。中文状态文字、形状与颜色共同表达信息，1366×768 能完成全部操作。

动画、特效、音效、震屏和顿帧消费不可变战斗事实，由表现策略决定。主推进链保持 BattleRuntimeBootstrap → UnityBattleDriver → Logic；HUD 不运行第二个模拟或写回战斗状态。

### 10.2 开发者回放

回放用 Header 中的定义、Encounter、运行时输入和种子创建新模拟，从 Tick 0 重演；逐 Tick 校验事件与规范化快照，发现偏差停止。玩家输入按原始边界录制，AI/System 再生，不作为新的外部权威输入重复注入。

LogicSnapshot 是观察、哈希和差异定位模型，不是可反序列化的完整存档。任意 Tick 跳转、中途保存/恢复、周期完整检查点、玩家回放库、分享、观战和跨版本迁移属于独立后续项目。

### 10.3 规模与性能

产品继续面向小规模战术遭遇，不再把旧稿“每方最多 5 单位”作为冻结技术容量。正式性能基线的典型负载为 2 单位/不超过 12 计划/6 Reservation，最大负载为 8/64/32；这是一组测量场景，不是玩家队伍人数的产品定案。

发布前仍需在 Development Build 的既定负载中满足 P50≤0.5ms、P95≤1ms、P99≤2ms、平均分配≤8KB/Tick、每墙钟分钟 GC≤1 次且停顿≤5ms、托管内存≤256MB、历史增长≤10MB/30min。没有新增历史时，旧历史的读/复制/哈希应为 0。具体条件与测量方式沿用任务 01/11，不用 Editor 低负载数字替代。

### 10.4 代表性设计验收场景

| 场景 | 必须成立的结果 |
|---|---|
| 跨窗口攻击 | A 在窗口末尾安排的长攻击在窗口到期后继续；B 的动作仍可与它交互 |
| 窗口起点约束 | 起点落在窗口外的普通动作被拒绝；系统延期把起点推出来源窗口时计划终止 |
| Guard 覆盖命中 | 命中落在持续区间内按配置部分抵抗；恰在区间结束 Tick 不享受抵抗；额度用完后后续命中不再抵抗 |
| Block 被抢先消耗 | 持续区间内更早的合格轻击触发 Block，后到的重击不再被格挡 |
| 同 Tick 多攻击与 Block | 一次 Block 抵抗全部合格入射载荷；AOE 其他目标仍结算；绕过分量可穿透 |
| Dodge 与大范围攻击 | 换位成功而新格仍覆盖时继续受伤，不发成功避伤奖励 |
| Dodge 后移动链 | 实际改变位置才取消依赖旧起点的未来移动闭包；未换位不取消 |
| 相反冲击 | 伤害和总冲击累加，可硬直/击倒，合力为零时无击退 |
| 三方拼刀 | 输入排列变化不改变组内残余动量、终态与事件 |
| 强制位移争抢 | 同落点、交换、循环失败；静止单位硬阻挡；合法空格依赖链批量移动 |
| 到期计划受控 | 有有限恢复 Tick 则原子延期并保留预留；永久失效终止并释放 |
| 同 Tick 双方全灭 | VictoryDefinition 的双方目标都为空时得到 Draw，结束事实只发一次 |
| 暂停规划 | Tick 与窗口剩余时长不动；多条草稿恢复后在下一正常 Step 采纳，拒绝不吞用户意图 |

这些是设计与回归的核对要求，不把未执行的测试写成通过。
