# 交互保真与迁移脚手架退出方案

日期：2026-10-15。针对新 HUD 缺少时间轴吸附线、把攻击方向误做成旋转按钮、迁移诊断侵入运行时代码的问题。本文修订主优化方案及 HUD v0.3 的实施约束；冲突处以本文为准。规则 R1～R4、唯一 Logic 时钟、命令事务与确定性回放继续有效。

**用户澄清后的范围：** 旧时间轴仅保留关键帧吸附及吸附线这一项功能；其他界面、轨道、草稿与反应交互均沿用 HUD v0.3 的 M1～M3 标准。旧 Player/Observed 双轨与新 HUD 冲突，不保留；幽灵插入交互继续搁置，不列入本轮实施或验收。此前本方案要求恢复旧 Canvas、原配色、双轨和幽灵块的条款属于理解错误，已撤回。

## 1. 当前核查结论

| 问题 | 当前源码事实 | 判定 |
|---|---|---|
| 新时间轴缺少吸附线 | 旧 `TimelineEditorUI` 保留 `ApplyKeyframeSnap` 与 `_snapIndicatorLine`；当前 `TimelinePlanView` 按钮行未接入这项功能。正式场景已移除旧 Canvas | 待在 M2 多单位轨道中接入吸附与吸附线；不恢复旧双轨或旧 Canvas |
| 方向操作退化 | 本轮修复前 `SelectAction()` 创建目标文字按钮，`Bind()` 注册 Rotate 循环 12 向；鼠标地面输入仅支持 Move | 属于表现层错误；保留 `AddOrdinaryPlanOperation.Facing`，恢复战场选向 |
| Shadow 留在主工程 | `ShadowBattleRunner/ComparisonDetector/ComparisonReport/CasePolicy` 等位于 `ProjectHero.UnityView`，Bootstrap 含比较与诊断分支；Player 入口虽拒绝 Legacy/Shadow，代码依赖仍在 | “默认不开启”不等于“退出生产程序集”；需按依赖拆出，不能只删文件 |

旧 `TimelineEditorUI` 整体处于 `#if UNITY_EDITOR`，依赖旧 `CombatUnit/BattleTimeline`；旧写入路径包括取消计划、预约和重排。仅复用其中吸附判定与辅助线表达，在新 HUD 上绑定 Model 的只读投影和事务入口；不重新启用旧组件，不要求恢复旧视觉子树。旧 Canvas 关闭或退役本身不作为本次缺陷，缺陷是新 HUD 未承接已确认保留的吸附功能。

## 2. 本轮已落地的源码修正

- 不再创建攻击目标文字按钮，不再注册 Rotate 回调，并隐藏既有序列化旋转按钮。`Facing` 仍是单次攻击的方向参数。
- 攻击鼠标指向经 `GridView.DirectionTo()` 映射为 12 向，红色范围直接来自 `AttackPayloadSpec.Pattern.Directions` 的规范三角表。点击战场格同时设置攻击方向和该格上的合格主目标；候选目标只取当前控制者可见且关系允许的单位。面积攻击可选地面，固定目标攻击点空地由既有 Logic 预览显示不可用。
- 世界输入检查战场相机视口、UI 遮挡、系统暂停、恢复选择框及战斗边界。选择只改变本地候选配置；多草稿仍经过“添加→应用→恢复→权威回执”，不绕过 M1 事务契约。
- 时间轴拖拽用父 `RectTransform` 的局部坐标、可配置 `PixelsPerSecond` 和定义的 `TicksPerSecond` 换算，移除硬编码“屏幕像素除 4”。系统暂停不能拖动或右键删除计划。
- Bootstrap 新增组件的默认模式改为 New，与正式启动路径一致。旧场景序列化值不会因此被覆盖。

**当前状态：** [M2 多单位轨道与吸附线已实现](执行记录/M2-多单位轨道与吸附线-2026-10-15.md)，已接入新 Model 并替换原时间轴按钮列表；定向原生验证通过，完整真实鼠标/物理键盘流程和 Player 专项仍待独立验收。旧双轨不保留，幽灵插入继续搁置，两者不计为待修复缺陷。M2 阶段攻击范围以已提交位置为原点；[M4 空间联动](执行记录/M4-空间联动-2026-10-16.md)已接入先移动后攻击的 Logic 未来原点及公开目标投影，验证范围见记录。

## 3. C1：在 M2 时间轴上接入关键帧吸附与吸附线

时间轴按 HUD v0.3 的 M2 多单位轨道建设，并延续 M1 多草稿与 M3 反应契约；仅从旧时间轴保留关键帧吸附与吸附线。C1 纳入 M2 实施，不另设恢复整套旧时间轴的前置任务。

1. 按 M2 的选择集合、固定排序、主选展开/其他轨道紧凑及跨轨道接触点标准实现轨道。样式和布局以新 HUD 为准，不迁回旧 Player/Observed 双轨、原配色或整套 Canvas。
2. Presenter 唯一数据源为 `BattlePresentationModel.Decision/Timeline/Preview/Drafts`。读取控制者过滤后的公开计划；隐藏计划不能成为吸附锚点。当前时钟读 Model，编辑边界读 `LockLine`，可编辑性读 `CanEdit`。使用 UnitId、ActionPlanId、Tick 和稳定草稿 ID，不依赖旧实体或第二个模拟。
3. 将旧 `ApplyKeyframeSnap` 的吸附判定和 `_snapIndicatorLine` 表达接到新 Tick 坐标映射，优先覆盖 M2 已规定的命中点对齐。关键帧 Tick 来自实际快照/Logic 预览，不沿用旧固定前后摇偏移。阈值由秒转换成局部坐标，支持 CanvasScaler、缩放与滚动；越界或不可用的锚点不采纳。
4. 吸附成功时显示对齐辅助线，脱离阈值、取消拖动、修订过期或退出编辑时清除；关键帧吸附是本地交互辅助，最终时序由 Logic 校验。草稿添加、已有计划移动/删除继续走 M1 的统一事务；失败显示冲突，不隐式提交。
5. M1 多草稿按稳定 ID 呈现，M3 反应按新方案表达硬/软占用及截止。已有 Logic 受限向右避让的结果仍按新 HUD 显示，但不恢复 `ResolveGhostCenterInsert`、旧幽灵块或鼠标插入推挤流程；也不以搁置幽灵 UI 为由删除底层排程规则。

验收按 M1～M3 原标准执行，并为吸附功能补充：在 M2 多单位轨道拖动轻斩，使命中点吸附对方公开命中点且显示辅助线；脱离、取消和过期时辅助线清除；隐藏计划不泄露为锚点；窗口和锁定边界有效；1366×768 和 1920×1080 下换算一致；不产生误提交，Player 构建同样可用。旧双轨、旧 Canvas、旧配色与幽灵插入不列入验收。真实鼠标操作、截图和原生测试分别存证。

## 4. C2：完成战场选向与时间轴联动

本轮恢复基础战场选向。后续仍通过既有端口完成：

- 规划移动后，攻击范围原点读 Logic 对候选起点的投影；目标位置同样读公开投影。UI 只负责坐标转换与绘制。
- 鼠标悬停预览与已点击配置区分显示；命中/未命中、拼刀、击退停止格等结论来自 Logic，不能由红色范围颜色推断或自行算伤害。
- 主目标可通过点击单位或其占位格确定；多目标重叠时按明确交互选择，不用一排 `Target N` 按钮代替。支持取消、重新选向，保留其他草稿。
- 补充完整鼠标流程验收：选攻击→指向改变范围→点击确定→加入草稿→时间轴调整→应用→恢复执行；视口边缘、UI 遮挡和系统暂停下不误选。

## 5. C3：Shadow 从生产代码退出

2026-10-15 已实施程序集与宿主拆分：正式 Bootstrap 只启动 New，诊断代码转入 `ProjectHero.Migration.Diagnostics`；当前执行结果与范围见 [Shadow 拆分记录](执行记录/Shadow-拆分-2026-10-15.md)。Player 脚本编译与 DLL 元数据隔离已验证，完整发行包运行不包含在这一结论内。

迁移比对保留为按需运行的回归工具；生产调用图与程序集必须不再依赖它。先分层，再移动文件，最后删除过期约束。

| 当前内容 | 目标归属 | 处理 |
|---|---|---|
| Shadow runner、比较器、报告、策略、迁移分类、镜像输入及检查点采样 | `Assets/Diagnostics/Editor/Migration/` 的 Editor 专用程序集 | 保留源码、元数据和历史报告；仅由显式诊断工具装配 |
| Bootstrap 中 Legacy/Shadow 分支、比较配置、报告累积与诊断入口 | Editor 的迁移验证宿主 | 从正式 Bootstrap 提取，宿主单向引用 Runtime；Runtime 不引用宿主 |
| RuntimeCallLedger | 测试/诊断观测适配器 | 只保留确有正式排障用途的轻量计数；迁移审计与调用点清单不进入日常玩法调用链 |
| LegacyWriterRegistry 与旧 writer hooks | Editor 兼容层或随旧写入者退役 | 先验证正式场景不再包含旧写入组件；不能提前删掉门控而重新开放旧写入 |
| New Driver、只读预览端口、命令入口、确定性 Replay 与偏差检查 | 生产 Runtime | 长期能力继续保留，不能误当 Shadow 一并删除 |
| 旧比对测试、证据哈希与历史清单 | Editor 测试和执行记录 | 测试跟随诊断宿主迁移；旧证据标明对应源码版本，新修改用新结果，不重写旧通过记录 |

执行顺序：

1. 冻结并保存当前迁移证据；以实际源码引用生成依赖清单。明确区分 Legacy 兼容、Shadow 比对和正式 Replay。
2. 抽出 New 专用 Bootstrap 路径与必要生命周期接口，正式主场景只挂这一条链。诊断宿主负责 Legacy/Shadow 的装配与两世界比对；历史验证场景保持在 Editor 目录。
3. 逐组移动诊断文件并同步 asmdef/测试引用。每组都跑编译及对应测试。禁止仅靠 namespace 改名、目录改名或运行时 false 开关宣称隔离完成。
4. 清理正式运行时残留的比较报告、policy、旧 writer 注册和三模式选择；修改正式场景/Prefab 接线并检查 Missing Script。
5. 验收 Player 程序集和主场景调用图无 Shadow/Legacy 诊断依赖；New 模式无第二世界、无比较采样、旧时钟无调用；重开、暂停、动态生成、战斗结束和确定性回放仍通过。Editor 中按需迁移比对仍能复现。

**删除门槛：** 确认无生产引用、替代生命周期与测试已通过后，才删除旧生产接线与无用门控。历史证据不删除；迁移比对不再作为每次 HUD 颜色/间距修改的验收前置，只在涉及历史规则一致性时按需运行。

## 6. 验收与优先级修订

实施顺序：本轮明显输入错误修正 → 按 M2 实施多单位轨道并接入 C1 吸附线 → 按 M3 实施反应交互 → C2/M4 未来空间联动。C3 诊断程序集退出独立安排，依赖清点可以先做，不作为 M2/M3 的额外前置条件。

M1 已有的时钟、窗口、多草稿与用户键盘复核保留为历史事实。M2 的多单位选择、轨道与跨轨道联动按 HUD v0.3 实施，C1 吸附线作为其中一项验收；M3 按既定标准扩展反应交互；M4 完成空间预测、分辨率与可访问性。另设 C3 的发行程序集验收，不能把它藏在“默认 New”后面。

每项状态明确写为“方案已定 / 源码已修改 / 原生测试通过 / 真实操作通过 / Player 验证通过”，不可互相代替。工程行数、测试数量和 Shadow 报告为零都不能证明玩家交互保真。
