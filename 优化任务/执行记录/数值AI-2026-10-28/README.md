## 已取得的结果

- 79 个固定场景全部产出记录并通过序列化后逐 Tick 重放校验，未发生入口/命令拒绝或实验异常。
- 64 场达到消灭目标；15 场到观察时限，其中 6 个稳定度短探针、8 个脚本观察场景、1 个开阔地短程击退场景。超时保持为 `timeout`，不补造胜负或战斗结束事件，不作为平衡胜率样本。
- 24 生命无防御目标：快斩 6 次有效命中、Tick 511 结束；重砸 4 次、Tick 571；横扫 8 次、Tick 1231。这些 TTK 限定于本轮窗口、脚本及实验几何。
- 基准重砸与快斩正面对撞：原动量 10/3，残余 7；伤害 `floor(6×1024×7/10)=4300 HealthQ10`，原攻击不重复扣血。
- 重砸在对手命中前一 Tick 造成控制时取消其伤害；命中后一 Tick 的控制保留已提交伤害。R=10 达到硬直门槛，R=10+1/1024 与 R=10.5 不达到。
- Guard 在真实重砸接触中将伤害从 6 降为 3。短程开阔地目标被推离后续范围，800 Tick 内保持超时；同条件墙边在 Tick 571 结束。
- 100 次重复重放包含拼刀小数残余和资源收入，事件与快照一致。多来源过量伤害测试严格只分配 24 点生命；三方拼刀按分配残余计算各份伤害，总量有界。

## 使用与复现

Unity 菜单 `Project Hero > Combat Experiments > Run First Round` 运行批次；`Open Replay Viewer` 打开单场 `.heroReplay`，旁边需保留同名 `.input.json`。查看器支持播放/暂停、单步和从 Tick 0 重启，显示生命、位置、状态、可用资源、预留、周期与当前 Tick 事件。查看器已随本轮 Unity 编译，未将其记作人工鼠标验收。

命令行入口（从仓库根目录执行）：

```powershell
unity run . --editor-version 6000.6.2f1 --timeout 300 --no-tail --format json -- -executeMethod ProjectHero.Editor.CombatExperimentTools.RunBatch
unity test . --editor-version 6000.6.2f1 --mode EditMode --filter CombatValuesV05Tests --output "优化任务/执行记录/数值AI-2026-10-28/unity-values-rerun.xml" --timeout 300 --format json
```

每次批量执行创建独立 UTC 时间戳目录，不覆盖前次原始证据。输入中保存规则/数值/脚本/场景版本、定义哈希、种子、全部可调场景字段及源码 SHA-256；快照与命令初始输入另在回放头中保存。最新版 CSV 区分“受伤目标 Tick 数”“正伤害接触数”“实际启动的攻击数”，不能把集火时一条目标聚合误当作一次攻击接触；较早运行的 `damage_contacts` 列实际表示受伤目标 Tick 数，后续分析使用最新目录。
