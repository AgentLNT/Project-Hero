## 3. 本轮范围（对应冻结件 §8.3 的四条）

### 3.1 旧写入路径必须「结构上不可达」

现状（主理人已逐行核实）：
- `Assets/Scripts/UI/Timeline/TimelineEditorUI.cs:1123-1135`（`RecomputePlayerBlocksForLane`）**仍无条件**调 `Timeline.CancelGroup(id)` + `placement.Schedule?.Invoke(...)`；
- `EndDragExisting`（`:515-556`）、`FinalizePlacement`、`RequestDelete`、`RequestReposition` 同理。

今天它们只是靠「端口接线后 `_playerBlocks` 为空」这一**隐式**前提才不执行 —— 这不是结构性保证。

**要求**：端口接线后，上述旧入口**一个都不能**触达 `BattleTimeline.CancelGroup` / `placement.Schedule` / 任何旧时间线写入；未接线时保持旧行为（PlayMode 38 条与旧场景不得回归）。请用**显式守卫**（例如统一的 `LegacyTimelineWritesEnabled => !IsInputPortsBound`）替代隐式前提，并在注释里写明理由。

### 3.2 时间线块标识语义：`GroupId` → `ActionPlanId`

- 现状：`TimelineBlockView.GroupId` 来自 `Timeline.ReserveGroupId()`，不是 Logic `ActionPlanId` ⇒ 端口接线后 `CanRequestDelete` 恒 false，删除/重排永远走不通。
- 要求：把块标识改成从 Logic **只读快照**投影出的 `ActionPlanId`（`IViewLogicPort` 已有 `TryFindEditablePlan` / `TryGetPlanSnapshot` 等面），并同步 `TimelineEditorUI._playerBlocks` 的键语义。
- **禁止**使用 `GetInstanceID()` / `GetEntityId()` / 注册顺序 / 名称等不稳定键（00 规则 16）。

### 3.3 秒 → Tick 的唯一换算点

- `TimelineEditorUI` 目前只有秒（`PixelsPerSecond` / `Timeline.CurrentTime`），而 `BeginPlacement` / `BeginReorder` 需要整数 Tick。
- 建立**唯一**换算点（依据快照 `CurrentTick` 与已知 tick 率），所有放置/重排调用都走它；**禁止**在 UI 各处散落乘 60 之类换算。
- 若换算必须依赖旧时间线的秒制，把假设写进注释与回报的诚实清单。
