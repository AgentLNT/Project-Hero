## 3. 本轮范围

### 3.1 产出 9：`AIControllerLogic`

- Step N 完成后读取**与玩家同时公开**的只读决策快照，**只**创建 `TargetTick = N + 1` 的 `CommandRequest`，并经其**已注册入口**提交；Step N+1 开始时与玩家请求一起冻结，**不能**读取 N+1 的新机会后同 Tick 抢跑。
- 普通攻击候选**逐 ActionSpec** 使用与处理器**相同**的 `FactionRelationResolver + AllowedTargetRelations`（复用 A2 的 `TargetCandidateQuery`，`From(DecisionSnapshot)` 是唯一构造入口），再按 `ActionSpecId` / `TargetUnitId` **稳定排序**。
- **AI 不保存由 Controller 类型推导的永久敌人**。
- 普通动作候选可生成 Add/Move/Remove 的 `ScheduleEditCommand`；**Move 候选必须调用任务 06 的同一 `Pathfinder`/`PathResult`**，不得用距离、速度或自建权重估算路线。
- 反应候选生成标准 `ReactionCommand`（经 `ReactionCommandPlanner` 的既有面；**不得**直接调 `ReactionOpportunitySystem.TryAcceptById`）。
- **候选稳定排序之后**才使用版本化确定性 RNG（`DeterministicRng`）；不得把原始集合枚举序当末级键。
- AI **不能**创建 Envelope、机会、计划，也不能分配任一顺序字段（`ProducerOrdinal`/`CommandSequence`），不能绕过 `ScheduleRevision`。
- AI 不得引用 `UnityEngine.Random` / `Time` / `ActionScheduler` / `TurnWindowManager` 的写方法（R-7；参照 `Assets/Tests/EditMode/Logic/AssemblyBoundaryTests.cs` 的手法钉死）。

### 3.2 产出 10：AI 提交权限边界

- AI 仅在**拥有当前窗口提交权限且 Lane 接受**时提出新增/增费普通动作；它可按控制权编辑自身仍为 `Editable` 的计划，但仍经**相同修订号与锁定检查**。
- 只要受控单位拥有**有效** `ReactionOpportunity`，便可在**任何单位窗口**提出 Block/Dodge。处理器重新校验全部条件。
- AI 与玩家的**理论动作可用性来自同一 `ActionSet`**。
- AI 没有可接受动作时可以生成**关闭窗口命令**，但**不能**直接调 `TurnWindowManager`。

### 3.3 产出 15：AI 未来决策状态入规范化快照与哈希

- `AiControllerSnapshot` 目前只有 `(ControllerId, NextThinkTick)`（`LogicSnapshot.cs:420`）。请按需扩展（若新增记忆/冷却/计划游标，同样必须进快照与哈希），并确保它**参与**规范化快照哈希。
- 回放语义：AI 由**相同初始输入与 RNG 从 Tick 0 重新生成**，**不直接载入记录的 AI 命令**作为权威输入（与 C 流的 `ReplayAuthorityInput` 口径一致，**不要**改 C 的文件）。

### 3.4 产出 17：`DecisionSnapshot` 按 Controller 过滤

- 只公开该 Controller **可控制单位**的 `Editable` 计划与可编辑字段。
- 其他 Controller 的普通计划在**锁定并按玩法公开前**，**不得**泄露 `ActionSpec`、目标、`Destination` 或精确 Tick。
- 开发者 Canonical Snapshot 仍可包含全部权威状态用于哈希（两者分型，不得合并）。
- UI 与 AI 的候选筛选必须共用这一只读面（`UiAndAiCandidateFiltersUseDecisionSnapshotFactionResolver` 已由 A2 落地，你的改动不得让它变红）。
