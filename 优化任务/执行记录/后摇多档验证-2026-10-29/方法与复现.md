# 后摇多档实验方法与复现

本轮承接实施方案第 5.2 节，使用已纠偏的真实战斗内核。固定脚本负责提交正常命令，Python 只检查和汇总导出的事实，不另建战斗模型。最终批次及结论见同目录 README；smoke 和第一次 coarse 为采集开发阶段证据，不计入最终样本。

## 控制变量

- 公共参数为钝击类型后摇增量 Δ，有效后摇为基础 30+Δ Tick。重砸前摇 90，类型探针前摇 30；快斩 30+30、横扫 60+30 不变。伤害、动量、成长公式、稳定度、资源和规则内核在各参数组间固定。
- 七档粗扫为 30/33/36/39/42/48/60；31/32 必测。相邻粗扫区间只要出现出手数、拼刀、控制取消、反应或终局类型变化，便补齐该区间的整数，不仅检查平均伤害。
- 每档使用同一组 212 个输入格、同一种子 31。它们是确定性控制实验，不是 212 次独立随机对局；不能据此计算泛化胜率或随机置信区间。
- 成长/生命取八组边际输入 `(0,24)/(1,27)/(2,30)/(3,36)/(4,24)/(0,27)/(0,30)/(0,36)`，覆盖成长 0～4 与生命 24/27/30/36，并非二者全因子。双方属性对称，不代表同预算角色构筑。稳定度另用 4096/6144/10240/10241/15360 的隔离探针。
- 对撞通常观察至 Tick 719，无防御击杀观察至 1799；未结束记 `observation-limit`，不记平局。有效样本以批次 progress、summary 和逐场重放共同确认。

## 权限、脚本与比较口径

双方通过注册的玩家输入入口提交；初始元资源 4，单位 1 在外方窗口中先支付正常并发激活命令，待授权生效后排程。单位 2 仍受自己的窗口约束。交换钝击归属、交换出生位置分别记录，不把权限不对称混成类型强弱。

第一个对撞采用公开固定承诺，命中 Tick 为 213/273/329/330/360。后续脚本使用决策只读视图、自身计划、公开机会和合法排程预览，不读取对手隐藏草稿。`Repeat` 在持续具有权限的窗口内取最早合法起点；跨窗时包含固定脚本的命令提交及并发激活步骤，不能声称是所有可能脚本的全局最快行动。

`WaitRealign` 由短后摇对手等待，按预先声明的招式时序重新对齐；`Guard/Move` 在钝击方第一次可行动时执行一次后恢复进攻；`Switch` 改用快斩；`Block/Dodge` 仅在自然收入、公开机会和合法时序均满足时触发一次，否则继续进攻并记录原因。移动目标固定为远离对手的位置，不代表战术寻路。防御分支使用公开机会候选构建器，不等于已实现阶段 3 战术 AI。

总伤害按实际扣血事实统计，包含过量伤害截断；直接伤害与拼刀残余分列。资源记录实际消耗和窗口清零。攻击 CSV 保存接受的起点、预定命中/结束、来源窗口、锁定、实际效果和终止；同 Tick 创建后即遭控制/死亡归档的计划，也保存原预定时序，避免漏计取消前摇。

每场保存输入 JSON、`.heroReplay`、事件 JSONL、决策 JSONL、动作 CSV、逐帧 CSV、伤害/收入 CSV。导出后从磁盘重新读取输入并重建定义，再载入磁盘回放逐 Tick 校验哈希与事件；摘要 `replay_verified=True` 在此之后写出。

## 复现命令

在仓库根目录运行（本机 Unity 6000.6.2f1，Unity CLI beta.13）：

```powershell
unity test . --editor-version 6000.6.2f1 --mode EditMode --output '优化任务/执行记录/后摇多档验证-2026-10-29/unity-editmode-final.xml' --timeout 600 --format json
unity run . --editor-version 6000.6.2f1 --timeout 1800 --no-tail --format json -- -executeMethod ProjectHero.Editor.RecoveryExperimentTools.RunCoarse
```

用 Python 运行同目录 `analyze_recovery.py --artifacts`，先校验粗扫产物，再生成 `fine-request.json`。把其中 values 以英文逗号连接后执行：

```powershell
unity run . --editor-version 6000.6.2f1 --timeout 3600 --no-tail --format json -- -executeMethod ProjectHero.Editor.RecoveryExperimentTools.RunSelected -recoveryTicks '31,32,...'
python '优化任务/执行记录/后摇多档验证-2026-10-29/analyze_recovery.py' --final --artifacts
```

Unity 每次创建新的时间戳目录；`latest-coarse.txt/latest-fine.txt` 指向最终分析所用批次。源指纹覆盖 `Assets/Scripts` 下全部 C# 文件；各场同时保存定义哈希、规则/数值/脚本/场景版本与种子。编辑器 `CombatExperimentWindow` 可载入对应输入 JSON 并查看单场回放。

本机在沙箱内启动 Unity 会遇到本地监听/套接字限制，以上原生运行使用正常的沙箱外 Unity 权限。测试生成的历史执行记录，在本轮结束时按 `pretest-baseline.zip` 恢复到开始验证前的字节；本轮生成版本另存，避免改写历史证据。该备份覆盖执行记录，不含 Assets；已有字体改动保留，测试重新生成的诊断场景另存为生成产物，不将其当作生产场景迁移。

## 结论边界

本轮可以验证有效时序、对齐条件、合法应对、输出与窗口代价，并筛选下一阶段的参数。固定脚本、单挑与有限场景不能决定最终平衡；规则策略、2 对 2、保留场景和人工试玩仍需另行执行。正式生产参数须在这些复核后确定。
