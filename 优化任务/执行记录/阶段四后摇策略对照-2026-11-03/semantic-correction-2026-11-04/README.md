# 时机语义与实验驱动说明纠正（2026-11-04）

本次按用户明确纠正修改动作卡提案和实验解释。此前把反击时机限定为命中目标某个动作阶段，并据此提出补场或奖励的解释撤回。修改前的 12 份文档与分析脚本保存在 `prior-documents.zip`，摘要见 `prior-documents-sha256.json`。

## 用户定义

选定敌方对自身的公开攻击后，以其预计命中 Tick 为参照，让自己的攻击在此之后尽早命中敌方。自己的前摇可提前开始，排程、受击控制、位移、接触及敌方应对都按现有规则处理。这个时机不保证实际命中；一旦正常命中，就按普通伤害、控制、位移及资源结算。敌方动作何时结束不构成成功边界，不增加按目标动作阶段发放的收益。

动作卡提案暂称“后手（受击后尽早命中）”。此前 v4/v5 的第三项时机及其价值解释失效，图像保留作历史追溯，当前定义见[分层方案 §3.7](../../../../设计文档/界面/HUD常规界面与介入界面分层方案-讨论稿-2026-10-17.md#37-相对时机试行2026-10-26)。

## 实际使用了什么决策方式

| 实验 | 实际驱动 |
|---|---|
| 阶段 0～2，包括 30～60 整数扫描的 6572 场 | 固定脚本提交动作，验证规则和数值时序 |
| 阶段三 62 场机制验证 | 一侧绑定实验规则决策器或旧基线；部分局面由对手脚本制造公开威胁，其他局面为固定初始情境 |
| 阶段四 V1 的 304 场 | 双方都注册为 AI；272 场新规则策略互战，32 场新策略对旧 AI |
| 阶段四 V2 的 96 场 | 双方使用修复后的规则策略，运行时生成动作，没有预写双方动作序列 |
| 正式定义默认值 | `AiPolicyKind.Legacy`；没有默认切换到三种实验策略 |

规则决策器由阶段三加入，包含持续进攻、寻找打断、谨慎防守三种固定策略。它根据公开战局生成候选、预演和评分，再经注册入口提交下一 Tick 命令。固定策略版本与种子使决策可复现，不表示动作已预先写定。

源码依据：

- [AiControllerLogic](../../../../Assets/Scripts/Logic/AI/AiControllerLogic.cs)：观察战局、调用选择函数并提交请求。
- [AiTacticalPolicy](../../../../Assets/Scripts/Logic/AI/AiTacticalPolicy.cs)：三种规则策略与评分。
- [CombatExperiment](../../../../Assets/Scripts/Logic/Experiments/CombatExperiment.cs)：早期固定脚本。
- [AiPolicyExperiment](../../../../Assets/Scripts/Logic/Experiments/AiPolicyExperiment.cs)：阶段三的脚本情境与规则策略组合。
- [Stage4RecoveryExperiment](../../../../Assets/Scripts/Logic/Experiments/Stage4RecoveryExperiment.cs)：阶段四为双方绑定 AI，并逐 Tick 推进；没有外部脚本提交双方动作。
- [ControllerBinding](../../../../Assets/Scripts/Logic/Definitions/ControllerBinding.cs)：默认策略为旧基线。

当前候选生成包含尽早普通动作和公开命中 Tick 的拼刀对齐，尚无专门的“后手”时机候选。当前动作卡设计也不能因这些实验被称为已经验收。
