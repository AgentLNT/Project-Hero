## 窗口与关闭

窗口覆盖 `[OpenedAtTick, EndTick)`，`EndTick = checked(OpenedAtTick + DurationTicks)`。主 Encounter 时长 180 Tick，即 60 Tick/s 下的 3 秒。普通动作没有时间费用；动作结束可晚于窗口结束。原有队列、批量与排程视野上限保留。

管理器在 Step `EndTick-1` 的第 17 阶段请求 `Expired` 并正式关闭；生产排程最早在下一 Tick 开窗。在存活/顺序不变时相邻窗口首尾相接。窗口切换不结算、锁定、改时序或取消计划，也不增加 ScheduleRevision。

三种有效关闭原因：`Expired=4`、`OwnerDied=2`、`BattleEnded=1`。死亡先走单位终态清理；战斗结束先统一终止全部计划，再正式关闭窗口。两者保留原本的并发授权撤销和肾上腺素清理。

关闭不变量由 `TurnWindowManager.BeforeCloseInvariantCheck` 在每种正式关闭之前调用 `BattleSimulation.RequireNoEditablePlanFromClosedWindow`：不能存在来源于该窗口的 Editable 普通计划。发现残留即令 Step 失败，绝不在关窗时批量取消。并发计划也没有绕过该检查的例外。

## 提交与编辑矩阵

唯一窗口校验为 `TurnWindowSubmissionAuthority : IScheduleWindowAuthority`。生产模拟显式接入同一个实例；`ScheduleEditor` 的预览与提交共用完整求值和校验路径。

| 操作 | 提交身份/当前窗口 | 最终起点 | 预览/提交 |
|---|---|---|---|
| Add（含 Lane 尾部追加） | 当前开放窗口；ExpectedWindowId 必填且一致；控制权；拥有者/并发授权 | `currentTick <= StartTick < 来源 EndTick`，且不早于来源 OpenedAtTick | 同源，任一失败整批拒绝 |
| Move / 拖动 | 控制权、Editable、修订号；不要求再次携带窗口 scope | 修改后的起点留在原 SubmittedWindowId 的区间内 | 同源，失败无排程/路径写入 |
| 移动链重算 | 同上 | 连带计划逐一检查各自来源窗口 | 任一越界整批拒绝 |
| 向右避让 / ripple | 同上 | 连带计划逐一检查各自来源窗口 | 任一越界整批拒绝 |
| Remove | 控制权、Editable、修订号 | 不检查窗口开放或起点区间 | 仍经统一终态协调器，无左吸 |

`SubmittedWindowId` 是来源窗口标识。并发授权提交的普通计划使用当前拥有者的窗口区间。反应计划保持无来源普通窗口，沿用机会、控制权和肾上腺素路径。

窗口相关稳定拒绝码：`WINDOW_NO_OPEN_WINDOW`、`WINDOW_EXPECTED_WINDOW_REQUIRED`、`WINDOW_STALE_OR_CLOSED`、`WINDOW_ISSUER_CANNOT_CONTROL_UNIT`、`WINDOW_NO_SUBMISSION_AUTHORITY`、`SCHEDULE_START_OUTSIDE_SOURCE_WINDOW`。既有修订、不可编辑、目标、路径和空间错误码保留。已废止 kind 0 一律 `WINDOW_CLOSE_NOT_PERMITTED`，回放读入也拒绝它。

## 系统延期与启动原子性

| 门禁/求值结果 | 行为 |
|---|---|
| RetryAtTick 及全部连带起点仍在各自来源窗口内 | 原子提交同一个 ScheduleEvaluator 的结果；保持 Editable；延期次数与修订号各 +1 |
| 到期计划自身越界 | 不提交候选；经终态协调器以 `DelayedBeyondSourceWindow=14` 终止 |
| 仅某个连带计划越界 | 先丢弃整份候选；结果携带稳定排序的 `OutOfWindowPlanIds`；逐个终止越界计划，依赖走既有清理；若到期计划仍存活，再重新求值一份新候选 |
| 视野/次数超限 | 沿用 `AutoDeferralLimitExceeded` |
| 其他不可恢复阻塞 | 沿用对应终态原因 |

越界拒绝不写候选的 Start/End/路径/空间投影，不消耗一次延期。新候选只有完整合法才提交，不能把原候选的某几项当作成功结果。

`CommitStart` 删除消费/回滚账本端口后，仍在一个提交中建立 LockedAtTick 并直接进入 Running；没有可观察的 Locked-but-not-Running 普通计划。新测试同时验证非法启动零写入及成功启动只发一次锁定事实。

闪避取消只处理旧起点的 Editable Move 依赖闭包，清除未来移动段与空间预留；预览仅包含计划 ID/数量。未换位时保留移动。实际 Canvas 用例保留两条移动取消、恰好一次终态、预览不写入、无路径预留残留及无关 Guard 起点不变，并从文件重演 100 次。

额外修复：既有 Dodge 接受路径已经容忍它可能失效的 Editable Move，但 Lane 的运行时不变量此前仍拒绝该重叠。现在复用 `DodgeMayInvalidate`，并检查所有重叠对，避免隔着被容忍 Move 漏掉 Guard 等真正冲突。它不是 12B 的硬/软占用新规则。真实组合夹具显式使用 Move `1/1`、Attack `60/30`、反应 `1/30`，用于使未来移动起点落在 R1 窗口中；生产动作定义未改为这些夹具值。

## 12B 接口约束

普通计划新增/拖动/移动链/避让必须继续复用 `IScheduleWindowAuthority` 与 ScheduleEditor 的提交区间校验，不另建窗口检查或费用壳。反应硬/软占用的新逻辑应明确区别于已有 Dodge 条件移动失效谓词；不能把本次不变量修复推广为 Block/Guard 或任意普通动作的重叠许可。仍由唯一终态协调器负责让出轨道、来源取消及从属清理，不能在关窗处批量终止。
