# 实验输入与解释边界

本轮只改变普通攻击的进攻评价。正式动作、单位、几何、费用、Q10/RoundHalfUp 资源规则与三种偏好的评分权重沿用任务 18。原策略及其定义哈希继续保留。

## 独立版本

`AiForecastSettings(360, ConsiderDefenses: true)` 显式启用 `public-kernel-single-defense-v1`，该版本进入定义哈希；不启用时保留原先的哈希编码。正式生产场景的默认控制配置不切换。新旧版回放必须按对应定义加载。

## 单次防御分支

原先不追加命令的预演继续作为条件结果及评价上界。无应对时得分已非正的攻击不展开应对，因为保守最小值不会超过该上界、无法胜过 0 分等待。新版额外枚举：攻击实际公开之后，敌方控制者可提出的 Guard、Block、Dodge。每个分支只由一位防御者追加一条命令，不合并多个防御者或多步命令。分支从同一过滤快照的隔离世界起点重演，不复制真实世界的隐藏敌方计划、待处理输入、AI 记忆或 RNG 状态。

Guard 复用当前普通候选的窗口与单次承诺限制，选择该真实窗口内最晚、且不晚于攻击命中的起点；持续时长、空间和实际抵抗交给内核解析。Block/Dodge 只使用此候选攻击真实公布的机会，起点按现有反应候选设为来源命中 Tick；Dodge 枚举公开目的格。命令一律投到观察边界的下一 Tick。

相同准入上下文先复用候选生成结果，避免逐 Tick 重建公开 Dodge 目的格；窗口、排程、公开资源、状态/效果、位置、机会与下一 Tick 到期边界进入上下文键。实际候选按既定应对键去重。每条新候选先在已过滤的场景副本中推进真实下一 Tick，执行窗口清零、轨道和资源准入；拒绝的候选直接记录该真实拒绝码，合法候选再从同一起点完整重演。这是有限的单次应对协议，没有枚举所有 Guard 起点、反应提前启动时刻、普通移动、攻击、私有排程或联合防御。

实际通过命令入口和 Step 才算合法。缺资源、缺机会、窗口或轨道不符的分支分别拒绝，不作为成功防御。无应对与各合法分支都相对于同一原始基线、同一 360 Tick 终点评分，沿用原来的伤害、承伤、位置、打断、拼刀、时间和资源权重，取进攻方最低收益作为保守估计。命令拒绝的分支不参加比较；攻击或合法应对尚未完成时，不授予可比较的完整收益。

这不是对手一定会采用该应对的预测，也不是最优对抗证明。多个敌人时仍只比较单个敌人的单次应对，未组合防御；敌人的隐藏既有计划或后续决策可以改变真实结果。无应对基准和限制分支的评分、伤害、合法性与提交时点分别保留，避免将保守收益误称为必然命中值。

## 验证输入

短局回归沿用任务 18 的三种同偏好 × 远距/近距 × 两种镜像，共 12 场、每场最多 360 Tick；每场记录候选、分支与磁盘回放。旧版从任务 18 原始回放重新运行前 360 Tick，形成 `baseline-summary.csv`，只在相同终点比较命令、生命损失与选招轨迹；审计另完整重演旧版 12 场各 900 Tick，不重写封存产物。360 Tick 是本项施工回归的观察长度，不作为长局、胜率或平衡定值依据。

条件探针使用旧版持续进攻的真实命令前缀：两种远距镜像 Tick 0，以及两种近距镜像 Tick 0/240/426，合计 8 个上下文，每个比较全部 5 个正式攻击。分别真实执行无应对及每个枚举的防御分支，比较准入拒绝码和终点单位生命、位置、状态与公开资源，并保存事件摘要。隔离预演的 ID 来自可见事实；独立真实执行通过来源攻击、控制者及公开机会绑定等价真实机会，不注入资源或更改时序。

`AttackDefenseEvaluationTools.Run` 生成对局和探针；`Audit` 在另一 Unity 进程中读取磁盘输入，校验定义、正式内容与源码指纹，重演新版/旧版对局并重新构建全部探针。源码在开始生成最终证据后保持固定。

逻辑回归覆盖近距选招、无资源/有资源准入、真实命令结果、源世界与待处理输入隔离、结果覆盖门禁、定义哈希及序列化回放。相关 PlayMode 检查覆盖新版正式场景时钟/回放及既有玩家入口、New/Shadow 所有权。

补充的三单位获资探针使用人工窗口与真实攻击命令，使另一攻击在候选攻击公开后命中防御者并产生收入；提高测试单位的控制抵抗，以隔离资源、位置与状态变化。去重键统一使用 `DecisionSnapshot.AdrenalineLedgers`，不依赖旧单位资源字段。探针在键统一前也通过，记录为覆盖验证，不称为已经复现的漏选故障。键统一前的整轮对局、分支、审计及源码保存在 `before-funding-dedup.zip`；最终松散产物在键统一后的同一源码下重新生成。

## 复跑

使用 Unity CLI beta.13 与项目 Editor 6000.6.2f1：

```powershell
unity test . --mode EditMode --output '优化任务/执行记录/进攻防御评价-2026-11-09/full-editmode.xml' --timeout 1200 --format json -- -nographics -logFile '优化任务/执行记录/进攻防御评价-2026-11-09/full-editmode.log'
unity run . --timeout 1800 --format json -- -nographics -executeMethod ProjectHero.Editor.AttackDefenseEvaluationTools.Run -logFile '优化任务/执行记录/进攻防御评价-2026-11-09/run.log'
unity run . --timeout 2400 --format json -- -nographics -executeMethod ProjectHero.Editor.AttackDefenseEvaluationTools.Audit -logFile '优化任务/执行记录/进攻防御评价-2026-11-09/audit.log'
```

测试会产生已有验证资产及旧证据的临时写入。`evidence.py snapshot` 在验证前保存原始字节和保护清单，`restore` 封存再恢复这些副作用；`analyze` 核算结果；`seal` 校验旧证据、正式内容与最终源码并封存。最初沙盒许可证失败和验证工具编译失败保留原日志，不算通过的测试结果。

首版 900 Tick 批量验证因重复候选生成开销，在尚无完成对局时主动终止；`run-before-context-cache.log`、`before-context-cache-source.zip` 及带 `before-context-cache` 的测试记录保留当时来源与结果。随后补充上下文复用和真实下一 Tick 准入预检，并将本项自主对局范围收回到 360 Tick 短局；Tick 240/426 的条件探针与旧版 900 Tick 兼容回放保留。该中止轮没有可用于新旧比较的完整对局，不混入最终样本。正式性能、分配与 GC 验收仍属既有延期项。
