### 2.2 旧→新 ID 映射与冲突处理规则

完整表格见 `02B-配置迁移记录.md` §2。冻结规则：

1. **不存在"把局部 ID 自动转成全局 ID"的路径**。每个最终 ID 在 `LegacyIdMigrationManifest.Actions` 中逐条写死；无 `ToLowerInvariant`、无文件名推导、无最后写入覆盖。
2. `QuickSlash` 等 5 个同名局部 ID 在 R1/R2 两库各有一条映射，分别指向 `action.*.radius_1` / `action.*.radius_2`（两者 Pattern 形状不同，规范定义不同）。
3. `AttackPattern` / `UnitVolume` 资产没有 ID 字段 → 最终 ID 完全由清单给出。
4. 迁移键（`资产 GUID + 局部条目 ID`）**只**用于在 Authoring/Editor 边界定位旧条目；GUID 不进入 Logic 类型、`BattleDefinition`、快照或回放（`EveryReferencedLegacyDefinitionHasExplicitStableId` 断言 ID 不匹配 32 位十六进制）。
5. 一个最终 ID 只能对应一个规范化定义：同 ID 不同内容 → `DEFINITION_ID_CONTENT_CONFLICT`（`DetectContentConflicts`，签名只由规范内容构成）。
6. 清单里声明的资产在输入集合中缺位 → `DEFINITION_REFERENCE_DANGLING`；输入集合中出现清单未声明的 GUID → `LEGACY_ID_MIGRATION_MISSING`。两者都整体失败，**不跳过**。

### 3.1 伤害通道 × 冲击 Profile × 防御通道

| 旧 `ImpactType` | 伤害通道（`DamageChannelId`） | 冲击 Profile（`ImpactProfileId`） | 传递系数 |

| `Blunt = 0` | `physical.blunt` | `impact.blunt` | 100 |

- 通道目录固定 8 个：`physical.blunt/slash/pierce`、`elemental.fire/frost/lightning`、`arcane`、`true`。
- 默认标签：`true` 通道 = `BypassPassiveResistance | BypassActionResistance`（不可 Block/Guard）；其余 = `Blockable | Guardable`。

## 4. `BattleDefinitionBuilder` 契约（必须产出 4）

| 项 | 内容 |
|---|---|
| 输入 | `LegacyAssetSet`（三个按 GUID 排序的资产字典）+ `LegacyBattleUnitSource`（两个单位的纯数值子集）；另有便捷重载 `BuildMainBattleDefinition(LegacyBattleUnitSource)` 从 `Resources` 自动加载 |
| 输出 | `BattleDefinitionBuildResult`：`Definition`（成功时非空）、`Errors`（按稳定键 `CODE|detail|origin` 排序）、`Warnings`、`Succeeded`、`ErrorCodes()`、`ErrorKeys()` |
| 失败语义 | **整体拒绝**：`Errors` 非空 ⇒ `Definition == null`。不存在"带着错误仍产出可运行定义"的路径 |
| 错误模型 | `DefinitionErrorCollector` 只追加，`Sorted()` 每次返回同一顺序；同输入重复构建得到逐项相同的 `ErrorKeys()` |
| 规范化顺序 | 资产集合按 GUID 的 `StringComparer.Ordinal`；定义内集合按 ID 的 Ordinal；12 向表按 `GridDirection 0 → 11`，方向内按 `(X, Y, T)`；阵营清单 / 关系对 / 槽位 / 控制器全部规范排序 |
| 哈希边界 | `BattleDefinitionHash.Compute(...)` 在 Builder 内一次性计算并写入 `BattleDefinitionHashValue`；覆盖范围见迁移记录 §11.2；**不覆盖**显示名、资产路径、发现顺序、资产内点排列、对象地址、Builder 实现细节 |

**构建步骤（固定顺序，错误累积不短路）**

1. 版本化规则常量（`BattleRules` / `PathCostRules.ValidateFrozenRules` / `PathSearchRules` / 强制位移协议 / `ConcurrentActionDefinition` / `ReactionRules` / `AdrenalineRules`）。
2. 目录：8 个伤害通道、3 个冲击 Profile、1 个 MovementPattern、2 个动作集合。
3. 阵营模型：`hero` + `monster`，唯一无序对 = Hostile。
4. Pattern / Volume：**全部**资产（不只被引用的）逐个转换并校验 12 向完整性。
5. 动作定义：10 条旧攻击（逐条沿用清单）+ Guard/Move/Block/Dodge（本任务新增），每条都过 `ActionDefinitionValidation`。
6. 单位定义：两个单位的旧字段一次性映射（含 `MaxHealth → InitialHealth`、动作集合 ID 由参数注入）。
7. Encounter：稳定 ID + 规范边界 + 2 个槽位 + 2 个 `ControllerBinding` + `VictoryDefinition`。
8. 交叉校验：阵营矩阵完备性、动作集合引用、单位→动作集合、动作→Pattern/MovementPattern、Encounter（含槽位阵营、越界、控制器、胜负）。
9. 反应闭合：可反应攻击的最小提前量、Block/Dodge 是否至少在一个集合中、费用与奖励闭合。
10. 组装 + 哈希。
