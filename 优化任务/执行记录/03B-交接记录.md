## 1. 关键设计决策：asmdef 边界与 PlayMode 可测试性

任务包要求"Bootstrap 与帧适配器契约不得依赖 Legacy 具体类型"，同时要求 PlayMode 测试能真实驱动 Bootstrap
并读取调用计数。Unity 规定自定义 asmdef **不能引用预定义 `Assembly-CSharp`**，因此落地如下单向依赖：

```
ProjectHero.Logic              (纯 C#，noEngineReferences)
      ↑
ProjectHero.Compatibility.Runtime        ← 新增（生产，引用 Logic + UnityEngine）
      ↑                               承载：BattleRuntimeMode / 回调分类表 / 调用计数账本 /
      │                                     IBattleFrameAdapter 契约 / BattleRuntimeBootstrap /
      │                                     ShadowBattleRunner / UnityBattleDriver /
      │                                     ShadowComparisonReport / ShadowCasePolicy
      ├── Assembly-CSharp                       ← Legacy 具体适配器留在旧程序集
      │     · CombatDemo : IBattleFrameAdapter（改造后的被调用适配器）
      │     · BattleSimulationSourceFactory : IBattleSimulationSource（真实 02B 初始化链接缝）
      │
      └── ProjectHero.Compatibility.Runtime.Tests  ← 新增（PlayMode 测试）
            asmdef 只引用 Logic + Compatibility.Runtime
```

- **契约程序集只引用 `ProjectHero.Logic`**（`ProjectHero.Authoring` 依赖旧资产类型，不能进这条链）。
  真实 02B 定义构建必须留在旧程序集：`BattleSimulationSourceFactory` 调用
  `LegacyAssetResolver.LoadAllFromResources()` + `BuildMainBattleDefinition` + 初始化链，
  通过 **Bootstrap 的显式序列化槽位 `_simulationSourceSlot`** 注入 `BattleSimulationSeed`（纯数据）。
- 显式槽位校验：`_legacyFrameAdapterSlot` / `_simulationSourceSlot` 若不是目标接口，启动时
  以 `BOOTSTRAP_ADAPTER_SLOT_INVALID` 快速失败，**不按容器枚举顺序或反射发现选择权威路径**。
- PlayMode 测试**不引用** `Assembly-CSharp` / `ProjectHero.Authoring`；真实组件类型经
  `Type.GetType(name + ", Assembly-CSharp")` 反射解析（只用类型名与只读成员，不构造夹具）。

### 任务 10 保留 `.meta` 搬入 UnityView 的单向方案

- 契约文件（`Assets/Scripts/Core/Compatibility/Runtime/*.cs`）**整体连 `.meta` 搬入**
  `Assets/Scripts/UnityView/`，GUID 不变；`BattleRuntimeBootstrap` 与 `IBattleFrameAdapter`
  的 `.meta` 是场景序列化引用的载体，搬迁后场景引用自动保持。
- `CombatDemo`（Assembly-CSharp）与 `BattleSimulationSourceFactory` 继续留在旧程序集，
  只实现 UnityView 拥有的接口。**UnityView 不得反向引用 Legacy 类型**——这是唯一允许的依赖方向。
- PlayMode 测试程序集需要同步改引用目标（由 `ProjectHero.Compatibility.Runtime` 改为 `ProjectHero.UnityView`）；
  `AssemblyBoundaryAuthoringTests.ExpectedAssemblyNames` 是**冻结程序集清单**，任务 10 必须同步更新（见 §11）。

## 8. 时间来源与暂停/销毁语义

| 项 | 语义 | 证据 |
|---|---|---|
| Legacy 段帧时间 | `Time.deltaTime`（**受 `timeScale` 缩放**——刻意保留慢动作影响旧 Tick 率） | `LegacyUsesScaledDeltaTimeAndNewUsesUnscaledDeltaTime` 通过（`LastLegacyDeltaTime == 0.25`） |
| New 段帧时间 | `Time.unscaledDeltaTime`；`UnityBattleDriver` 对 `TimeScaleIsolated == false` 抛 `NEW_DRIVER_REQUIRES_UNSCALED_DELTA_TIME` | 同上（`LastNewDeltaTime == 0.05`）+ `VisualTimeScaleIsolationDoesNotLeakIntoNewSimulation` 通过（`timeScale = 0` 时仍推进） |
| 固定 Tick | 60 Ticks/s（与 `BattleTimeline.TicksPerSecond` 同量纲）；单帧最多 8 Tick，溢出保留在累加器（**不丢 Tick**） | 代码 + `NewModeNeverCallsLegacyAdvanceTime` |
| Bootstrap 暂停 | `SetPaused(true)` 后两侧**都不推进**（Legacy 适配器与 Shadow runner 各自有 pause guard） | `PausedBootstrapDoesNotAdvanceEitherSide` 通过 |
| 旧时间线暂停 | `BattleTimeline.Paused` 时 `AdvanceTime` 立即 return（保留旧语义），但**计数仍自增**（计数是事实记录，不参与暂停判断） | 同上 + §7 |
| 销毁边界 | `OnDestroy` → `StopBattle("BOOTSTRAP_DESTROYED")` → `ReleaseBattle()`；停止/释放幂等；每个 Bootstrap 至多一条 `DestroyedStopReasons` 记录 | `DestroyingBattleStopsActiveAdaptersExactlyOnce`（**部分通过**：停止/释放幂等断言通过，销毁边界断言失败，见 §13） |
| 每场战斗一次 | `StartBattle` 重复调用抛 `BOOTSTRAP_DOUBLE_START`；模式在战斗创建后 `TrySetRequestedMode` 拒绝 | `RuntimeModeCannotChangeDuringActiveBattle` 通过 |

## 10. Shadow 独立性与比较配置

  **分类表里两条记录都存在且正确**，说明分类表侧没有问题。
- 根因：`RuntimeCallbackRegistry.IsUnclassifiedLogicWriter` 使用 `Type.GetMethod(..., DeclaredOnly)`

  的静态类型扫描（不依赖场景实例），或在 PlayMode 夹具里先 `yield return null` 让装机链稳定后再扫描。

### 13.5 `DuplicateRuntimeBootstrapFailsFast` —— 重复组件未被计入存活实例数

> → **收尾轮已解决，且本节原根因判断是错的**。真实根因：`BattleRuntimeBootstrap` 带

### 13.7 `DestroyingBattleStopsActiveAdaptersExactlyOnce` —— 重新开局失败

   `ShadowBattleRunner` 加回 `Update()`/`Coroutine`/`Timer`。新系统的推进只能由

   只能保持为 `ProjectHero.Logic`；新接缝一律走接口 + 显式序列化槽位。

   New 模式未分类门禁的唯一依据；任务 04–09 每迁移掉一个写入者，都要把它从

4. **只读检查点顺序。** `CheckpointExecutionOrder(+10000)` 必须始终大于所有已登记写入者的顺序；
   新增写入者时若其脚本执行顺序 ≥ 10000，`WritersExecutingAtOrAfterCheckpoint()` 会失败。
5. **暂不可比较字段只能减少，不能转为永久批准差异。** 3 条记录各自带负责任务（07/07/04）与
   最迟清零门槛（任务 10 切换主场景到 New 之前）；任务 10 之前必须归零。
6. **Shadow 比较配置版本。** 字段集合、分类或对齐规则变化时必须提升
   `ShadowComparisonConfig.CurrentVersion` 并同步报告断言。
7. **不得为了让比较通过而放宽断言。** 首个非预期差异必须精确定位；禁止忽略整类事件/血量/位置。
8. **GBK 源文件。** `CombatDemo.cs` 与 `UIManager.cs` 仍为 cp936 + CRLF + 无 BOM；
   后续任务改动它们时必须**先按 cp936 读出、写回后再按 cp936 读回核对中文**（§17 R1 记录了事故与修复）。
