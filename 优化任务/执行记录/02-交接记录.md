## 2. ID 值类型与校验规则（必须产出 6/7）

### 2.1 配置定义 ID（12 种，`ProjectHero.Logic.Ids`，底层 string）

`UnitDefinitionId`、`ActionSpecId`、`VolumeSpecId`、`AttackPatternId`、`MovementPatternId`、`ActionSetId`、`DamageChannelId`、`ImpactProfileId`、`StatusEffectSpecId`、`EncounterDefinitionId`、`EncounterSlotId`、`FactionId`。

- 格式：非空、仅小写英文字母 `a-z`、数字 `0-9`、点 `.`、下划线 `_`（`DefinitionIdValidation.IsValidFormat`）。
- 校验收敛于 `DefinitionIdValidation`（ID 值类型保持哑构造，与主方案 2.2.1 一致）：`ID_EMPTY` / `ID_INVALID_CHARACTERS` / `ID_DUPLICATE`。
- 同一命名空间内不得重复（Ordinal 比较）；禁止把显示名、GameObject 名、资源加载顺序或 Unity 实例 ID 转换成 Logic ID；不得用数字前缀编码对象类别。
- 内置常量：伤害通道 8 个（`physical.blunt/slash/pierce`、`elemental.fire/frost/lightning`、`arcane`、`true`，`DamageChannels`）；冲击 Profile 3 个（`impact.blunt/slash/pierce`，`ImpactProfiles`）；阵营示例 `hero` / `monster`（01B 拍板 A1，`FactionIds`）。

### 2.2 战斗实例 ID（5 种，底层 long）

`UnitId`、`ActionPlanId`、`ReactionOpportunityId`、`WindowId`、`EffectId`：0 保留为无效值（default 即无效），首个有效值为 1；`LogicIdGenerator` 各计数器从 1 起、单场单调递增、不复用；所有下一个值必须进入规范化快照与哈希（任务 03 落实）。不同类型间**无隐式转换运算符**（测试用反射锁定）；`GridPoint`/`MovementSegment`/`Reservation` 不建立独立 ID（主方案 2.2.2）。

## 3. 五类 TimingSpec / Payload 与量化规则（必须产出 2/10）

| 动作 | TimingSpec | Payload | 量化/时序规则（版本化，进哈希） |
|---|---|---|---|
| Attack | `AttackTimingSpec(BaseWindupTicks, RecoveryTicks)` | `AttackPayloadSpec(DamageComponents[], ImpactProfileId, ForceMultiplier, TargetPolicy, AllowedTargetRelations, MomentumDirectionOffsetSteps, AttackPatternSpec, AttackTagMask)` | 兼容链 `BaseTime → BaseWindupSeconds → BaseWindupTicks = RoundHalfUp(秒 × TicksPerSecond)`；`ResolvedWindupTicks = max(1, RoundHalfUp(BaseWindupTicks × ReferenceActionSpeed / ActionSpeed))`（ReferenceActionSpeed=20）；后摇不随速度缩放；缺后摇用 DefaultAttackRecoveryTicks=30（禁止运行时硬编码 0.5f）；`ImpactTick = StartTick + ResolvedWindupTicks`、`EndTick = ImpactTick + RecoveryTicks`、`BudgetCostTicks = 前摇+后摇` |
| Guard | `GuardTimingSpec(WindupTicks, ActiveTicks, RecoveryTicks)` | `GuardPayloadSpec(DamageResistanceQ10[通道], MomentumResistanceQ10, EligibleTags)` | 部分抵抗只在半开 `[ActiveStartTick, ActiveEndTick)`；分通道伤害抵抗与动量抵抗各严格 ∈ [1,1023]（定义层保证"部分"）；`BudgetCostTicks = 三段和` |
| Move | `MoveTimingSpec(BaseStepTicks, RecoveryTicks)` | `MovePayloadSpec(MaxPathWeightUnits, MovementPatternSpec)` | `ResolvedBaseStepTicks = max(1, RoundHalfUp(BaseStepTicks × ReferenceMoveSpeed / MoveSpeed))`（ReferenceMoveSpeed=20）；每边 `DurationTicks = StepWeightUnits(方向) × ResolvedBaseStepTicks`（checked）；MoveSpeed 不参与选路；`MaxPathWeightUnits ∈ (0, PathSearchRules.MaxPathWeightUnits]`；旧逐边 0.2-4.0s 浮点 Clamp **不属于**新规则（仅 max(1,·) + RoundHalfUp） |
| Block | `BlockReactionTimingSpec(ReactionWindupTicks, RecoveryTicks)` | `BlockPayloadSpec(EligibleTags)`（无抵抗字段！） | `TriggerTick = 来源攻击 ImpactTick`（Logic 固定推导）、`StartTick = TriggerTick - ReactionWindupTicks`、`EndTick = TriggerTick + RecoveryTicks`；合格接触伤害/动量抵抗由规则固定 1024（`BattleRules.FullBlockResistanceQ10`），Authoring 无降低字段；Windup/Recovery 不提供免伤；冻结 `ReactionWindupTicks=60`（旧 BlockDuration 1.0s） |
| Dodge | `DodgeReactionTimingSpec(ReactionWindupTicks, RecoveryTicks)` | `DodgePayloadSpec(MaxDistanceSteps, MovementPatternSpec)` | 同上推导；只有 TriggerTick 一次换格判定（任务 08 求解）；冻结 `ReactionWindupTicks=30`（旧 DodgeDuration 0.5s）；不提供状态免伤 |

- 闭合匹配矩阵：`ActionType` ↔ Timing/Payload 具体类型一一对应（`ValidateTypePairing`），不得把攻击时序套用到其他动作。
- 费用：Attack/Guard/Move 的 `AdrenalineCost` 必须为 0；Block/Dodge 必须为正（拍板 Block=2、Dodge=1，`FrozenDesignValues`）。
- 校验：所有 TimingSpec Tick 为正整数；ActionSpeed/MoveSpeed 有限正数；伤害分量有限非负；ForceMultiplier 有限正数；非法配置以稳定原因码拒绝（`ActionDefinitionCodes`），不钳制。

## 7. 路径与强制位移规则（必须产出 14/15）

- `PathCostRules(EvenDirectionStepWeightUnits=1, OddDirectionStepWeightUnits=2)`（冻结字段化常量）+ 启发版本 `3.8-nonnegative-integer-v1`：`HeuristicWeightUnits(a,b) = dy + max(0, (dx-dy)/2)`（dx=|a.X-b.X|、dy=|a.Y-b.Y|，checked long，坐标差先转 long 再取绝对值）。`MoveSpeed` 不在任何路径成本/启发接口中（反射锁定）。
- `PathSearchRules(MaxExpandedNodes=4096, MaxPathWeightUnits=256, MaxPathEdges=192)`：三项必须为正；包含式边界（恰好等于合法，严格大于才失败）；搜索空间由 Encounter GridBoundary 唯一限定。稳定失败码（任务 06 使用）：`PATH_INVALID_START`、`PATH_INVALID_DESTINATION`、`PATH_COST_OVERFLOW`、`PATH_SEARCH_NODE_LIMIT_EXCEEDED`、`PATH_EDGE_LIMIT_EXCEEDED`、`PATH_WEIGHT_LIMIT_EXCEEDED`、`PATH_NOT_FOUND`。
- `GridPoint` 合法点 X+Y 偶数；`TrianglePoint` 合法点 T∈{-1,1} 且 X+Y+T 偶数。Logic 运行时只允许方向索引查表 + 整数平移（`DirectionalTableQuery.GetTrianglesFor`），不暴露任意角旋转/三角/浮点舍入。

## 8. 12 向规范表与 60° 整数展开（必须产出 13）

- `AttackPatternSpec` / `VolumeSpec` / `MovementPatternSpec` 持有严格按 `GridDirection 0→11` 排列的 12 个 `DirectionalTriangleSet`；每个方向内按 `(X,Y,T)` 去重并升序。
- 定义构建专用 `DirectionalGeometry.Rotate60CounterClockwise`：`X'=(X-3Y-T)/2, Y'=(X+Y+T)/2, T'=-T`（受检整数；合法点奇偶约束保证整除；溢出 → `DIRECTIONAL_EXPANSION_OVERFLOW`）。`ExpandFromBases(evenBase, oddBase)`：East 基准旋转 0..5 次填偶数方向、EastNorth 基准填奇数方向；缺基准 → `DIRECTIONAL_BASE_MISSING`（不用偶数基准猜 30° 方向）。
- 适配器 `LegacyGridDefinitionConverter`：旧资产显式序列化的其他方向只作校验输入，与展开结果逐点比较，不一致 → `DIRECTIONAL_TABLE_MISMATCH`。

### 14.3 编译期修正记录（真实过程，不隐瞒）

首次编译暴露 Unity 6000.6.2f1 默认 C# 9 的边界：`record struct` 是 C# 10 特性（CS8773）、`init` 需要 `IsExternalInit`（CS0518，netstandard2.1 无此类型）。修复：Logic 增加标准 polyfill `IsExternalInit.cs`（`namespace System.Runtime.CompilerServices` 内的 internal 空类）；19 个 ID/协议/伤害分量值类型改为手写只读结构体（类 record 保留，C# 9 可用）。其余编译错误均为命名参数大小写（record 主构造参数是 PascalCase）、`Action` 类型歧义（System.Action vs 旧 Action，已全限定）、缺 using 等，逐项修复后全绿。测试程序集发现机制额外踩坑：Unity 6 按 `AssemblyFlags.EditorOnly` 分桶，EditMode 测试 asmdef 必须 `includePlatforms: ["Editor"]`，否则被归入 PlayMode 桶而不执行（已实测验证并写入 §1）。
