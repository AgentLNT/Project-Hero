## ④ 排列不变性的构造方式与证据

**用例**：`ForcedDisplacementInputAndResolutionPermutationsProduceIdenticalResults`（任务包 :358，逐字同名）。

**构造**：同一个几何（1 号 `(0,0)`、2 号 `(2,0)`、3 号 `(10,0)`，另有 plan 11 在 `(8,0)` 的预留）跑**两次真实不同的输入排列**：
`[1 East 2, 2 East 2, 3 West 1]`（正序）与把它**整体倒序**后的 `[3 West 1, 2 East 2, 1 East 2]`。
断言比较的是**规范化描述串**：每单位 `UnitId : From -> To / AppliedSteps / StopReason / [InvalidatedPlanIds]` 的拼接。
并先断言该描述串**非平凡**（含真实换位 `->`、含失效候选 `[11]`），否则"排列不变"是空断言。

**为什么每个稳定键都与输入顺序无关**：

| 环节 | 稳定键 | 为什么与输入排列无关 |
|---|---|---|
| 请求规范化 | `UnitId.Value` 升序 | 求解器在入口 `ordered.Sort(...)`，内部**只有一个顺序来源**；重复键检测在同一排序后进行 |
| 每轮活动集 | `proposals` 数组下标（= 已排序的请求序） | `active` 只按下标升序收集，不遍历任何哈希容器 |
| 同锚点/重叠判定 | `GridPoint` 值的逐对比较 | 双重循环 + 值比较，**没有**"谁先提出"的概念 |
| 依赖图 | 节点 = 数组下标；边 = 目标 footprint 的**占位所有者**（`TempSpace` 值的查询） | `IndexOfUnit` 是按 `UnitId` 升序线性查找；`DependencyEdgeCount` 也因此与排列无关 |
| 循环判定 | 从每个节点沿依赖边做可达性搜索 | 只依赖图结构，不依赖发现顺序 |
| 不动点分类 | 逐轮扫描下标序，直到无变化 | 单调收敛（循环预标记后剩余子图无环），结果与扫描顺序无关 |
| 失效候选 | `AllReservationsOrdered()`（规范空间键序）+ `CollectNonTerminalPlansOfUnit`（`ActionPlanId` 序）+ 最终 `ids.Sort()` | 三类来源各自规范化，最终再去重升序 |
| 输出 | `FromResolutions` 内部 `TargetUnitId` 升序 | 结果集合与位移集合都只有这一种顺序 |
| 事件 | `CleanupAndCommitRelocationBatch` 直接遍历 `Resolutions`（已升序） | 事件 `Sequence` 由 Outbox 单调分配 ⇒ 事件序列也一致 |
| 哈希 | 位置/朝向/停止原因/失效计划都在 `Resolution`/网格里；规则常量在 `BattleRules` | 输入排列不进任何哈希分量 |

**哈希层的排列不变性**：`ForcedDisplacementRulesParticipateInBattleDefinitionHash` 断言规则分量逐个参与摘要；
位置侧的排列不变由上面的 `Describe(...)` 相等保证（哈希是位置的函数，位置相等 ⇒ 哈希相等）。
