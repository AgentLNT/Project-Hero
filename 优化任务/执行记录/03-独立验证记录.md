### D3（中）`CommandIngressEntry.InjectRecordedFact(long producerOrdinal, …)` 是公开的"可填写 ProducerOrdinal"入口，与验收标准冲突且无测试覆盖

**证据**

- `Assets/Scripts/Logic/Commands/CommandIngressEntry.cs:116`
  ```csharp
  public CommandIngressRejection InjectRecordedFact(long producerOrdinal, CommandRequest request)
  ```
  是 **public**，且经 `BattleSimulation.CommandIngress`（public，`BattleSimulation.cs:238`）→ `CommandIngressRegistry.FindEntry`（public，`CommandIngressRegistry.cs:176`）→ `CommandIngressEntry` 完全可达。
- 另有 DTO 重载 `InjectRecordedFact(RecordedCommandRequest fact)`（`CommandIngressEntry.cs:96`，public），而 `RecordedCommandRequest` 是公开 record，其 `ProducerOrdinal` 为公开构造参数（`ReplayContracts.cs:50-54`）。

**违反的冻结条文**

- 任务包核心契约：*"生产者不得填写 `ControllerId`、`CommandSourceKind`、`SourcePriority`、`ProducerOrdinal` 或 `CommandSequence`"*（`03-确定性内核.md:72`）。
- 验收标准：*"UI/AI 可见 API 中不存在可填写来源优先级、发行者、生产者序号、全局命令序号、规则费用或反应 TriggerTick 的入口"*（`03-确定性内核.md:179`）。

**测试缺口（关键）**

- 必需测试 `ProducerCannotProvideSourcePriorityOrCommandSequence`（`CommandIngressTests.cs:282-327`）的 `producerVisible` 白名单只含 `CommandRequest` / 三个 scope / 三类 payload / 四种排程操作，**不含 `CommandIngressEntry`**；它也不扫描"任何 public 成员是否接受序号参数"。因此上述验收标准**没有被任何一条测试真正验证**。
- 交接 §3.2 声称的反射断言（*"生产者可见类型…不存在名称含 `SourcePriority`、`CommandSequence`、`ProducerOrdinal`…的公开成员"*）同样只覆盖该白名单，措辞容易被读成已覆盖全公开面。

**缓解事实（不改变结论，但影响定级）**

- 非 Player 入口被稳定拒绝：`OnInjectRecordedFact` 首检 `entry.SourceKind != Player → REPLAY_NON_PLAYER_SOURCE_NOT_AUTHORITATIVE`（`CommandIngressRegistry.cs:349-351`）；序号必须 `>= 1`；注入事实仍要过网关的重复/回退/结构校验。
- `ControllerId` / `CommandSourceKind` / `SourcePriority` **确实不可伪造**（由入口绑定派生），`CommandSequence` **确实只由 `CommandGateway` 分配**（`CommandGateway.cs:252-253`）——契约的这几项成立。
- 两项必需测试**正是依赖**该 API 才能构造碰撞组与序号回退：`DuplicateProducerOrdinalRejectsEntireCollisionGroup`（`CommandIngressTests.cs:201-202`）、`ProducerOrdinalRegressionIsRejected`（`CommandIngressTests.cs:240`）。因为 `Submit` 自动分配严格递增序号，没有注入面就**无法**触发这两条路径。

**张力说明（需协调者裁决）**：任务包同时要求"生产者不得填写序号"与"Tick 0 重演按**原始** `ProducerOrdinal` 记录玩家请求"（`03-确定性内核.md:63`、`217`）；二者必然需要一个受控注入面。当前实现选择了"public + 语义注释约束"，而非"internal / 回放会话令牌"。

**建议归属**：任务 03 补正 ——（a）把裸 `long` 重载收窄为 `internal`（或在交接中显式裁决其定位并写入 03B 约束）；（b）补一条"公开面不存在接受 ProducerOrdinal/CommandSequence 的入口"的反射测试，使该验收标准真正可证伪。若协调者判定 DTO 重载属回放契约的固有部分，则应把验收标准改写为"仅回放 DTO 可携带序号，且必须经入口重新验证"，而不是留一条无人验证的绝对条款。
