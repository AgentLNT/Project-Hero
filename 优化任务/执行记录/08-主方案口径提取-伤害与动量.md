## 1. `RawAmount` 的 float→定点口径

### 1.1 主方案原文（逐字）

**主方案 `0.4.2.1`（`优化方案-逻辑表现解耦与逻辑帧判定.md:342-346`）** 定义载荷结构：

```csharp
public readonly record struct DamageComponentSpec(
    DamageChannelId ChannelId,
    float RawAmount,
    DamageTagMask Tags);
```

**主方案 `0.4.2.1`（`:396-417`）** 定义结算顺序：

```text
直接接触先构造原始载荷，再按以下顺序结算：

LegacyBaseComponent =
  DamageComponent(ChannelFromLegacyImpactType, ActionSpec.BaseDamage)
LegacyImpactComponent =
  DamageComponent(physical.blunt, MomentumUnits / 5000)
ClashResidualComponent =
  DamageComponent(physical.blunt, ResidualMomentumUnits / 1000)

AfterPassiveResistance =
  Has(BypassPassiveResistance)
    ? RawAmount
    : RawAmount * (1024 - Target.BaseDamageResistanceQ10[Channel]) / 1024
AfterActionResistance =
  Has(BypassActionResistance)
    ? AfterPassiveResistance
    : AfterPassiveResistance * (1024 - ActiveDefense.DamageResistanceQ10[Channel]) / 1024
AfterMomentumResistanceUnits =
  RoundHalfUp(IncomingMomentumUnits
    * (1024 - ActiveDefense.MomentumResistanceQ10) / 1024)
```

**主方案 `0.4.2.1`（`:421`）**：

> 目标的全部接触先按 `ContactKey → DamageChannelId` 排序，以 `double` 中间值分别求和，最后只转换一次为逻辑血量使用的 `float`；不得按容器发现顺序逐次做 float 累加。伤害事件必须保留各通道的 Raw、被动抵抗后、动作抵抗后数值以及抵抗来源，便于验证 Guard/Block 是否只修改了预期维度。

## 3. `0.4.2.1` 目标聚合公式逐步骤抄录

主方案 `0.4.2.1` 标题为「首版动量、伤害与控制量化」（`:336`）。以下按主方案 `:396-436` **逐段抄录**，并标注落点类型与清单条目号。

### 步骤 0（载荷构造，`:396-404`）

```text

  DamageComponent(ChannelFromLegacyImpactType, ActionSpec.BaseDamage)
LegacyImpactComponent =
```

### 步骤 1（逐分量：被动抵抗 → 动作抵抗，`:406-417`）

```text
AfterPassiveResistance =
  Has(BypassPassiveResistance)
    ? RawAmount
    : RawAmount * (1024 - Target.BaseDamageResistanceQ10[Channel]) / 1024
AfterActionResistance =
  Has(BypassActionResistance)
    ? AfterPassiveResistance
    : AfterPassiveResistance * (1024 - ActiveDefense.DamageResistanceQ10[Channel]) / 1024
AfterMomentumResistanceUnits =
  RoundHalfUp(IncomingMomentumUnits
    * (1024 - ActiveDefense.MomentumResistanceQ10) / 1024)
```

主方案补充（`:419`）：

> `Guard` 为 `Guardable` 分量提供配置的部分 `DamageResistanceQ10`，并对动量提供独立的部分 `MomentumResistanceQ10`。`Block` 对 `Blockable` 分量和可格挡动量使用 1024，因此结果严格为 0；不合格分量继续正常结算。没有活动防御时动作抵抗为 0。抵抗按“被动 → 动作”依次乘算，不相加，禁止用单个 `DamageReduction` 同时覆盖所有通道和动量。

**落点**：`ResolutionSolver` 聚合阶段；清单 §1.11（`:143-153`），条目号 **18 / 19 / 48 / 51 / 52**（清单 §4.1 `:540`、`:541`、`:570`、`:573`、`:574`）。
**既有接缝**：被动抵抗 `UnitDefinition.BaseDamageResistanceQ10`（`Assets/Scripts/Logic/Combat/UnitDefinition.cs:37`，按通道 7 项、无通用 `DamageReduction`）；动作抵抗 `GuardPayloadSpec`（`ActionPayloadSpec.cs:60-63`）；Block 固定值 `BattleRules.FullBlockResistanceQ10 = 1024`（`BattleRules.cs:44`，已进哈希 `:109`）；标签 `DamageTagMask`（`DamageComponentSpec.cs:11-18`）+ 矛盾标签校验（`:81-86`）。
**歧义待裁定**：`:414-416` 的 `AfterMomentumResistanceUnits` 写作 `RoundHalfUp(整数 × 整数 / 1024)`，**未写「整数除法」**（对比 `:332` 对 `LossFromBToA` 明写「整数除法向下取整；`+512` 表示 half-up」）。既有 `TickQuantization.RoundHalfUpDivide(numerator, denominator)`（`Assets/Scripts/Logic/Combat/TickQuantization.cs:20-33`，实现 `(2n + d) / (2d)`）可等价表达，但 08 需裁定「分子先乘再一次性 RoundHalfUp」是否符合 `:415-416` 字面。

### 步骤 3（控制阈值与击退，`:423-434`）

### 步骤 4（抵抗后总冲击、有向合力、控制结果，主方案 `0.4.5` `:488-490`）

> 7. 对每个目标收集所有未失效的直接 Hit 和 ClashResidualImpact：各 `DamageChannelId` 的分量按稳定键求和；`TotalImpactUnits` 累加抵抗后的入射动量绝对值；有向合力按 Q10 方向向量求和。
> 8. 合力方向选择与合力向量点积最大的 `GridDirection`，并列时取枚举值较小者；最大点积不大于 0 时无击退方向。合力强度为 `maxDot / 1024` 向下取整。
> 9. 硬直/击倒阈值读取 `TotalImpactUnits`，击退读取有向合力。因此两股等强反向冲量会造成两次伤害并累加硬直，但击退可以为零。

任务包对应冻结（`08:109-111`）：

> - 目标合力以 `Σ(DirectionVectorQ10 * RemainingMomentum)` 求和。
> - 合力方向选择点积最大的 GridDirection，并列取枚举值较小者；最大点积不大于 0 时无击退方向。
> - 合力强度使用 `maxDot / 1024` 向下取整；硬直/击倒阈值只读取所有入射动量绝对值之和 `TotalImpactUnits`。

**落点**：`TargetAggregateResolution`（清单 §1.7 `:123`、§3.5 `:490`），条目号 **29 / 41 / 66**（清单 `:551`、`:563`、`:588`）。
**待裁定（口径级，非笔误）**：`:489`「合力强度为 `maxDot / 1024` 向下取整」——`maxDot` 的量纲为 `1024 × ΣMomentumUnits`，除以 1024 后与 `ΣMomentumUnits` 同域，也与任务包 `:111` 逐字一致；但主方案**未说明**该「合力强度」与 `:432` 的 `ResultantMomentumUnits` 是否同一个量（任务包 `:111` 把前者叫「合力强度」、`:103` 把后者当 `KnockbackSteps` 的分子）。合力的**逐方向比较**用点积即可（比值单调，`/1024` 不影响 argmax），可避开该歧义；但 `floor(ResultantMomentumUnits / ControlResistanceUnits)` 的分子必须有唯一定义。**需调度者裁定。**

### 步骤 5（提交顺序，主方案 `0.4.5` `:492`）

> 所有 `ContactResolution`、`ActionTerminalResolution` 和 `TargetAggregateResolution` 计算完成后，`ResolutionCommitter` 才能按稳定顺序统一提交。由目标聚合产生的击退必须再进入 0.4.6 的全 Tick 同时强制位移批次；不能按冲突组或目标逐个改写世界。死亡只在批量换位、状态和控制提交后处理，允许同 Tick 同归于尽。

**落点**：`Logic/Interactions/ResolutionCommitter.cs`（清单 §1.13 `:162-170`），条目号 **13 / 66 / 92 / 96 / 97**（清单 `:583`、`:588`、`:614`、`:618`、`:619`）。
