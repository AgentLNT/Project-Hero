## 0. 执行摘要

任务 03 全部「必须产出」13 项落地，20 个 Step 阶段按任务包顺序冻结并可从代码与测试直接识别，
57 个必需测试名逐一命名并通过（另加 13 项补充用例，共 70 项新增用例）。

- 唯一模拟入口：`BattleSimulation.Step(long tick, FrozenCommandBatch externalBatch)`；
  `FrozenCommandBatch` 只有 `CommandIngressRegistry` 能创建，且 `Step` 校验批次上的**注册表印记**，
  驱动器既不能构造批次、也不能伪造其中的来源事实。
- 命令边界：`CommandRequest(TargetTick, Scope, Payload)` → 入口注册表（唯一信任边界，分配
  `ProducerOrdinal`）→ `CommandGateway`（派生 `SourcePriority`、规范化、重复/回退拒绝、分配唯一
  `CommandSequence`）→ **内部** `CommandEnvelope`（构造器非 public）。
- 规范化快照覆盖入口注册/每入口下一个与已冻结 `ProducerOrdinal`/未来 Tick 桶/全部 ID/Sequence/
  RNG/全局 `ScheduleRevision`/`HistorySummary`；Canonical 与 Decision **分型**。
- 历史归档：`ArchivedAtTick → RecordKind → StableKey` 顺序、域分离长度前缀编码、固定初始种子、
  增量摘要 + 独立完整重算参照 + 访问计数夹具；**无新增归档的 Tick 旧历史访问 = 0/0/0**（实测）。
- 生命周期：`Create → Step* → RequestStop → Dispose`；重复停止/释放幂等，释放后 `Step` 明确拒绝。
- 未实现系统全部是**明确的空实现或小接口占位**（阶段不被合并、不被跳过），任务 04–11 可直接接入。

## 3. 核心契约（冻结）

### 3.1 命令边界：`CommandRequest → CommandIngress → CommandGateway → internal CommandEnvelope`

```text
生产者：new CommandRequest(targetTick, scope, payload)          // 只有三样东西
   │  entry.Submit(request)                                     // 唯一信任边界：绑定 Controller/来源
   ▼
CommandIngressRegistry（按 TargetTick 分桶；每入口严格递增 ProducerOrdinal，从 1 起）
   │  registry.FreezeTick(tick) → FrozenCommandBatch            // 只有注册表能创建（构造器 internal + 注册表印记）
   ▼
BattleSimulation.Step(tick, batch)  ← 校验 tick 连续性、批次来源（印记）、批次/请求 Tick
   │  阶段 5：CommandGateway.NormalizeAndAssignSequence(...)
   ▼
FrozenTickCommandSet { Envelopes（规范顺序 + 唯一 CommandSequence）, RejectedCommands, IngressRejections }
   │  阶段 6：IFrozenCommandProcessor.ProcessOrdered(envelopes, tick, batchBaseScheduleRevision)
   ▼
处理器（任务 05–09）／占位槽：每条命令稳定拒绝为 COMMAND_PROCESSOR_NOT_IMPLEMENTED（不写任何状态）
```

**scope 判别**（`CommandScopes.KindOf`）：`ScheduleEditScope`（任务 02 冻结类型）/
`WindowCommandScope`（任务 03 补齐的第三类，同为 `Combat.CommandScope` 判别联合成员）/
`ReactionCommandScope`（任务 02 冻结类型）。**没有第二套 scope 体系**：
任务 03 复用 `ProjectHero.Logic.Combat` 里任务 02 冻结的 `CommandScope` 联合，只补齐窗口一类与判别函数。

**拒绝语义（稳定码）**

| 码 | 层级 | 语义 |
|---|---|---|
| `DUPLICATE_COMMAND_ORDINAL` | 入口级（无 CommandSequence） | 同一规范键出现多次 → **整个碰撞组**拒绝，`CollisionCount` = 组大小，没有赢家 |
| `COMMAND_ORDINAL_REGRESSION` | 入口级 | 序号 ≤ 入口**本批冻结前**的水位 |
| `SCOPE_PAYLOAD_MISMATCH` | 入口级 | scope 与 payload 判别不一致（不回退当前窗口、不临时查找机会） |
| `PAYLOAD_STRUCTURALLY_INVALID` | 入口级 | 空操作列表 / Dodge 缺目的格 / Block 携带目的格 / 动作 ID 格式非法 |
| `REPLAY_NON_PLAYER_SOURCE_NOT_AUTHORITATIVE` | 入口级 | 非 Player 入口注入记录事实（首版权威回放只接受 Player） |
| `COMMAND_ORDINAL_INVALID` | 入口级 | 记录事实序号 < 1 |
| `LATE_REQUEST_FOR_FROZEN_TICK` | 入口级 | 批次冻结后到达、目标 Tick 已被冻结（不静默丢弃） |
| `STALE_REQUEST_TARGET_TICK_SKIPPED` | 入口级 | 目标 Tick 在推进中被跳过（永远等不到 Step） |
| `BATTLE_ALREADY_ENDED` | 入口级 | 进入终态后的新命令（不进入 Tick 桶） |
| `SYSTEM_SOURCE_INTERNAL_ONLY` | 入口级（API 误用） | 外部调用者试图经公开 `Submit` 使用系统来源入口 |
| `COMMAND_PROCESSOR_NOT_IMPLEMENTED` | 处理器级（**已**有 CommandSequence） | 任务 03 占位槽 |
| `EXTERNAL_INGRESS_SYSTEM_SOURCE_REJECTED` | 注册期异常 | 外部把入口注册为 `System` |
| `COMMAND_INGRESS_DUPLICATE_CONTROLLER` / `COMMAND_INGRESS_CONTROLLER_INVALID` | 注册期异常 | 重复/非法 ControllerId |

**判定优先级（冻结）**：重复（键级）→ 回退（键级）→ 结构（载荷级）。
入口级拒绝**不消耗** `ProducerOrdinal`，也**不分配** `CommandSequence`；
每个非法规范键只产生**一个**按组键排序的 `CommandIngressRejectedEvent`（记录 Controller、SourceKind、
SourcePriority、ProducerOrdinal、原因、碰撞数量；**不回显任何成员载荷**）。

### 3.2 信任边界与防伪造

- `FrozenCommandBatch` / `SourcedCommandRequest` / `CommandEnvelope` **没有 public 构造器**（反射测试断言）。
- `FrozenCommandBatch.RegistryStamp` 是本注册表的私有对象；`Step` 用 `ReferenceEquals` 校验，
  其它注册表（或伪造对象）冻结的批次以 `STEP_BATCH_NOT_FROM_REGISTRY` 拒绝。
- `CommandIngressRegistry.RegisterSystemEntry` 是 **internal**；公开面没有系统来源注册入口（反射断言）。
- 系统来源入口的**公开** `Submit` 一律以 `SYSTEM_SOURCE_INTERNAL_ONLY` 拒绝；Logic 内部系统走
  `internal SubmitSystemInternal`（任务 05+ 的系统事务使用）。
- 生产者可见类型（`CommandRequest` / 三个 scope / 三类 payload / 三种排程操作）经反射断言：
  不存在名称含 `SourcePriority`、`CommandSequence`、`ProducerOrdinal`、`ControllerId`、`SourceKind`、
  `Issuer`、`TriggerTick`、`Cost`、`Adrenaline`、`Budget`、`MetaResource`、`Price`、`Fee` 的公开成员。

### 3.3 所有排序键（唯一权威）

| 对象 | 排序键 |
|---|---|
| 命令规范顺序 | `SourcePriority → ControllerId(StringComparer.Ordinal) → ProducerOrdinal`（原始枚举顺序**不是**末级键） |
| 入口（快照/哈希/注册表枚举） | `SourcePriority → ControllerId(Ordinal) → RegistrationOrdinal` |
| 入口拒绝事件 | 组键 `SourcePriority → ControllerId(Ordinal) → ProducerOrdinal` |
| UnitId 分配 | `EncounterSlotId` 的 `StringComparer.Ordinal` 升序（任务 02B 初始化器） |
| `LogicSnapshot` 哈希 | 单位 `UnitId`；效果 `UnitId→AppliedAtTick→EffectSequence`；窗口 `WindowId`；计划 `ActionPlanId`；机会 `ReactionOpportunityId`；Lane `UnitId`；Intent `IntentSequence`；段 `(ActionPlanId, StepIndex)`；Reservation `(ActionPlanId, X, Y)`；AI `ControllerId(Ordinal)`；入口（见上）；桶 `TargetTick` |
| 历史归档 | `ArchivedAtTick → RecordKind 整数值 → StableKey(Ordinal)` |
| 阶段内批次应用 | 状态推进请求按 `UnitId`；强制位移请求/换位按 `TargetUnitId`；处理器拒绝按 `CommandSequence`；死亡事件按 `UnitId` |
| 决策观察者 / 不变量检查 / 归档来源 | 显式装配顺序（**不是**容器或反射注册顺序） |

### 3.4 ID / Sequence / 计数器

| 类别 | 类型 | 起点 | 快照字段 |
|---|---|---|---|
| 实例 ID | `UnitId` / `ActionPlanId` / `ReactionOpportunityId` / `WindowId` / `EffectId`（`long` 包装，0 无效） | 1，单场单调、不复用 | `NextUnitId` / `NextActionPlanId` / `NextReactionOpportunityId` / `NextWindowId` / `NextEffectId` |
| Sequence | Command / Intent / Resolution / Event / Effect 顺序（`LogicSequenceGenerator`） | 1，与 ID **完全独立** | `NextCommandSequence` / `NextIntentSequence` / `NextResolutionSequence` / `NextEventSequence` / `NextEffectSequence` |
| 入口序号 | 每入口 `ProducerOrdinal`（严格递增） | 1 | 每入口 `NextProducerOrdinal` 与 `FrozenProducerOrdinal`（已冻结水位） |
| 归档计数 | `HistorySummary.RecordCount` | 0 | 不占用玩法 ID 或 EventSequence |

- `UnitId`：固定单位按 `EncounterSlotId` 的 Ordinal 顺序（主战斗场景顺序为 `enemy=1`、`hero=2`）；
  动态单位按规范化命令处理顺序调用同一个 `NextUnitId()`（任务 04 接入；计数器已进快照）。
- `FactionId`：创建事实，来自槽位/显式继承策略；入口、Controller 或 View 不能覆盖（`UnitSnapshot` 从首版即含）。
- 死亡、取消或集合清理**不回退、不复用**任何 ID/Sequence。

### 3.5 RNG、事件、编码

- `DeterministicRng`（`splitmix64-v1`，`AlgorithmVersion = 1`）：状态进快照与哈希；
  `PickIndex(candidateCount)` 只接受候选**数量**（候选集必须先按稳定键排序）；
  **没有** `State` setter、没有 `FromState` 工厂、没有中途恢复 API。
- `LogicEvent`（不可变） / `EventBatch`（只读包装） / `LogicEventOutbox`：事件序号整场单调递增、
  不按 Tick 清零；Tick 末一次性可见；不含震屏/顿帧/Animator 等表现数据。
- 规范编码（`CanonicalEncoder`）：域标记长度前缀 + **所有整数 8 字节小端**（含长度前缀）+
  UTF-8 字符串长度前缀 + 单字节布尔 + 字节数组长度前缀 + 集合"先计数后逐项"；
  摘要 = FNV-1a 64，宽度固定 16 位小写十六进制。**编码/宽度/域标记/类型键全部纳入 `ReplayFormat.Version`**。
- 哈希域标记：`HistorySeed` / `HistoryAppend` / `LogicSnapshot`（另定义 `InitialStateHash` 域名常量）。

### 3.6 规范化快照与历史摘要

```
H0 = Hash(Encode("HistorySeed", ReplayFormatVersion))
Hi = Hash(Encode("HistoryAppend", ReplayFormatVersion, H(i-1), i, ArchivedAtTick, RecordKind, StableKey, RecordPayload))
SnapshotHash(T) = Hash(Encode("LogicSnapshot", ReplayFormatVersion, T, 活动状态…, RecordCount, H(RecordCount)))
```

- `LogicSnapshot`：32 字段，含 `RulesVersion`、`BattleDefinitionHash`、`EncounterId`、
  `BattleEnd`、`Units`（含 FactionId）、Effects/窗口/并发/资源/Plans/机会/Lane/Intent/Segment/Reservation/AI
  的**已冻结空槽位**、`ScheduleRevision`、入口快照、RNG、全部 next 值、`HistorySummary`、
  `CommandSourcePriorityMappingVersion`。
- 哈希前每类集合按各自冻结键**重新规范排序**（`CanonicalSnapshotIgnoresInsertionOrder` 证明插入顺序无关）；
  所有集合以 `Array.AsReadOnly` 冻结，不可经别名改写（`StepResultExposesOnlyImmutableEventsAndSnapshot`）。
- 未实现系统的槽位类型（`ActionPlanSnapshot` / `ReactionOpportunitySnapshot` / `ActorLaneSnapshot` /
  `IntentSnapshot` / `MovementSegmentSnapshot` / `ReservationSnapshot` / `AiControllerSnapshot` /
  `StatusEffectSnapshot`）以**最小恒等键**冻结，任务 04–09 只**扩展字段**，不改槽位与排序键。
- 归档资格：候选必须携带 `HistorySealProof`；未封条候选被**跳过并计数**
  （`IneligibleCandidatesSkipped`），绝不提前冻结可变账本。
- 归档访问计数：`OldRecordReads` / `OldRecordCopies` / `OldRecordHashes` / `NewRecordsProcessed` /
  `TotalAppends` / `IneligibleCandidatesSkipped`；`AccessCounters` 返回**值拷贝**，
  `DeltaFrom(baseline)` 取差值（若直接持有活动引用，差值会恒为 0——该陷阱已被测试覆盖）。

- 不接受 `deltaTime`、MonoBehaviour、GameObject、View 或回调式表现依赖；
  帧时间到 Tick 的累积属于 03B/10 的外部适配器。
- `BattleSimulation` 不含 `Update()`、协程、定时器，也不读取 Unity 帧时间/时间缩放
  （`SimulationHasNoUnityTimeOrViewWritebackDependency`、`TimeScaleOrFrameTimingIsNotPartOfLogicInput` 反射 + 行为断言）。

### 4.2 首个 Step 之前的哈希读取时机

```csharp

string initialHex = sim.InitialStateHashHex;

// 契约：preStep.ComputeHash() == sim.InitialStateHash
```

再从 Tick 0 开始注入记录输入（`TickZeroReplayFromRecordedPlayerFactsReproducesIdenticalHashes` 用最小夹具证明）。

### 4.3 驱动器调用序列

```csharp
long tick = sim.Tick + 1;                                   // sim.Tick 初始为 -1
FrozenCommandBatch batch = sim.CommandIngress.FreezeTick(tick);   // 冻结当前 Tick（唯一合法批次来源）
StepResult result = sim.Step(tick, batch);                  // 唯一模拟入口
// 需要结束战斗时：
sim.RequestStop("RESULT_CODE");                             // 请求（幂等）；终止由下一个 Step 的阶段 2/16 原子提交
StepResult ended = sim.Step(sim.Tick + 1, sim.CommandIngress.FreezeTick(sim.Tick + 1));
// 释放：
sim.Dispose();                                              // 幂等
```

- 生产者投递：`sim.CommandIngress.FindEntry(controllerId).Submit(request)`（**必须在冻结之前**）；
  AI 在阶段 18 只经注册入口投递 `tick + 1`。
- 结束后误调用 `Step(任意 tick, 任意批次)` → `AlreadyEnded` + **空**事件批次 + **同一** `FinalSnapshot` 实例：
  不推进 Tick/RNG/ID/Sequence、不追加归档、不重复发事件。

### 4.4 不可变结果边界

`StepResult` 只有 `Status` / `Events` / `Snapshot`（+ 便捷只读派生属性），**全部只读**：
不暴露 Logic 内部集合、不暴露任何写接口、不接受快照作为输入。
`LogicSnapshot` / `DecisionSnapshot` / `FrozenTickCommandSet` / `HistoryDiagnosticView` 亦为只读，
集合经 `Array.AsReadOnly` 冻结。

### 4.5 失败语义（03B 必须按此分支）

| 情形 | 结果 |
|---|---|
| 释放后 `Step` | `LogicDefinitionException(SIMULATION_DISPOSED)` |
| `tick != 已完成 Tick + 1` | `LogicDefinitionException(STEP_TICK_NOT_CURRENT)`（活动战斗严格递增、不跳 Tick） |
| 批次不是本注册表冻结的 | `LogicDefinitionException(STEP_BATCH_NOT_FROM_REGISTRY)` |
| 批次 Tick / 成员请求 Tick ≠ Step Tick | `LogicDefinitionException(COMMAND_BATCH_TICK_MISMATCH)` |
| 战斗已结束 | **不是异常**：`StepStatus.AlreadyEnded` + 空批次 + 缓存最终快照 |
| 非法命令（重复/回退/scope 不匹配/迟到） | 不抛异常：`CommandIngressRejectedEvent`（入口级，无 CommandSequence） |
| 合法但未实现的命令 | `CommandRejectedEvent(COMMAND_PROCESSOR_NOT_IMPLEMENTED)`（有 CommandSequence） |
| 不变量检查失败 | `LogicDefinitionException(STEP_INVARIANT_VIOLATION)`，本 Tick 不归档 |
| 强制位移批量验证失败 | `LogicDefinitionException(STEP_RELOCATION_BATCH_INVALID)`，禁止逐单位退化提交 |

### 4.6 `LogicSnapshot` 不提供恢复保证（再次明确）

`LogicSnapshot` 是**观察/校验/哈希模型**：没有 `BattleSimulation.Restore(...)`、没有 `SimulationState`、
没有中途存档/载入、没有任意 Tick 跳转、没有周期性检查点
（`NoSimulationStateRestoreOrTickJumpApiExists` 反射断言）。
确定性只能通过"两次新建模拟并从 Tick 0 运行"证明——任务 03 用 100 次重复运行证明。

### 7.4 自纠错 2：我自己的性能夹具单位换算错误（已修正，保留记录）

- **发现方式**：阶段采样总和（0.02ms/Tick）与外部 Step 测量（11.2ms）相差 500 倍 → 触发自查。
- **处置**：修正换算（`×1000/Frequency`），并新增"阶段采样总和与外部 Step P50 必须同量级"的互证断言；
  同时把每 Tick 分配测量改为 §19 规定的 `Profiler.GetTotalAllocatedMemoryLong()`，
  并在计数恒为 0 时**明确报告"未获得有效测量"**而不是让全 0 样本伪装通过。
- **保留原因**：任务包要求"性能相关只做证据化声明，不得伪造数字"，故记录该错误的发现与修正过程。

### 7.5 自纠错 3：网关分组比较器把"原始序号"混进相等性（已修正）

- **现象**：`DuplicateProducerOrdinalRejectsEntireCollisionGroup` 首轮失败——同一规范键的两条事实
  没有被判为碰撞组（比较器把 `OriginalIndex` 当成了相等性的一部分）。
- **处置**：拆分"排序比较器"（含 `OriginalIndex` 稳定平局键）与"规范键相等性"
  （`SameCanonicalKey`，只比较 `SourcePriority/ControllerId/ProducerOrdinal`）；
  该测试同时验证"排列不同 → 拒绝事件与快照一致"。

### 7.6 自纠错 4：归档访问计数基线的别名陷阱（已修正）

- **现象**：`NewArchiveBatchProcessesOnlyNewRecords` 首轮失败（增量为 0），因为测试把**活动**计数器对象
  当成基线，`DeltaFrom` 与自己相减恒为 0。同时这会掩盖
  `EmptyArchiveBatchDoesNotReadCopyOrHashOldHistory`（当时是"假绿"）。
- **处置**：`HistoryArchive.AccessCounters` 改为返回**值拷贝**（新增 `Snapshot()`），
  并在文档中写明"基线必须取拷贝"。两项测试现在都是真断言。

### 7.7 自纠错 5：归档批次内 ArchiveIndex 重复（已修正）

- **现象**：`HistoryArchiveOrderIgnoresCandidateEnumerationOrder` 发现同批 4 条记录的 `ArchiveIndex`
  都是 1（`Summary.RecordCount + 1` 在循环内未自增），而摘要因增量与参照同源而"看起来一致"。
- **处置**：改为批内局部自增；该测试同时断言 `ArchiveIndex` 为 `1..N` 与规范顺序。

### 7.8 自纠错 6：入口拒绝未进入事件流（已修正）

- **现象**：`LateInputAfterBatchFreezeCannotMutateCurrentTickSchedule` 首轮失败——迟到请求的拒绝只
  返回给调用者，没有进入待排空队列，因此不会在 Step 中变成 `CommandIngressRejectedEvent`
  （违反"不得静默丢弃"）。
- **处置**：`OnSubmit` / `OnInjectRecordedFact` 的全部拒绝路径统一 `RecordPending(...)`，
  在第 5 阶段按组键排序排空并发射事件。

## 8. 对后续任务的约束（04–11）

1. **不得新建第二个模拟入口或第二套阶段链**：所有系统都接入 `SimulationPhaseSystems.cs` 已冻结的阶段槽位；
   装配顺序即执行顺序，禁止容器扫描/反射注册。
2. **不得改写已冻结的排序键、拒绝码、编码协议**：
   命令规范顺序、入口拒绝组键、归档顺序、快照哈希字段顺序、FNV-1a 64/16 位摘要、
   `ReplayFormat.Version` 的协议描述——改变任何一项都必须提升 `ReplayFormat.Version`
   并更新 golden，且**不得**借此改写 `RulesVersion` / `BattleDefinitionHash`。
3. **`ScheduleRevision` 语义**：成功命令排程事务与系统自动延期事务**各恰好 +1**；
   阶段 0–4 不得改动它（阶段 5 有硬断言）。
4. **不可变快照槽位**：任务 04–09 只能**扩展字段**；未归档计划快照与终态归档都必须含
   `AutomaticDeferralCount` 等完整审计字段；`LogicSnapshot` 与 `DecisionSnapshot` 保持分型，
   其他 Controller 的 Editable 计划不得进入决策快照。
5. **归档**：候选必须携带 `HistorySealProof`；关闭但仍可能退款/消费的账本必须未封条；
   归档前必须完成清理与只读不变量检查；不得扫描/复制/哈希旧记录（用 `HistoryAccessCounters` 自证）。
6. **命令身份**：任何新命令类型都只能经 `CommandIngressEntry.Submit` 投递；
   不得新增绕过入口的构造路径，不得让生产者提供 ControllerId/来源优先级/ProducerOrdinal/
   CommandSequence/费用/反应 TriggerTick。
7. **窗口**：`TurnWindow` 只控制提交权限与预算，不拥有动作、不是结算边界
   （`TurnWindowState` 结构上就没有计划集合）。
8. **强制位移**：必须保持"全 Tick 全局请求 → 只读临时求解 → 清理 → **一次**批量换位 + 事件"的四段结构；
   批量验证失败必须整体以 `STEP_RELOCATION_BATCH_INVALID` 失败，禁止逐单位退化提交。
9. **状态/控制与死亡**：阶段 14/15 只能读取批量换位之后的最终位置（阶段 14 的入参就是换位后快照）。
10. **任务 03B**：只用 §4 的公开接口；不得反射访问 Logic 内部可变对象；
    不得依赖 `LogicSnapshot` 作为恢复输入。

## 11. 结论

任务 03 的验收标准逐条成立：基础设施全部位于 `ProjectHero.Logic` 且通过无 Unity 引用检查；
阶段顺序可从代码与测试直接识别；强制位移拥有四个独立阶段槽；100 次重复运行哈希与事件完全一致；
历史记录数、增量摘要与独立重算一致，空归档 Tick 旧历史访问为 0；错误 Tick、重复 ID、非法排序键
均有稳定错误或拒绝事件；同一可信来源请求以不同枚举顺序输入得到一致的 Envelope、`CommandSequence`、
事件与快照；UI/AI 可见 API 中不存在可填写来源优先级、发行者、生产者序号、全局命令序号、规则费用
或反应 TriggerTick 的入口；`UnitId` 分配不依赖槽位枚举顺序；`UnitSnapshot` 保留 `FactionId`；
唯一关系解析器与定义哈希一致；没有新增 `SimulationState` / `Restore(...)` / 中途存档 / 任意跳转。
