# 02 - 程序集边界与纯数据定义

状态：待执行  
前置任务：01  
建议规模：1-3 天

## 执行目标

先建立不会被旧 `Assembly-CSharp` 反向依赖卡住的最小编译边界，并完成一个旧 ScriptableObject 到纯 C# 定义的兼容垂直切片。任务结束时，Unity 只要求把 `ProjectHero.Logic` 和 `ProjectHero.Logic.Tests` 建成独立 asmdef；Logic 不引用 `UnityEngine`，纯逻辑测试可由 Unity EditMode Test Runner 在不启动战斗场景的情况下运行，现有场景仍可运行。

本任务**不创建依赖旧类型的 `ProjectHero.Authoring` asmdef**。只要 `ActionLibrarySO`、`AttackPattern`、`UnitVolume` 等类型仍编译在预定义 `Assembly-CSharp` 中，读取它们的兼容适配器就必须暂留在 `Assembly-CSharp`，由旧程序集单向引用 `ProjectHero.Logic`。完整 Authoring 程序集、全资产 ID 迁移、`BattleDefinitionBuilder` 和战斗初始化链由任务 02B 完成。

## 本任务的过渡依赖方向

```text
Assembly-CSharp（旧代码与兼容适配器） ──→ ProjectHero.Logic

ProjectHero.Logic.Tests ──→ ProjectHero.Logic
```

`ProjectHero.Logic` 必须启用不引用引擎的边界；Logic 不得反向引用旧 `Assembly-CSharp`。Unity 不允许 asmdef 自定义程序集引用预定义 `Assembly-CSharp`，因此不得把“读取旧资产类型”的转换器提前放入 `ProjectHero.Authoring` 后再尝试引用旧代码。

最终的 `UnityView → Authoring → Logic` 依赖方向仍是目标，但分两次落地：任务 02B 在搬迁完整 Authoring 依赖闭包后创建 `ProjectHero.Authoring`；任务 10 在搬迁表现依赖闭包后创建 `ProjectHero.UnityView`。

`ProjectHero.Logic.Tests` 是 Unity EditMode 测试程序集。它只引用 Logic，被测生产代码保持纯 C#，但首版测试仍由 Unity Test Runner 启动；这不违反逻辑与表现解耦。独立 SDK 风格的 `.NET` 测试工程不属于本任务完成条件，未来只有在需要无 Unity CI、服务器模拟或独立战斗工具时才单独评估。

## 必须产出

1. 建立以下实际程序集：
   - `ProjectHero.Logic`
   - `ProjectHero.Logic.Tests`
   同时记录 `ProjectHero.Authoring` 与 `ProjectHero.UnityView` 的最终依赖草图，但本任务不要求创建这两个 asmdef。
2. 在 Logic 中定义最小不可变数据模型，至少覆盖动作标识、抽象 `ActionTimingSpec`、动作 Payload、预算/肾上腺素成本、离散目标、`TargetRelationMask` 和标签。分别定义 `AttackTimingSpec`、`GuardTimingSpec`、`MoveTimingSpec`、`BlockReactionTimingSpec`、`DodgeReactionTimingSpec`；不得把攻击时序隐式套用到其他动作。攻击 Payload 使用 `DamageComponents[] + ImpactProfileId + ForceMultiplier + AllowedTargetRelations`，Guard 使用分通道部分伤害抵抗与部分动量抵抗，Block 使用合格标签的完全抵抗，Move/Dodge 使用离散移动 Pattern。Logic 数据不得持有 Unity 对象。
3. 在仍属于 `Assembly-CSharp` 的兼容层中建立一个配置转换垂直切片：把一条现有动作资产转换成 Logic 定义，并在加载边界只做一次 `seconds -> ticks` 量化。旧攻击资产的 `BaseTime` 明确迁移为 `BaseWindupSeconds`；独立后摇秒数若缺失则使用 `DefaultAttackRecoveryTicks = 30`，不得继续由运行时调度器硬编码 `0.5f`。该适配器只证明接口可用，不替代任务 02B 的全资产迁移。
4. 建立自动化边界检查，防止 Logic 源码或程序集引用 `UnityEngine`。
5. 保留现有场景兼容入口，避免一次性搬迁全部旧脚本。
6. 在 Logic 中定义配置 ID 值类型：`UnitDefinitionId`、`ActionSpecId`、`VolumeSpecId`、`AttackPatternId`、`MovementPatternId`、`ActionSetId`、`DamageChannelId`、`ImpactProfileId`、`StatusEffectSpecId`、`EncounterDefinitionId`、`EncounterSlotId`、`FactionId`；底层为字符串，格式统一为小写英文字母、数字、点和下划线。
7. 在 Logic 中定义战斗实例 ID 值类型：`UnitId`、`ActionPlanId`、`ReactionOpportunityId`、`WindowId`、`EffectId`；底层为 `long`，0 保留为无效值，首个有效值为 1。不同 ID 类型之间不得隐式转换。
8. 建立最小 `EncounterUnitSlot` 纯数据定义及兼容转换接缝：包含不可空 `FactionId`，验证 SlotId 非空且唯一，并使用 `StringComparer.Ordinal` 排序；同时冻结 `FactionDisposition(Allied/Neutral/Hostile)`、`UnitRelation(Self/Allied/Neutral/Hostile)` 与 `TargetRelationMask` 的数值编码。本任务只冻结纯数据输入，不提前实现完整关系矩阵 Builder 或战斗创建器。
9. 在 Logic 单位定义或初始快照中提供 `Mass`、`MomentumSpeed`、`MoveSpeed`、按 `DamageChannelId` 索引的 `BaseDamageResistanceQ10`、`AvailableAdrenaline` 与 `AdrenalineCycleId`；反应预留是按 ActionPlan 归属、带 `ReservationCycleId` 的独立数据。兼容适配器把旧 `TotalMass`、`Swiftness` 和护甲/魔抗字段一次性映射；旧单一护甲公式只写入明确物理通道，不再生成通用 `DamageReduction`。
10. 冻结全部动作时序的版本化定义输入：攻击的 `ReferenceActionSpeed = 20` / 默认后摇、移动的 `ReferenceMoveSpeed = 20` / 每权重单位 Tick、Guard 的 Windup/Active/Recovery、Block/Dodge 的 ReactionWindup/Recovery、`RoundHalfUp` 舍入方式全部进入 `BattleDefinitionHash`。本任务只提供定义和校验，运行时解析由任务 05/06 完成。
11. 验证所有 TimingSpec Tick 为正整数，兼容映射后的 `ActionSpeed` / `MoveSpeed` 为有限正数，Move 的 `MaxPathWeightUnits` 为正且不超过规则搜索上限，基础抵抗范围为 `[0,1024]`，Guard 对已配置合格通道和动量的动作抵抗严格位于 `[1,1023]`，Block 的合格抵抗固定为 1024 且不可由 Authoring 降低，伤害分量有限非负；Attack/Guard/Move 的 `AdrenalineCost` 必须为 0，Block/Dodge 成本必须为正。旧逐边 `0.2-4.0s` 浮点 Clamp 不进入 New 定义；非法配置使用稳定原因码拒绝，不得钳制后继续模拟。
12. 定义 `ReactionOpportunity` / 按 ActionSpecId 排序且各自带截止 Tick 的 `ReactionOption`、判别式 `CommandScope` 所需纯数据、`Reactable/Blockable/Dodgeable` 等反应标签，以及伤害的 `Blockable/Guardable/BypassPassiveResistance/BypassActionResistance` 标签、`ReactionRules(CommandIngressLeadTicks, MinimumReactionLeadTicks)` 和 `AdrenalineRules(MaxAvailablePerCycle, DamageDealtGainQ10, DamageReceivedGainQ10, SuccessfulBlockReward, SuccessfulDodgeReward, ClashReward)`；`true` 通道默认同时绕过被动/动作抵抗且不可 Guard/Block，矛盾标签必须拒绝。输入提前量/上限必须为正，获得率/奖励非负，每个反应成本不超过上限，Block/Dodge 成功奖励分别小于所有对应动作成本。机会运行时创建与命令处理留给任务 05/09。
13. 冻结带朝向离散几何的纯数据契约：`AttackPatternSpec` / `VolumeSpec` 持有严格按 `GridDirection 0 -> 11` 排列的 12 个 `DirectionalTriangleSet`；每个方向内 `TrianglePoint` 按 `(X,Y,T)` 去重和稳定排序。合法点必须满足 `T ∈ {-1,1}` 且 `X + Y + T` 为偶数。Authoring 的 60° 逆时针展开固定使用 `X'=(X-3Y-T)/2, Y'=(X+Y+T)/2, T'=-T` 的受检整数公式；Logic 运行时只按方向查表和整数平移，不暴露或调用任意角旋转、三角函数或浮点舍入。任务 02 只用一个真实 Pattern/Volume 切片证明接口和公式，完整资产展开、稳定错误与哈希由任务 02B 完成。
14. 定义纯数据 `PathCostRules` / `PathSearchRules` 契约：合法 `GridPoint` 满足 `X + Y` 为偶数；偶数 `GridDirection` 的 `StepWeightUnits = 1`、奇数方向为 2；启发函数版本固定为主方案 `3.8` 的非负整数公式；`MaxExpandedNodes`、`MaxPathWeightUnits`、`MaxPathEdges` 必须为正。Logic 类型只声明 checked `long` 成本、稳定失败码与哈希字段，不在本任务提前实现 Pathfinder。`MoveSpeed` 明确不属于路径成本输入。
15. 定义纯数据 `ForcedDisplacementProtocolVersion.SimultaneousStepV1 = 1` 与稳定 `ForcedDisplacementStopReason` 数值编码（`Completed=0`、`Boundary=1`、`StaticObstacle=2`、`OccupiedUnit=3`、`DestinationContention=4`、`DependencyCycle=5`、`VolumeOverlap=6`），并把协议版本纳入 `BattleRules` / `BattleDefinitionHash`。本任务只冻结“全 Tick 单批、逐格临时同时求解、每步使用一次规范方向增量且不读取 PathWeight、部分距离保留、同落点全败、依赖链只通向空格、不连锁推人、强制位移优先 Reservation、批量换位先于死亡”的版本标识和数据编码；求解器及运行时请求/结果由任务 08 实现。

## 工作步骤

1. 根据任务 01 的循环依赖清单，确认旧配置类型仍位于哪个预定义程序集；选择最小纯数据类型进入 Logic，不先移动高耦合 MonoBehaviour 或 ScriptableObject 依赖闭包。
2. 创建 Logic asmdef 与 EditMode 测试 asmdef，确认依赖方向和平台设置；运行测试时不得要求加载战斗场景。
3. 定义 Logic 侧值类型；坐标使用离散 `GridPoint` / `TrianglePoint` 等纯数据表示。
4. 定义 `DirectionalTriangleSet` 与 12 向索引不变量；在兼容边界实现受检整数展开，并验证旋转六次回到原点、每一步保持三角格合法性。该展开只能用于构建定义，不能成为 Logic Step 的运行时服务。
5. 在旧程序集兼容目录中，为 `ActionLibrarySO`、`AttackPattern`、`UnitVolume` 中至少一条真实配置建立转换器或 builder 接缝；攻击切片必须把 `BaseTime` 迁移成 `BaseWindupSeconds`，并显式产出 `AttackTimingSpec`；Pattern/Volume 切片必须从 East/EastNorth 基准产出规范 12 向整数表。
6. 明确 Tick、各动作 TimingSpec 以及主方案 `0.4.2.1` 的动量/伤害量化规则、舍入方式和非法配置错误；验证动作速度、移动速度、质量、动量速度、力度倍率、分通道伤害、标签、抵抗与反应成本。战斗开始后禁止再次从 float 秒或旧 MonoBehaviour 属性推导逻辑值。
7. 添加编译与边界测试，并运行现有主场景冒烟检查。
8. 建立集中 ID 校验器；禁止把显示名、GameObject 名、资源加载顺序或 Unity 实例 ID 转换成 Logic ID。
9. 输出 Authoring 依赖闭包清单，列明任务 02B 为创建 `ProjectHero.Authoring` 必须搬迁的旧类型、资产、引用者和 `.meta` 文件。

## 验收标准

- Unity 将 Logic 作为独立 asmdef 编译，源码搜索与程序集引用均没有 `UnityEngine`。
- EditMode 测试程序集只引用 Logic，不通过 UnityView 访问逻辑；纯逻辑测试无需加载战斗场景。
- 至少一个真实资产通过仍位于 `Assembly-CSharp` 的兼容适配器完成 `ScriptableObject -> 不可变 Logic 定义` 转换。
- 本任务没有创建一个反向引用预定义 `Assembly-CSharp` 的自定义 Authoring asmdef。
- 秒只存在于 Authoring 输入；Logic 中攻击定义使用整数 `BaseWindupTicks` / `RecoveryTicks`，不再保留含义不明的 `BaseTimeTicks`。攻击运行时解析值与预算字段也只能使用整数 Tick。
- `ReferenceActionSpeed`、默认后摇、舍入方式与攻击时序字段结构均参与 `BattleDefinitionHash`；任务 05 无需访问 ScriptableObject 即可解析计划时序。
- `AttackPatternSpec` / `VolumeSpec` 是完整、规范排序的 12 向纯整数表；一个真实 Pattern/Volume 切片可从 East/EastNorth 基准无浮点展开，非法三角格点被拒绝，Logic 消费端只需要方向索引与整数平移。
- `PathCostRules` 明确冻结偶数/奇数方向 1/2 权重，`PathSearchRules` 三个上限为正并参与定义哈希；MoveSpeed 不出现在任何路径成本或启发函数接口中。
- `ForcedDisplacementProtocolVersion` 与全部停止原因有纯 Logic 稳定编码并参与定义哈希；任务 08 不需要访问 Unity/Authoring 即可判断当前战斗是否使用 `SimultaneousStepV1`。
- 任务 08 所需的 `DamageComponents[]`、`ImpactProfileId`、`ForceMultiplier`、`Mass`、`MomentumSpeed`、分通道被动抵抗与动作抵抗均可从纯逻辑定义或快照读取，无需访问旧 MonoBehaviour；不存在通用 `DamageReduction`。
- FactionId、FactionDisposition、UnitRelation 与 TargetRelationMask 是纯 Logic 稳定类型；Attack Payload 能显式携带非空目标关系掩码，任务 02B 无需重新发明编码。
- Guard/Move/Block/Dodge 均有独立 TimingSpec 和 Payload；反应标签、费用、最小提前量以及 Adrenaline 上限/伤害获得率/Block-Dodge-Clash 奖励参与定义哈希。
- 兼容壳没有复制一份可独立写入的战斗状态。
- 配置 ID 与战斗实例 ID 的类型、格式、0 值和比较规则与主方案 2.2 完全一致。

## 禁止事项

- 不在 Logic 中定义 Unity 类型别名或包装 `UnityEngine.Vector3` 规避检查。
- 不把旧 `GridMath.Rotate`、`Mathf.Sin/Cos`、浮点矩阵或舍入步骤带入 Logic 的 Pattern/Volume 查询路径。
- 不一次性移动所有 Core 文件。
- 不在旧配置类型仍属于 `Assembly-CSharp` 时创建依赖这些类型的 `ProjectHero.Authoring` asmdef。
- 不实现完整模拟循环、动作排程、窗口或仲裁。
- 不删除旧资产字段；本任务只建立转换边界。
- 不使用数字前缀编码对象类别，不为 GridPoint、MovementSegment 或 Reservation 创建多余的独立 ID。
- 不为了声明“无 Unity 环境测试”而复制 Logic 源码或在本任务新增独立 `.NET` 测试工程。
