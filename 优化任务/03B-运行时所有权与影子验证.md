# 03B - Unity 运行时所有权壳与 Shadow 验证

状态：待执行  
前置任务：02B、03  
建议规模：2-4 天

## 执行目标

在完整玩法迁移之前先消除“谁在推进战斗”的集成风险：让 `BattleRuntimeBootstrap` 成为场景中唯一通过 Unity `Update()` 选择并推进顶层战斗时钟的组件，把旧 `CombatDemo` / `BattleTimeline` 与最小新逻辑 Driver 都改成被调用适配器，并建立 `Legacy`、`Shadow`、`New` 三种启动模式和隐藏验证场景。

本任务完成后，主场景仍默认以 Legacy 规则运行，玩家可见行为不应改变；新模拟只在隐藏场景或 Shadow 模式中提前接入。它不是完整 UnityView 迁移，也不允许两套运行时同时写场景。

## 必读范围

- 主方案：目标架构、`2.1`、`2.1.1`、`3.3`、`3.4.0`、第三阶段与运行时相关风险
- [00 - 执行规则与依赖](00-执行规则与依赖.md)
- [02B - 完整配置、ID 迁移与战斗初始化](02B-完整配置与战斗初始化.md)的真实定义、Encounter、运行时输入和 Slot 映射契约
- [03 - 确定性内核、事件与规范化快照](03-确定性内核.md)的初始化、`Step()`、`StepResult`、事件、快照与哈希接口
- 任务 01 记录的全部运行时启动入口、场景/Prefab 引用和典型战斗基线
- `CombatDemo.Update()`、`BattleTimeline.AdvanceTime()`、`BattleManager.Update()` 及其他可能自主推进战斗的调用链

## 必须产出

1. **Unity 回调清单与基线**：
   - 扫描所有 `Update()` / `LateUpdate()` / Coroutine / Invoke / Timeline 回调中会推进旧或新战斗状态的入口。
   - 将入口分类为：顶层时钟/Timeline 推进者、Legacy 从属写入者、只读输入/表现回调；记录主场景、测试场景和 Prefab 中的挂载位置、调用目标、写入对象与时间来源。
   - `CombatDemo.Update()` / `BattleTimeline.AdvanceTime()` 属于本任务必须立即收拢的顶层时钟路径；`CombatUnit.Update()`、`BattleManager.Update()`、`EnemyAIController.Update()` 等已知旧逻辑回调先归入 Legacy 从属写入组，任务 04-10 再迁移其职责。
   - 改造前先保存 Legacy 典型场景的可复核行为和调用计数基线。
2. `BattleRuntimeMode`，至少包含 `Legacy`、`Shadow`、`New`。模式必须在创建本场战斗前确定；活动战斗期间修改模式应明确拒绝，不能迁移运行中状态。
3. `BattleRuntimeBootstrap`：
   - 是场景中唯一通过 `Update()` 选择并推进顶层战斗时钟的组件。
   - 启动时验证场景中恰有一个 Bootstrap，且没有已知适配器仍启用自主推进。
   - 根据固定模式调用一个明确的帧适配器，不通过容器枚举顺序选择权威路径。
   - 显式控制 Legacy 从属写入组：Legacy/Shadow 按基线启用，New 全部禁用；未知或未分类的逻辑写入回调阻止 New 启动。
   - 负责暂停和销毁边界；每场战斗只能初始化、停止和释放一次。
   - Shadow 在 `Update()` 中推进两边，但只在同一 Bootstrap 的只读 `LateUpdate()` 检查点采样比较；该检查点不推进时钟、不写两边状态，并以显式脚本执行顺序晚于全部已登记 Legacy 写入者。
   - Bootstrap 与帧适配器契约不得依赖 Legacy 具体类型；接口和序列化绑定设计应允许任务 10 保留 `.meta` 搬入 UnityView，而 Legacy 在 `Assembly-CSharp` 实现该接口并经显式 `MonoBehaviour` 槽位校验/注入。
4. **Legacy 被调用适配器**：
   - 把当前 `CombatDemo.Update()` 中推进旧 Timeline 的职责提取成显式 `AdvanceFrame(float deltaTime)` 或语义等价入口。
   - `CombatDemo` 不再拥有自主战斗推进生命周期；Bootstrap 的 Legacy/Shadow 分支是旧 Timeline 的唯一调用者。
   - Legacy 保留迁移前的 `Time.deltaTime`、暂停、事件和场景写入语义，避免本任务提前改变玩法。
5. **最小 New 被调用适配器**：
   - 由 Bootstrap 显式调用，自身没有 `Update()`。
   - 用 `Time.unscaledDeltaTime` 累积固定 Tick，并调用任务 03 的唯一 `BattleSimulation.Step()`。
   - 能用任务 02B 的真实定义、Encounter 和 `BattleRuntimeInputs` 新建模拟，并消费最小 `StepResult`；本任务不要求绑定正式 View、UI 或完整反馈。
6. **Shadow runner**：
   - Legacy 仍是唯一场景权威和唯一反馈来源。
   - 新模拟使用独立 Logic 世界，从相同定义、Encounter、运行时输入和当前阶段可镜像的请求创建；不持有旧可变对象或 View 引用。
   - 任务 09 完成前允许只覆盖空 Tick 和固定的可信测试请求，但必须预留显式请求镜像接口；任务 04-09 每完成一个子系统都扩展对应输入与检查点。
   - 比较按逻辑 Tick 或具名检查点对齐，不以 Unity 帧序号或容器枚举顺序强行配对。等价性用例固定 `timeScale = 1`；视觉时间缩放隔离另设用例验证。
   - 暂时无法在只读检查点前稳定采样的旧字段必须标记为“暂不可比较”，记录具体 Legacy 对象路径、字段、原因、负责迁移的任务和最迟清零门槛；不得直接转成永久批准差异。
   - 隐藏等价性场景使用固定、可重复的帧时间序列。记录 Shadow 每帧/每 Tick 耗时与 backlog；超出诊断预算时把本次比较标记为无效并停止宣称等价，但不得丢逻辑 Tick、修改 Legacy 的 `deltaTime` 或切换权威路径。
7. `ShadowComparisonReport` 或等价结构，至少记录：
   - BattleDefinitionHash、Encounter、运行模式、输入摘要和比较配置版本。
   - 首个非预期差异的逻辑 Tick/检查点、字段路径、旧值摘要、新值摘要和相关事件序号。
   - “必须相等的基础设施事实”“按新规则验证的事实”“限期清零的暂不可比较字段”“逐用例批准差异”四类结果。
   - 批准差异的用例 ID、RulesVersion、精确字段和原因；禁止忽略整类事件、全部血量、全部位置或任意后续差异。
8. **场景接入**：
   - 主战斗场景只挂载一个 Bootstrap，并默认选择 Legacy；玩家可见基线不改变。
   - 新增一个不进入正式内容流的隐藏验证场景，使用任务 02B 真实初始化链运行 Legacy/Shadow/New 三模式测试。
   - 场景或 Prefab 中发现重复 Bootstrap、重复旧顶层推进器、未分类逻辑写入回调，或 New 中仍启用 Legacy 从属写入者时，测试失败并列出对象路径。
9. **可观察调用计数**：测试可直接证明每种模式调用了哪条顶层推进路径、哪条路径为 0、Legacy 从属写入组是否正确启停，以及 Shadow 新模拟的 Unity/旧状态/反馈写入数为 0；不得只靠日志文本推断。

## 模式契约

| 模式 | 旧运行时 | 新模拟 | 场景/反馈写入 |
|------|----------|--------|---------------|
| Legacy | Bootstrap 调用；Legacy 从属写入组启用 | 不创建、不推进 | 只有完整旧运行组 |
| Shadow | Bootstrap 调用；Legacy 从属写入组启用 | 独立推进并比较 | 仍只有完整旧运行组；新模拟零写入 |
| New | 调用数为 0；Legacy 从属写入组禁用 | Bootstrap 通过最小 Driver 调用 | 本任务仅隐藏验证场景；主场景切换留给任务 10 |

所谓“可回切”只表示销毁当前战斗后，用同一入口以另一模式创建一场新战斗。不得尝试把 Legacy 的运行中对象、Tick、RNG 或计划复制到 New，反向亦然。

## 验收标准

- 顶层战斗时钟只由唯一 Bootstrap 调度；所有旧逻辑回调均已分类，Legacy 从属写入组在 Legacy/Shadow 启用且在 New 全部禁用；代码扫描、场景扫描与调用计数三类证据一致。
- 主场景默认 Legacy，迁移前可见行为和旧时间语义不因本任务改变。
- Shadow 新模拟对 Unity 对象、旧运行时状态和表现反馈的写入次数为 0。
- New 隐藏场景只调用任务 03 的 Step，旧 `BattleTimeline.AdvanceTime()` 调用次数为 0。
- 模式在战斗生命周期内不可变；停止后重新创建另一模式的战斗可成功。
- Shadow 报告能定位首个非预期差异，批准差异精确到用例与字段，不存在宽泛白名单。
- 只读 LateUpdate 检查点的执行顺序有自动化证据；暂不可比较字段都有对象路径、负责任务和清零门槛，并在任务 10 切换前归零。
- 后续任务可在不改 Bootstrap 所有权模型的前提下扩展新模拟与 Shadow 检查。

## 禁止事项

- 不让 Legacy、Shadow 或 New 适配器各自实现 `Update()`、Coroutine 或其他自主顶层时钟推进机制。
- 不把尚未迁移的 Legacy 逻辑写入误标为表现回调，也不允许未分类写入者在 New 启动。
- 不在 Shadow 模式绑定正式 View、消费为表现反馈、修改旧组件字段或让新模拟决定胜负界面。
- 不在同一场战斗中热切换模式或迁移运行中状态。
- 不在 Legacy 从属写入尚未完成的 `Update()` 中提前比较，也不把采样顺序造成的偏差登记为玩法差异。
- 不为降低 Shadow 开销而跳过新模拟 Tick、篡改 Legacy 时间输入、减少比较字段后继续报告通过，或把 Shadow 设为正式发行默认模式。
- 不为了让比较通过而忽略整类事件、血量、位置或首个差异后的全部结果。
- 不把测试夹具定义当作正式场景初始化链，也不在运行时补 ID、默认值或旧资产转换。
- 不提前迁移完整表现层、重做 UI 或删除 Legacy 启动路径。
