# 03 - 确定性内核、事件与规范化快照

状态：待执行  
前置任务：02B  
建议规模：2-3 天

## 执行目标

建立纯 C# 模拟入口和确定性基础设施：固定 Tick 阶段、单调 ID、稳定命令批次、版本化 RNG、语义事件 Outbox、规范化快照与哈希，以及从相同初始输入由 Tick 0 重演的最小确定性夹具。该任务还必须冻结一个可由普通 C# 调用者显式驱动的生命周期边界，供任务 03B 在不依赖 Unity 生命周期和不接触内部可变状态的前提下创建、推进、观察与销毁模拟。该任务只搭建可验证骨架，不提前实现完整动作、窗口、网格、仲裁或中途恢复规则。

## 必须冻结的 Step 阶段

```text
0. 应用全局动作的命令前边界
1. 推进状态与持续效果
2. 处理死亡和胜负；战斗结束则进入唯一终态清理并输出最终结果
3. 战斗未结束时打开到期的提交窗口（先执行拥有者个人周期肾上腺素清零）
4. 刷新此前已公开 ReactionOpportunity 的来源失效/已过期状态；尚未锁定并启动的 Editable Attack 不得提前公开，截止 Tick 本身仍可响应
5. 合并 Step 开始前已经冻结的玩家与 AI 当前 Tick 请求，同时冻结 BatchBaseScheduleRevision，并按稳定键排序；本阶段不得生成并执行同 Tick AI 请求
6. 按 ScheduleEdit/Window/Reaction scope 校验命令；原子应用 Editable 普通计划的 Add/Move/Remove 与预算/空间重算，创建固定 Locked 反应计划，随后关闭到截止点仍未接受的既有机会
7. 对 StartTick 等于本 Tick 的 Editable 普通计划执行启动门禁：Startable 才原子完成执行数据冻结、预算消费、Locked→Running；Retryable 先用同一 ScheduleEvaluator 做系统自动延期并向右 ripple；Terminal 经统一协调器清理；InvariantViolation 明确令 Step 失败。随后处理到期固定 Locked 反应（永不延期）；新 Attack 原子启动后才公开 Telegraph/ReactionOpportunity，然后处理本 Tick 反应 Trigger
8. 取出本 Tick 全部到期 Intent
9. 按稳定键原子提交到期 Dodge 目的格，并冻结旧格/新格/失败原因记录
10. 基于 Dodge 提交后的 LogicGrid 与提交记录构建规范化冲突图，以连通分量为组计算 Resolution
11. 按稳定顺序提交其余 Resolution，按 UnitId 一次性应用规范聚合的肾上腺素获得事实，再执行动作后边界；Dodge 位置不得重复提交
12. 再处理死亡
13. 再评估胜负；战斗结束则进入唯一终态清理
14. 战斗未结束时正式关闭已请求关闭的窗口并排定下一窗口
15. AI 读取与玩家将看到的同一只读决策快照，只经注册入口投递到下一 Tick
16. 运行只读 Step 末不变量检查，再输出 EventBatch 与规范化 Snapshot；结束 Tick 缓存最终快照
```

尚未实现的系统用明确的空实现或小接口占位，但阶段不得合并成依赖容器遍历的隐式调用链。

## 必须产出

1. `BattleSimulation.Step(long tick, FrozenCommandBatch externalBatch)` 或语义等价的唯一模拟入口。`FrozenCommandBatch` 只能由 Logic 的入口注册表创建；驱动器不能伪造其中的来源事实。
2. 命令确定性骨架：
   - 生产者只能创建 `CommandRequest(TargetTick, CommandScope, Payload)`；排程编辑使用 `ScheduleEditScope(ExpectedScheduleRevision, ExpectedWindowId?)`，关闭/并发命令使用 `WindowCommandScope(ExpectedWindowId)`，反应命令使用 `ReactionCommandScope(ReactionOpportunityId)`。任何请求都不能声明反应 TriggerTick。
   - `CommandIngressRegistry` 使用任务 02B 的 `ControllerBinding` 创建入口，固定绑定 `ControllerId` / `CommandSourceKind`，并分配每入口严格递增的 `ProducerOrdinal`；外部入口不得注册为 `System`。
   - 可信来源请求和内部 `CommandEnvelope` 的构造器对生产者不可见；Envelope 中的 `SourcePriority` 由规则映射派生，`CommandSequence` 只由 `CommandGateway` 分配。
   - `CommandGateway` 冻结、校验、规范化并生成可处理 Envelope；为任务 09 预留基于权威控制映射的载荷授权接口。
3. 活动战斗期间严格递增 Tick；空 Tick 也返回 `StepResult`。战斗结束后的误调用不采纳新 Tick，而是返回缓存的最终快照。
4. 单调 ID/Sequence 生成器：实例 ID 至少覆盖 Unit、ActionPlan、ReactionOpportunity、Window、Effect；Sequence 至少覆盖 Command、Intent、Resolution、Event、Effect 顺序。每类计数器独立，从 1 开始，0 保留为无效值，战斗内不复用。
5. 版本化 `DeterministicRng`；当前 RNG 状态必须进入规范化快照与哈希，随机选择前候选集必须稳定排序。首版不要求公开从中途 RNG 状态恢复模拟的 API。
6. 不可变 `LogicEvent`、`EventBatch` 与 `LogicEventOutbox`；事件序号整场战斗单调递增。
7. 只读、规范化 `LogicSnapshot` 与稳定哈希；集合在序列化和哈希前按契约排序。单位快照从首版就包含 `FactionId`；动作系统接入后计划快照必须包含 `AutomaticDeferralCount`。它是观察/校验模型，不是完整 `SimulationState`，不能作为 `BattleSimulation` 的构造或恢复输入。
8. 命令时间桶边界：入口默认按目标 Tick 分桶，`Step` 只接收当前 Tick 的冻结批次，错误 Tick 不得静默丢弃。规范化快照必须包含入口注册、每入口下一个/已冻结 `ProducerOrdinal`、未来 Tick 桶、下一个 `CommandSequence` 和全局 `ScheduleRevision`，用于尽早检测未来行为偏差。
9. `StepStatus` 至少区分 `Advanced`、`BattleEnded` 和 `AlreadyEnded`；结束后误调用返回空事件批次与缓存的最终快照。
10. `BattleEndSnapshot` 至少包含 Active/Ended、EndedAtTick 和 ResultCode，并参与规范化哈希。
11. Step 末只读不变量检查扩展点；参与者显式装配且顺序固定，不得修改逻辑状态。任务 05 将在这里检查活动索引、Lane、Intent、MovementSegment 和 Reservation 不引用终态 ActionPlan。
12. 从任务 02B 的不可变 `FactionModelDefinition` 创建整场唯一只读 `FactionRelationResolver`。Canonical/Decision Snapshot 中的单位均保留 FactionId；Decision API 可以提供只读 `Classify/Allows` 结果，但不得复制可被 UI/AI 修改的关系矩阵。静态矩阵由 Replay Header 的 BattleDefinitionHash 锁定，不逐 Tick 重复成为可变状态。
12. 冻结轻量 Tick 0 回放数据契约：独立 `ReplayFormatVersion`、包含 RulesVersion/定义哈希/Encounter/完整运行时输入/首个 Step 前 `InitialStateHash` 的 Header，以及“玩家请求按原始提交 Tick 记录，AI/System 由逻辑重建”的输入边界。任务 03 只需用最小夹具证明契约，不实现播放器或产品 UI。
13. 冻结任务 03B 可消费的显式调用边界：
   - 只通过任务 02B 初始化器由完整 `BattleDefinition`、Encounter 和 `BattleRuntimeInputs` 创建一场新模拟，并在首个 Step 前读取 `InitialStateHash`。
   - 调用者只能提交当前 Tick 的冻结输入并取得不可变 `StepResult`、`EventBatch`、`LogicSnapshot` 和哈希；不得取得 Logic 内部集合或写接口。
   - 明确定义 `Create -> Step* -> End/Stop -> Dispose` 语义；重复停止/释放幂等，释放后 Step 明确拒绝。
   - 接口不接受 `deltaTime`、MonoBehaviour、GameObject、View 或回调式表现依赖。帧时间到 Tick 的累积属于任务 03B/10 的外部适配器。

## 核心契约

- 生产者不得填写 `ControllerId`、`CommandSourceKind`、`SourcePriority`、`ProducerOrdinal` 或 `CommandSequence`；载荷也不得携带应由规则读取的费用。注册入口是来源身份的唯一信任边界。
- `CommandScope` 是判别联合：普通 Add/Move/Remove 只能使用 ScheduleEdit scope，关窗/并发激活只能使用 Window scope，Block/Dodge 只能使用 Reaction scope；scope 与 payload 不匹配必须稳定拒绝，不能回退到当前窗口或按攻击者临时查找机会。
- 网关先按首版固定映射 `Player = 0`、`AI = 10`、`System = 20` 从 `CommandSourceKind` 派生版本化 `SourcePriority`，再按 `SourcePriority -> ControllerId（StringComparer.Ordinal）-> ProducerOrdinal` 规范化。`System` 只允许 Logic 内部稳定来源；原始集合枚举顺序不得作为隐式末级键。映射变化必须更新 RulesVersion、定义哈希和 golden snapshot。
- 同一规范键重复时，整个碰撞组以 `DUPLICATE_COMMAND_ORDINAL` 拒绝，不能选择“先枚举者”；低于入口已冻结水位的序号以 `COMMAND_ORDINAL_REGRESSION` 拒绝。入口级组拒绝的事件/诊断顺序必须独立于碰撞成员的原始排列。
- 入口级非法键尚未获得 Envelope，不得伪造 `CommandSequence`。每个非法规范键只产生一个按组键排序的 `CommandIngressRejectedEvent`，记录 Controller、SourceKind、ProducerOrdinal、原因和碰撞数量，不选择或回显某个成员 Payload。
- 只有通过入口校验的请求才按规范顺序获得整场唯一、单调且不复用的 `CommandSequence`；处理器严格按该序号执行。该顺序也是预算、Lane、ActionPlan 和 Reservation 等竞争资源的统一提交顺序，后处理命令不得按另一套优先级抢占已提交资源。
- Intent 排序使用 `Tick -> InteractionPriority -> IntentSequence`。
- EventBatch 在 Tick 末一次性对外可见；表现订阅不能在 Step 中回写。
- 规范化快照必须包含所有 ID/Sequence 的下一个值和 RNG 状态，而不只是单位表面数据；这些字段用于观察与哈希，不构成首版恢复契约。
- 后续每个系统必须把所有会影响未来结果的权威状态扩展进规范化快照并补确定性测试；不得因为首版不支持恢复而省略 AI 决策时钟、活动效果、授权、资源或未来请求桶等内部状态。
- 规范化 Canonical Snapshot 与面向 Controller 的 DecisionSnapshot 必须分型：前者覆盖全部权威状态用于哈希，后者可按授权/公开规则过滤。任务 05/09 接入后，其他 Controller 的 Editable 普通计划不得出现在决策快照中；不得为了 UI 方便直接暴露 Canonical Snapshot。
- 任务 05/07/09 接入后，快照必须增加 ScheduleRevision、ActionPlan 的 Editable/Locked/Running 状态与创建/编辑/锁定 Tick、`AutomaticDeferralCount`、投影/冻结 Timing、窗口预算预留，按 ID 排序的 ReactionOpportunity、反应计划 TriggerBinding、可用/预留肾上腺素、目的格预留及 `NextReactionOpportunityId`；ScheduleRevision 注释必须覆盖成功的命令排程事务与系统自动延期事务，不能只写“玩家编辑”；任务 03 先为这些扩展冻结规范化接口。
- 固定参战单位按 `EncounterSlotId` 的 `StringComparer.Ordinal` 顺序分配 UnitId；动态单位按规范化命令处理顺序调用同一个 `NextUnitId()`。死亡、取消或集合清理不得使任何实例 ID 回退或复用。
- 动态单位创建还必须从任务 02B 的固定/显式继承策略得到 FactionId；解析后的 FactionId 与 UnitId 同时成为创建事实并进入 UnitSnapshot，入口、Controller 或 View 不能覆盖。
- `MovementSegment` 以 `(ActionPlanId, StepIndex)` 定位，Reservation 归属于 ActionPlanId；不得新增同义的 SegmentId 或 ReservationId。
- 同一规则版本、相同定义、初始状态、命令与 RNG 种子必须得到相同快照哈希和事件序列。
- `Time.frameCount`、`Time.time`、`deltaTime`、`GetHashCode()` 与无序容器遍历不得成为逻辑输入或排序键。
- `BattleSimulation` 不实现 `Update()`、Coroutine 或定时器，也不自行读取 Unity 帧时间；每次推进都必须由外部显式调用唯一 `Step()`。
- 严格递增 Tick 契约只适用于活动战斗；进入终态后，后续 `Step()` 不验证或采纳传入 Tick，不推进 Tick、RNG、ID、Sequence，也不重复发事件。
- 任务 03 先冻结可扩展的 `BattleEndFinalizer` 阶段和幂等结果缓存；任务 05 建立统一 ActionPlan 终态协调器后，Finalizer 必须按 ActionPlanId 复用该入口，不能让计划、Lane、Intent、MovementSegment 和 Reservation 各自在 Finalizer 中复制清理。窗口、命令桶等非计划对象仍通过各自显式钩子接入唯一 Finalizer。

## 验收标准

- 所有基础设施位于 Logic 程序集并通过无 Unity 引用检查。
- Step 的阶段顺序可从代码和测试直接识别，不依赖注释猜测。
- 100 次重复运行的空内核/最小夹具哈希与事件完全一致。
- 错误 Tick、重复 ID、非法排序键等失败路径有稳定错误或拒绝事件。
- 相同可信来源请求以不同集合枚举顺序输入时，内部 Envelope、`CommandSequence`、事件和快照一致；重复键没有隐式赢家。
- UI/AI 可见 API 中不存在可填写来源优先级、发行者、生产者序号、全局命令序号、规则费用或反应 TriggerTick 的入口。
- UnitId 分配不依赖槽位输入枚举顺序、GameObject 名称或 Unity 注册顺序。
- UnitSnapshot 保留任务 02B 初始化/动态生成时解析得到的 FactionId；控制入口注册不会覆盖或派生阵营。唯一关系解析器与定义哈希一致，Canonical/Decision 查询对相同单位对返回相同 Self/Allied/Neutral/Hostile 结果。
- 后续系统可接入既定阶段，无需另建第二个模拟入口。
- 任务 03B 可仅凭公开初始化、Step、只读结果和释放接口驱动隐藏验证场景，无需反射或访问 Logic 内部可变对象。
- 后续系统可在 Step 输出前接入固定顺序的只读不变量检查，不依赖事件订阅或容器注册顺序。
- 结束 Tick 与结束后误调用的状态码、事件批次、快照和计数器语义均可由测试直接识别。
- 任务没有新增 `SimulationState`、`BattleSimulation.Restore(...)`、中途存档/载入或任意 Tick 跳转 API；相同输入的确定性通过两次新建模拟并从 Tick 0 运行来证明。

## 禁止事项

- 不把 `TurnWindow` 作为 ActionPlan 容器占位。
- 不为了演示完整流程而把动作、网格和仲裁写成不可替换的临时代码。
- 不在事件中加入震屏强度、顿帧秒数、Animator 参数等表现数据。
- 不宣称跨规则版本得到相同回放结果。
- 不把 `LogicSnapshot` 设计成首版恢复格式，不实现中途恢复、任意跳转、周期性完整状态检查点或玩家回放 UI。
- 不在任务 03 实现录制管理、播放控制或回放产品；这里只冻结任务 11 将消费的数据边界。
- 不在 Logic 中加入 MonoBehaviour、`Update()`、帧累加器、View 绑定或 Shadow 对旧运行时的引用；任务 03B 只在外部适配这些接口。

## 交接重点

交接必须列出 Step 阶段扩展点、BatchBaseScheduleRevision 冻结点、状态到期/排程编辑先于启动门禁、启动门禁先于 Intent、反应机会刷新/截止/Trigger 插槽、Step 末只读不变量检查入口、`CommandRequest -> CommandIngress -> CommandGateway -> internal CommandEnvelope` 边界、ScheduleEdit/Window/Reaction scope 判别、来源注册与授权扩展点、重复/回退拒绝语义、所有排序键、配置 ID 与实例 ID 类型、全部 ID/Sequence/ProducerOrdinal 计数器、UnitId/FactionId 初始与动态分配规则、唯一 FactionRelationResolver 及 DecisionSnapshot 只读查询边界、入口/ID/RNG 规范化快照格式、哈希算法边界、`ReplayFormatVersion` 与 Tick 0 重演契约，供任务 04-09 直接接入；还必须单列供任务 03B 使用的创建/Step/停止/释放接口、首个 Step 前哈希读取时机、不可变结果边界和失败语义，使其无需访问内部 mutator 即可建立 New/Shadow 适配器；同时明确 `LogicSnapshot` 不提供恢复保证。
