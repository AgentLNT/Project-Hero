# 04 - 单位状态、持续效果、死亡与胜负

状态：待执行  
前置任务：03B  
建议规模：2-3 天

## 执行目标

把分散的状态 bool 收敛为单一 `UnitStateMachine`，并将状态到期、持续效果、死亡和胜负统一纳入固定 Tick 阶段。状态机描述单位当前状态，但不接管 ActorLane 的新动作接受权。

## 必读范围

- 主方案：`3.4.1-3.4.3`、`3.5`、`3.10`、风险中的浮点范围与窗口解耦
- [00 - 执行规则与依赖](00-执行规则与依赖.md)
- 任务 03 交接的 Step 阶段、事件与快照接口
- 任务 03B 交接的隐藏验证场景、Shadow 比较配置、独立性约束与当前批准差异

## 必须产出

1. `UnitState` 与 `UnitStateMachine`，覆盖 Idle、Windup、Recovery、Moving、Guarding、Blocking、Dodging、Staggered、KnockedDown、Recovering、Dead。
2. 明确的转换矩阵、持续 Tick、半开时间区间和 `NextOnExpire`；显式转换与自动到期走同一入口并发射同类事件。
   - 为任务 05 提供只读启动阻塞事实：当前控制状态、是否有有限结束 Tick、`BlockingUntilTick`。状态机只报告事实，不自行延期/终止计划，也不改 ActorLane。
3. 定义仅供尚未被特殊交互消解的直接 Hit 结算使用的 `CanReceiveDirectHit`；状态机不得提供或暗示一个同时控制特殊交互参与资格的通用 `IsTargetableByInteraction`。
4. Dead 为终态；死亡系统按 UnitId 稳定处理，并为每个单位只发出一次确定的生命周期清理通知。任务 05 必须消费该通知，按 ActionPlanId 通过统一终态协调器终止死者全部非终态计划（包括 Editable、Locked 与 Running），而不是只清理“未来计划”或直接删除从属对象。
5. `BuffSystem` / 持续效果最小内核：每个可独立移除/到期的实例拥有 `EffectId`，配置类型使用 `StatusEffectSpecId`；按 `AppliedAtTick -> EffectSequence` 稳定推进，遍历中的增删进入延迟队列。完整配置扩展与 Unity 表现接入留到第六阶段，后续必须复用本内核，不得再建立第二套效果推进器。
6. 死亡与胜负阶段：
   - 状态/持续效果后、到期窗口打开与命令前处理一次。
   - Resolution 的伤害、全 Tick 强制位移批量换位、位移事件、状态/控制提交完成后再处理一次；同 Tick 已致死单位也先保留占位参与同时位移求解，批量换位后才进入 Dead 并移除最终 footprint。
   - 胜负均先于窗口推进。
7. 状态、效果、生命值、死亡和胜负进入事件与快照。
8. 胜负系统只读取任务 02B 初始化到运行时单位的 `FactionId` 和 Encounter 的 `VictoryDefinition`：Allied/Hostile 目标组任一侧无存活单位时按配置产生 Victory/Defeat；双方在同一死亡阶段均无存活单位时产生 Draw。它不得扫描 `FactionDisposition` 动态重建目标组；关系矩阵只由 Builder 用来验证 Allied 组内部互为 Allied、跨组 Hostile，Hostile 组内部可保持任意关系。胜负系统只确定 `ResultCode` 并触发任务 03 的统一 Finalizer，不直接发射 `BattleEndedEvent`；最终事件必须等待后续系统的终态清理钩子全部完成后发射。
9. 扩展任务 03B 的 Shadow 检查点，至少覆盖状态转换、持续效果到期、死亡与胜负；旧规则与新规则预期不同的字段必须按具体用例登记，不能扩大忽略范围。

## 核心规则

- 状态机不提供“能否提交新动作”的权威判断。后续 `ActorLane` 必须独立实现提交规则，不能从 Idle 或其他状态直接推导。
- `CanReceiveDirectHit` 只回答尚未被特殊交互消解的接触能否在 Remaining Hit 阶段进入直接命中结算；Remaining Hit 是处理阶段名称，不是独立攻击类型。`Guarding`、`Blocking`、`Dodging` 均返回 true：Guard 的部分抵抗来自计划 Active 区间，Block 的完全抵抗来自匹配 TriggerTick 的反应 Intent，Dodge 的避伤来自 TriggerTick 原子换格后的空间复核，状态本身不提供免伤。
- Block/Dodge 只在其来源机会决定的 TriggerTick 产生特殊交互，不拥有持续免伤区间。Block 对合格载荷归零，Dodge 只使新位置不再命中的接触失效；二者不终止来源攻击，也不影响同一 AOE 的其他目标。
- 首版继续让 `Staggered`、`KnockedDown`、`Recovering` 返回 `CanReceiveDirectHit == false`。以后若加入倒地追击，应作为直接命中规则变更单独修改并更新 golden snapshot。
- 持续区间使用 `[AppliedAtTick, AppliedAtTick + DurationTicks)`；到期 Tick 先移除，不额外触发一次效果。
- 自动状态转换必须使用当前逻辑 Tick，不使用动画事件或 Update 计时。
- Tick T 的状态自动到期发生在任务 05 的 StartTick=T 启动门禁之前；有限阻塞查询返回的恢复 Tick 必须来自状态实例的权威结束边界，不能用“下一 Tick再试”代替。
- 首版保持单一互斥状态。若出现“边移动边攻击”的未来需求，另行设计正交状态机，不在本任务提前扩展。
- 生命和伤害可暂时保留集中管理的 float，但不得由 `deltaTime` 推进；分支阈值和快照格式必须有测试。
- 死亡系统负责 Dead 状态、存活视图和单位最终占位移除；它只发出稳定生命周期通知，不直接修改 ActionPlan、Intent、MovementSegment、Reservation 或 ActorLane。Resolution 阶段必须先完成任务 08 的强制位移批量提交，死亡系统只读取换位后的最终位置并移除该 footprint；不得因为本 Tick 生命值已降到 0 而让单位提前退出同时空间求解。计划从属对象由任务 05 的统一终态协调器清理。
- `FactionId` 与 Controller/窗口归属正交且进入 UnitSnapshot；胜负按 VictoryDefinition 中的 FactionId 目标组规范聚合，不得读取 `IsPlayerControlled` 或用关系矩阵临时扩张目标组。未列入两侧的目标外阵营不阻止消灭条件完成，但也不会因此被关系解析器视为 Neutral。

## 验收标准

- 旧 bool 不再是新 Logic 路径的权威状态；兼容属性只能从状态机派生读取。
- 所有状态与效果推进发生在 Step 中，动画和 Update 不可改变状态结果。
- 死亡处理不依赖任何窗口归属；后续动作与窗口任务只能通过一次性的稳定清理通知接入，且任务 05 能据此终止死者全部 Editable/Locked/Running 计划。
- Resolution 后死亡处理严格读取同 Tick `ApplyBatchRelocation` 已提交的最终位置；位移事件先于死亡事件，死亡占位移除不能改变该批其他单位的成功/失败结果。
- 胜负结果只有一个终态入口；`BattleEndedEvent` 不会由胜负系统和 Finalizer 重复发射。
- UnitSnapshot 保留初始化/动态生成时解析的 FactionId；改变 ControllerBinding、玩家标志或当前窗口拥有者不会改变同一存活集合的胜负结果。目标外阵营的存活不阻止结果，也不修改其关系；同 Tick 双灭稳定得到 Draw。
- 相同效果插入顺序变化不改变结果和事件序列。
- 任务 08 只在 Remaining Hit 阶段查询 `CanReceiveDirectHit`；Guard/Block/Dodge 的效果不得由该属性实现或提前过滤。Guard 必须读取 Active 区间和抵抗配置，Block/Dodge 必须读取有效机会绑定与 TriggerTick；所有结果再通过统一转换/死亡入口提交。
- 对应隐藏场景/Shadow 用例已重跑，状态、效果、死亡与胜负的差异全部按用例和字段分类；新模拟仍零 Unity/旧状态/反馈写入。

## 禁止事项

- 不把 `CanExecuteImmediately` 当作 ActorLane 接受新计划的判断。
- 不允许 Dead 自动恢复到 Idle。
- 不让 Buff 回调在遍历中直接修改活动集合。
- 不在窗口关闭时统一结算状态或动作。
- 不由 Animator 回调成为状态权威来源。
- 不让状态机直接移动、终止或锁定 ActionPlan；它只向启动门禁提供当前状态与有限结束 Tick。
- 不使用 `IsPlayerControlled`、Controller 类型或窗口拥有者区分胜负阵营。
- 不遍历 FactionDisposition 推导或扩张 VictoryDefinition，也不把目标外阵营统一重写为 Neutral。

## 交接重点

交接必须冻结包含 Guarding/Blocking/Dodging 的转换矩阵、这些状态不自带免伤的契约、到期区间、只读有限启动阻塞查询、死亡清理通知的一次性与 UnitId 排序语义、Resolution 后“伤害/合力聚合 → 同时强制位移 → 位移事件 → 状态/控制 → 死亡”的阶段边界、同 Tick 致死单位仍参与位移且从最终位置移除 footprint 的规则、FactionId/FactionDisposition/Victory 目标组的职责边界、基于 FactionId/VictoryDefinition 的胜负与同 Tick Draw 矩阵、目标外阵营语义、胜负阶段顺序、效果排序键、仍保留的旧字段兼容方式，以及本任务新增的 Shadow 检查点、报告结果和精确批准差异。任务 05 必须用该通知锁定 Lane，并按 ActionPlanId 将死者全部非终态计划交给统一终态协调器；它还必须在状态到期阶段之后读取阻塞事实完成启动门禁，不能只处理未来计划、直接清理计划从属对象，或把提交/延期判断塞回状态机。
