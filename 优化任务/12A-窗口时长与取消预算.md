# 12A - 窗口固定时长与取消时间预算（R1）

状态：已完成（2026-10-14）。全量 EditMode 889/889、PlayMode 61/61 通过；交接、逐项测试迁移、哈希及 Shadow 证据见 [12A 交接记录](执行记录/12A-交接记录.md)。

前置任务：01～11 已完成（2026-10-10 非性能收尾）。本任务是 2026-10-13 规则修订迁移的第一包，后续依次为 [12B](12B-防御时序与反应占用.md)、[12C](12C-肾上腺素公开与收尾.md)。
建议规模：4-6 天

## 执行目标

按主方案开头的 **R1** 修订，把回合窗口从"费用预算"改为"固定打开时长"，具体包括四项：

1. 窗口覆盖 `[OpenedAtTick, EndTick)`，到期自动关闭，下一窗口在 `EndTick` 打开。
2. 普通动作的 `StartTick` 必须落在当前窗口内，动作本身可以延伸到窗口之外。
3. 删除窗口预算的额度、预留、消费账本和由预算触发的关闭。
4. 删除玩家和 AI 主动结束窗口的能力。

肾上腺素、并发授权、反应机会和连续时间轴的其他不变量保持不变。Guard/Block/Dodge 的时序不在本包范围，属于 12B。

## 冻结语义

| 项 | 规则 |
|---|---|
| 窗口区间 | `TurnWindow` 新增 `DurationTicks`（来自 `TurnSubmissionDefinition.WindowDurationTicks`，主场景 180），`EndTick = OpenedAtTick + DurationTicks`，区间半开 |
| 接受提交 | Step k（`OpenedAtTick ≤ k < EndTick`）中处理的命令，可新增 `k ≤ StartTick < EndTick` 的普通计划。这与 00 第 28 条一致：Step k 先应用目标为 k 的排程编辑，再评估 `StartTick = k` 的计划 |
| 到期关闭 | Step `EndTick − 1` 的第 17 阶段以新原因 `Expired` 关闭窗口；下一窗口最早在 Step `EndTick` 打开。在顺序、存活单位都不变时，窗口首尾相接，没有空隙也没有重叠 |
| 关闭原因 | 只剩 `Expired`、`OwnerDied`、`BattleEnded`。枚举数值参与哈希，**不得重排或复用**：`OwnerRequested = 0` 和 `BudgetExhausted = 3` 保留为"已废止、永不产生"，`Expired` 取新值 4 |
| 主动关闭命令 | 从命令面删除 `WindowCommandKind.CloseOwnWindow`，但数值 0 保留不复用，`ActivateConcurrentAction` 仍为 1。网关对 kind 0 稳定拒绝，拒绝码为 `WINDOW_CLOSE_NOT_PERMITTED`。`WindowCommandScope` 保留给并发激活使用 |
| 来源窗口 | 普通计划的 `SubmittedWindowId` 保留，语义改为"来源窗口"，不再表示预算来源 |
| 显式编辑 | Add，以及任何改变 `StartTick` 的编辑（拖动、移动链重算、向右避让），结果的 `StartTick` 都必须在来源窗口内，否则整个事务拒绝，拒绝码为 `SCHEDULE_START_OUTSIDE_SOURCE_WINDOW`。Add 还要校验 `ExpectedWindowId`、当前窗口开放以及提交授权（拥有者或并发授权）。Remove 只校验控制权、Editable 状态和修订号 |
| 系统延期 | `ActionStartGate` 返回 Retryable 时，若 `RetryAtTick ≥ 来源窗口 EndTick`，该计划不延期，而是以新的终止原因 `DelayedBeyondSourceWindow = 14` 经统一终态协调器终止。`ApplySystemAutoDeferral` 连带推移的依赖计划同样适用：只要任一计划越界，整个候选不提交，越界计划按此原因终止，其依赖按现有终态规则处理 |
| 窗口关闭不变量 | 窗口正式关闭时，不存在仍为 Editable、且 `SubmittedWindowId` 等于该窗口的普通计划。违反时报不变量错误，Step 失败，而不是静默终止 |
| 费用 | 普通动作没有时间费用。删除 `BudgetCostTicks`、`ReservedTurnBudgetTicks`，以及启动提交中的 `Reserved → Spent` 环节 |

## 原子性与边界

- 本包完成后，代码中不得残留任何"窗口预算"概念，包括类型、字段、事件、拒绝码、快照字段、UI 文案和注释。用 `budget`（不区分大小写）全仓扫描，逐条确认剩余命中都属于 Shadow 步进预算等无关概念，并在交接中列出这些命中。
- 窗口切换仍然不得查询、移动、锁定、取消或结算任何计划。到期关闭只把窗口设为不再接受提交；"关闭时没有残留 Editable 计划"是检查出来的不变量，不是关闭时执行的清理动作。
- 战斗结束 Finalizer 仍以 `BattleEnded` 关闭窗口并撤销并发授权；删除其中的预算清理步骤，肾上腺素清理不变。
- 拥有者死亡仍在本 Tick 请求关闭，下一窗口最早在下一 Tick 打开。此时窗口提前结束，起点晚于死亡时刻的普通计划属于这个死亡单位，由死亡流程终止，不另设规则。
- 并发授权的语义不变，但并发授权提交的计划，其来源窗口就是当前窗口，起点受该窗口区间约束。
