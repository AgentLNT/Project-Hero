# 09 - 命令入口、AI 与输入模式

状态：待执行  
前置任务：07、08  
建议规模：3-5 天

## 执行目标

建立唯一的逻辑命令入口，把设备输入和 AI 都降为命令生产者。普通动作的原子时间线编辑、威胁绑定反应、窗口关闭和并发授权经过同一排序、校验、拒绝与记录流程；UI 选择/拖拽状态不再通过布尔标志直接控制战斗逻辑。

## 必读范围

- 主方案：`3.6`、`3.9`、`3.4.3` 的命令阶段、`0.5`
- [00 - 执行规则与依赖](00-执行规则与依赖.md)
- 任务 03B 交接的请求镜像接口、隐藏验证场景、Shadow 比较配置和零写入约束
- 任务 02B 的 ControllerBinding / ConcurrentActionDefinition 与任务 03 的 CommandIngress / CommandGateway / 快照契约
- 任务 07 的授权/拒绝码与任务 08 的动作结果接口

## 必须产出

1. 不可变 `CommandRequest`：只包含 `TargetTick`、判别式 `CommandScope` 和 `BattleCommand` 载荷。`ScheduleEditScope` 携带 `ExpectedScheduleRevision` 与可空 `ExpectedWindowId`；`WindowCommandScope` 携带 `ExpectedWindowId`；`ReactionCommandScope` 携带 `ReactionOpportunityId`。UI/AI 可创建该类型，但其中不存在 `ControllerId`、来源、优先级、生产者序号、全局命令序号、规则费用或 BlockTick/EvadeTick。
2. `CommandIngressRegistry` 与不透明 `FrozenCommandBatch`：
   - 使用任务 02B 初始化的 `ControllerBinding` 创建玩家/AI 入口，入口固定绑定 `ControllerId` / `CommandSourceKind`。
   - 每个入口分配严格递增 `ProducerOrdinal`，按目标 Tick 分桶并冻结；调用方不能构造可信来源请求，也不能注册 `System` 来源。
   - 过期、结束后、重复或回退的提交有稳定结果；入口状态进入规范化快照与哈希。
3. 复用并完成任务 03 的 `CommandGateway`：
   - 从来源类型派生版本化 `SourcePriority`。
   - 按 `SourcePriority -> ControllerId（StringComparer.Ordinal）-> ProducerOrdinal` 规范化；重复键整组拒绝，原始集合顺序不能选择赢家。
   - 为有效请求分配整场唯一、单调、不复用的 `CommandSequence`，生成仅 Logic 内部可构造的 `CommandEnvelope`。
4. 至少支持：
   - `ScheduleEditCommand`，包含稳定顺序的 `AddOrdinaryPlan` / `MoveEditablePlan` / `RemoveEditablePlan`
   - `ReactionCommand`
   - `CloseTurnWindowCommand`
   - `ActivateConcurrentCommand`
   - Add 操作携带可空 `RequestedStartTick`（null=本次事务 Lane 尾部）、可空插入锚点、Facing、离散 Destination 和 `PrimaryTargetUnitId`；Move 携带 PlanId、请求 Tick 与可空锚点；Remove 只携带 PlanId。`PrimaryTargetOnly` 缺少目标、目标不存在/已死，或唯一 FactionRelationResolver 的分类不在该 Attack `AllowedTargetRelations` 中时，分别以稳定原因拒绝；关系不允许固定使用 `TARGET_RELATION_NOT_ALLOWED`，且不得自动换目标。
   - `ReactionCommand` 只携带 `DefenderUnitId`、`ReactionActionSpecId` 和 Dodge 可选目的格；它必须搭配 Reaction scope，不能携带 TriggerTick、WindowId 或费用。Block 不得带目的格，Dodge 必须带合法目的格。
   - `ActivateConcurrentCommand` 只携带 `PlayerUnitId`，不携带费用；费用由任务 07 的权威能力定义读取。
5. 命令时间桶：设备输入默认投递到 `CurrentTick + 1`；Step 只收到当前 Tick 的不透明冻结批次；过期和错误 Tick 生成稳定拒绝，不静默丢弃。Tick N 快照产生的 N+1 ScheduleEdit 必须在 N+1 到期计划启动门禁前处理，批次冻结后的输入只能目标 N+2。
6. `BattleCommandProcessor`：所有来源走同一入口。处理每种载荷前，使用权威 `ControllerId -> UnitId 集合` 验证发行者可控制其涉及单位；ScheduleEdit 调用任务 05/07 的统一 ScheduleEditor。
7. ScheduleEdit 总是把 `ExpectedScheduleRevision` 与目标 Step 冻结时的 BatchBaseScheduleRevision 比较，并重新校验计划状态和控制权。同一批互不相交 Lane 可依序成功；触及本批已改写依赖闭包的后处理事务按 CommandSequence 拒绝。Add、预算增加或新增占用还把 `ExpectedWindowId` 传入规则侧校验窗口/普通提交授权。既有计划成本增加时该 ID 必须同时等于其 SubmittedWindowId，首版不能跨窗口转移预算。纯 Move/Remove 在成本不增加时不要求原窗口仍打开。
   所有反应命令都把 `ReactionOpportunityId` 传给任务 05 的 ReactionPlanner，并重新校验机会/选项截止、来源威胁、ActionSet、控制权、状态/Lane、任务 06 目的格和任务 07 肾上腺素；不得检查当前窗口或并发授权。
8. 输入模式状态机：选择单位、选择动作、选择方向/目标、取消与时间线放置/重排属于 UnityView；另提供 `ReactionSelection` 和 `DodgeDestinationSelection`。本地草稿可包含多次鼠标移动、吸附和预览，但只有确认后的原子 Operations 进入 ScheduleEditCommand。UI 可用 DecisionSnapshot 的只读关系查询按当前 ActionSpec 掩码展示 Self/Allied/Neutral/Hostile 候选，但展示不是授权，确认时 Logic 必须重验。UI 只能从开放 Opportunity 选择 Block，或为 Dodge 选择 Logic 校验的目的格；不得在时间线拖放/编辑 TriggerTick。
9. `AIControllerLogic`：Step N 完成后读取与玩家同时公开的只读决策快照，只创建 `TargetTick = N + 1` 的 `CommandRequest` 并经其已注册入口提交；Step N+1 开始时与玩家请求一起冻结，不能读取 N+1 新机会后同 Tick 抢跑。普通攻击候选逐 ActionSpec 使用与处理器相同的 `FactionRelationResolver + AllowedTargetRelations`，再按 ActionSpecId/TargetUnitId 稳定排序；AI 不保存由 Controller 类型推导的永久敌人。普通动作候选可生成 Add/Move/Remove 的 ScheduleEditCommand，Move 候选与玩家预览/提交必须调用任务 06 的同一 Pathfinder/PathResult，不能用距离、速度或自建权重估算路线；反应候选仍生成 ReactionCommand。候选稳定排序后才使用版本化确定性 RNG。AI 不能创建 Envelope、机会、计划或分配任一顺序字段，也不能绕过 ScheduleRevision。
10. AI 仅在拥有当前窗口提交权限且 Lane 接受时提出新增/增费普通动作；它可按控制权编辑自身仍为 Editable 的计划，但仍经相同修订号和锁定检查。只要受控单位拥有有效 ReactionOpportunity，便可在任何单位窗口提出 Block/Dodge。处理器重新校验全部条件。AI 和玩家的理论动作可用性都来自同一 ActionSet。
11. 命令接受/拒绝事件与回放输入记录：首版权威回放输入只记录入口绑定后的 Player Controller/来源/ProducerOrdinal + Request。时间线本地草稿、鼠标轨迹、吸附预览不记录；成功或拒绝的 ScheduleEditCommand 记录最终 Operations、目标 Tick 与 ExpectedScheduleRevision。启动门禁的系统自动延期是逻辑输出事件，不是 CommandRequest/System 输入；AI/System 由逻辑重建，若额外记录其请求或 Envelope，只能用于差异诊断，回放时不得再次注入。
12. 战斗结束后的命令入口立即返回 `BATTLE_ALREADY_ENDED`；请求不进入 Tick 桶、不分配 ProducerOrdinal/CommandSequence，也不进入回放命令流。
13. 如果状态/持续效果在命令阶段前结束战斗，本 Tick 已冻结的请求仍经网关规范化、分配 `CommandSequence` 并按序返回 `BATTLE_ENDED_BEFORE_COMMAND_PHASE`；未来 Tick 桶由 Finalizer 清空，二者都不得被静默吞掉。
14. “取消当前手势/关闭行动面板”仍只是 UnityView 状态；“删除时间线中的 Editable 普通计划”则编码为 `RemoveEditablePlan`，经过同一入口、修订号、控制权与原子事务，并只调用任务 05 的统一终态协调器。Locked/Running/反应计划不能用该操作删除；不得直接删除 Plan、Intent、MovementSegment、Reservation 或 Lane 项。
15. AI 的未来决策状态（至少包括 `nextThinkTick`；若以后增加记忆、冷却或计划游标也同样适用）必须进入规范化快照与哈希；回放时 AI 由相同初始输入和 RNG 从 Tick 0 重新生成，不直接载入记录的 AI 命令作为权威输入。
16. 完成任务 03B 预留的真实请求镜像：Shadow 只镜像入口接受的玩家可信请求及其原始提交 Tick，AI/System 在新模拟内重建，不把诊断轨迹二次注入；比较命令接受/拒绝、顺序、AI 决策检查点和最终事实。
17. `DecisionSnapshot` 按 Controller 过滤：只公开该 Controller 可控制单位的 Editable 计划与可编辑字段；其他 Controller 的普通计划在锁定并按玩法公开前不得泄露 ActionSpec、目标、Destination 或精确 Tick。开发者 Canonical Snapshot 仍可包含全部权威状态用于哈希。

## 核心命令语义

- ScheduleEdit 携带采样时看到的 `ExpectedScheduleRevision`；与目标 Step 的 BatchBase 不匹配时返回 `STALE_SCHEDULE_REVISION` 并拒绝整批。同一冻结批次内玩家/AI 的互不相交事务不会仅因前一事务令全局修订 +1 而过期；重叠依赖则返回 `SCHEDULE_EDIT_CONFLICT_IN_BATCH`。全部显式命令处理完成后，启动门禁的成功系统自动延期可再令全局修订 +1；该变化出现在本 Step 输出快照，供下一 Tick UI/AI 采样，不能反向使本批已处理命令过期。Add/增费还携带 `ExpectedWindowId`，处理时窗口已变化或停止接收时返回 `STALE_OR_CLOSED_WINDOW`。这些版本字段只校验采纳时权限，不进入 ActionPlan 后续执行条件。
- 反应请求携带已公开的 `ReactionOpportunityId`。处理时机会关闭、来源失效、选项过期或 scope/payload 不匹配时返回各自稳定拒绝码；系统不能改用“当前最近攻击”或把过期请求顺延。
- 设备输入与 AI 默认只能提交到 `CurrentTick + 1`，因此任务 02B/05 必须保证 Reactable 攻击的 Telegraph/Impact 间隔满足最小输入往返和所选 ReactionWindup；不满足者根本不生成该反应选项。
- 玩家和 AI 的差异只体现在已注册的来源类型与生产策略，不体现在动作接受实现；`SourcePriority` 由网关规则映射派生，生产者不可填写。
- 载荷中的单位 ID 只表达意图目标，不证明权限。发行者身份来自入口绑定，`CommandAuthority` 必须验证它能控制载荷涉及的单位。
- 并发能力费用从 `BattleDefinition.ConcurrentAction` 读取，其他权威规则值从定义/规则状态读取；任何命令字段都不能降低或提高实际消费。
- AI 没有可接受动作时可以生成关闭窗口命令，但不能直接调用 TurnWindowManager。
- AI 对每个机会可以选择不响应、Block 或 Dodge；评分至少可读取预计分通道伤害、动量、可用目的格、肾上腺素成本和 Lane Recovery，但选择结果最终只表现为标准 ReactionCommand。首版不允许 AI 直接“完美命中时机”，因为时机由机会统一推导。
- 暂停期间入口不得生成或积压战斗命令；暂停边界的 Unity 驱动由任务 10 实现。
- `StepStatus.BattleEnded` 返回后必须关闭命令入口；结束后的拒绝是入口返回值，不通过再次推进 `Step()` 生成新的逻辑事件。
- UI 的“返回/取消选择”不是战斗命令；删除 Editable 计划是可回放的 RemoveEditablePlan，并复用统一终态入口，释放未消费预算预留但不自动左移后续计划。锁定后的取消仍只能来自明确的战斗交互/生命周期规则，首版不提供玩家撤销。
- 锁定线显示在快照 `CurrentTick + 1`；这不是 UI 自己判定权限。Logic 最终以命令目标 Tick、计划 State 和 Step 启动门禁阶段拒绝越线编辑，UI 只用于提前反馈。

## 验收标准

- 所有新战斗输入都能追溯为 `CommandRequest -> 已注册入口 -> 内部 CommandEnvelope`；没有输入回调直接修改血量、状态、位置、预算或计划。
- AI 不引用 `UnityEngine.Random`、Time、ActionScheduler 或 TurnWindowManager 的写入方法。
- 命令顺序、拒绝码、ProducerOrdinal 水位、CommandSequence 和 AI 未来决策状态可通过规范化快照观察、可测试、可由 Tick 0 重演复现；相同可信请求集合的原始排列不能改变任何竞争资源赢家。
- 生产者无法伪造 Controller/来源、提升优先级、选择全局序号、控制未授权单位或覆盖权威能力费用。
- 生产者无法填写反应 TriggerTick；Block/Dodge 只能由存在且未过期的 Opportunity 创建，玩家和 AI 经同一 ReactionPlanner，敌我身份不会改变 ActionSet 规则。
- UI、AI 预筛选与命令处理对相同单位对/ActionSpec 使用同一个 Self/Allied/Neutral/Hostile 分类和 AllowedTargetRelations；Controller 来源变化不改变资格，非法目标以稳定码拒绝且不自动重选。
- 旧 `IgnoreUnitClicks` 等布尔通信不再控制新逻辑路径。
- WindowId 只出现在命令校验和审计字段，不成为动作生命周期边界。
- ScheduleRevision、锁定线与计划 State 共同关闭并发编辑；旧快照整批拒绝，UI/Logic 不做静默部分合并。系统自动延期后的新修订只由 Step 输出快照传播，UI/AI 不伪造或重复提交该事务。
- ReactionOpportunityId 只建立对已公开来源威胁的创建权限与审计绑定；实际 TriggerTick 由 Logic 从来源 ImpactTick 推导，不由命令或表现层维护。
- UI 手势取消只改变输入模式；删除 Editable 计划必须是 RemoveEditablePlan，不存在能绕过 CommandGateway、ScheduleEditor 和统一计划终态协调器的删除写入路径。
- 对应隐藏场景/Shadow 用例已重跑；玩家请求只镜像一次，AI/System 只由新模拟重建，命令/AI 差异全部可追溯且 Shadow 仍零写入。

## 禁止事项

- 不为并发行动建立单独动作调度器。
- 不让 AI 直接消费预算、添加计划或推进窗口。
- 不让 UI/AI 用 Controller、玩家标志、名称、Tag/Layer 或本地“敌人列表”替代 FactionRelationResolver，也不把友军伤害实现为绕过 ActionSpec 的独立开关。
- 不让 AI 直接消费肾上腺素、创建/关闭 ReactionOpportunity、推导 TriggerTick、写入 Dodge 逻辑位置或添加反应计划；AI 只能在 ReactionCommand 中选择 Logic 公布的合法目的格，由统一事务在 TriggerTick 提交位置。
- 不把鼠标位置、GameObject 或 ScriptableObject 放入逻辑命令。
- 不向 UI/AI 暴露可构造的可信来源请求或内部 `CommandEnvelope`，不接受其自报 Controller、来源、优先级、ProducerOrdinal、CommandSequence 或费用。
- 不静默修正过期命令到当前 Tick。
- 不把 Window scope 与 Reaction scope 混用，不在缺少机会时用攻击者/目标临时猜一个机会。
- 不让 UI 选择状态进入回放日志。
- 不让 UI/AI、旧时间线控件或命令处理器直接设置 ActionPlan 终态或删除其从属对象；RemoveEditablePlan 也只能请求任务 05 的统一终态入口。
- 不把鼠标拖动的每一帧包装成 ScheduleEditCommand，不让 UI 自己提交局部 ripple/移动链结果，也不允许旧修订“尽量合并”。
- 不向普通时间线暴露 Block/Dodge 的 Move/Remove/TriggerTick 编辑操作。

## 交接重点
