# 12B - 防御时序、反应占用与删除反击窗口（R2、R3）

状态：已完成（2026-10-14；[交接与验收](执行记录/12B-交接记录.md)，EditMode 929/929、PlayMode 65/65 通过）

前置任务：[12A](12A-窗口时长与取消预算.md)
建议规模：5-8 天

## 执行目标

按主方案开头的 **R2、R3**，迁移 Guard / Block / Dodge 的时序与生效方式。

| 动作 | 现状 | 迁移后 |
|---|---|---|
| Guard | 前摇 15 / Active 60 / 后摇 15，Active 区间内对每次接触按比例抵抗 | 无前后摇，整段 60 Tick 生效；每个有合格接触的 Tick 消耗抵抗额度，额度用完即终止 |
| Block | 起点 = 命中点 − 60，只在来源命中点判定一次，之后后摇 30 | 无前后摇，整段 60 Tick；控制者在 `[T+1, ImpactTick]` 内选起点；区间内**第一个**有合格接触的 Tick 生效一次后终止 |
| Dodge | 起点 = 命中点 − 30，只在来源命中点换位一次，之后后摇 30 | 同 Block，持续 30 Tick；落点在生效 Tick 复核 |
| 反应占用 | 整个反应区间都不允许与其他计划重叠 | 硬段 `[StartTick, ImpactTick]` 不可重叠；软段 `(ImpactTick, End)` 允许普通计划从中开始，届时未生效的反应以"让出轨道"终止 |
| 反击窗口 | 闪避成功时发出 `DodgeCounterWindowOpenedEvent`，但没有任何效果 | 删除 |

反应机会的公开条件、肾上腺素账本规则、冲突图阶段顺序和 Dodge 旧格/新格表都不变。

## 冻结语义

### 时序

| 项 | 规则 |
|---|---|
| 时序规格 | `GuardTimingSpec(int DurationTicks)`、`BlockReactionTimingSpec(int DurationTicks)`、`DodgeReactionTimingSpec(int DurationTicks)`。主场景默认值：Guard 60、Block 60、Dodge 30。哈希键改为 `guard_timing.duration_ticks`、`block_reaction.duration_ticks`、`dodge_reaction.duration_ticks` |
| 计划区间 | `EndTick = StartTick + DurationTicks`。删除 `ActiveStartTick`、`ActiveEndTick`、`ReactionWindupTicks` 及其快照字段。Guard 的状态全程为 `Guarding`；Block/Dodge 从 StartTick 起为 `Blocking`/`Dodging`，生效或终止时回到 Idle |
| 起点 | Guard 是普通动作，按 12A 的提交区间规则放置。Block/Dodge 的起点由命令给出：`ReactionCommandPayload` 新增 `long? StartTick`，缺省时取来源 `ImpactTick`，必须满足 `T+1 ≤ StartTick ≤ ImpactTick` 且 `StartTick + Duration > ImpactTick`；违反时稳定拒绝，拒绝码为 `REACTION_START_OUT_OF_RANGE` |
| 截止 | 每个选项的 `ResponseDeadlineTick = ImpactTick − CommandIngressLeadTicks`。公开条件仍为 `ResponseDeadlineTick ≥ TelegraphTick + CommandIngressLeadTicks`。删除 `ReactionWindupOf` 及旧公式 |

### 生效判定

| 动作 | 判定 |
|---|---|
| Guard | 在区间 `[StartTick, EndTick)` 内，每个对该单位存在至少一条合格接触的 Tick，按 R2 第 2 条计算实际比例：`实际 = min(配置比例, 剩余额度)`，按通道与动量分别计算，然后从额度中扣除各项实际比例的最大值，同 Tick 只扣一次。额度为 0 时，在该 Tick 结算后以 `GuardQuotaExhausted` 终止 |
| Block | 对每个处于区间内、尚未生效的 Block：在**本 Tick 的冲突图构建之后、Block 阶段之前**，判定是否存在指向该单位且带可格挡载荷的接触。存在则在本 Tick 生效（完全抵抗本 Tick 全部合格载荷），在组末以 `ReactionTriggered` 终止，并消费肾上腺素预留 |
| Dodge | 对每个处于区间内、尚未生效的 Dodge：在**换位前冻结旧接触之后、提交落点之前**，判定旧格是否存在可闪避接触。存在则本 Tick 生效：按稳定顺序复核落点并原子换位，按现行旧格/新格表判定，然后以 `ReactionTriggered` 终止，并消费预留。落点复核失败则判定为失败，照样消费并终止，不退款 |
| 合格接触 | 合格接触不限于来源攻击，只要满足阵营关系、标签和空间条件即可；更早到达的轻击同样会消耗反应 |
| 未生效 | 区间走完仍未生效，以 `ReactionExpired` 终止，不退款 |
| 让出轨道 | 若普通计划在软段内到达启动门禁时反应仍未生效，反应在启动门禁阶段先以 `ReactionYieldedLane` 终止，随后普通计划正常启动，不退款 |
| 来源取消 | 来源攻击在其 `ImpactTick` 之前（含）进入终态，且反应尚未生效时，沿用现行 `SourceThreatCancelled` 规则：同周期退还肾上腺素，并释放闪避落点预留 |

### Guard 不强过 Block 的校验（R2 第 2 条）

Builder / Validator 必须拒绝以下三种定义：

1. Guard 的任一通道 `DamageResistanceQ10 ≥ 1024`，或 `MomentumResistanceQ10 ≥ 1024`，拒绝码 `GUARD_RESISTANCE_NOT_BELOW_FULL`；
2. 任一伤害分量带 `DamageTagMask.Guardable` 但不带 `Blockable`，拒绝码 `GUARDABLE_COMPONENT_NOT_BLOCKABLE`；
3. 运行时同步修正一个现存漏洞：`TargetAggregator.BuildDefendedContact` 中 Guard 的动量抵抗目前不检查 `attackTags & AttackTagMask.Blockable`（[TargetAggregator.cs:412](../Assets/Scripts/Logic/Combat/TargetAggregator.cs)），导致 Guard 能减免不可格挡攻击的冲击。改为与 Block 相同的门槛。

### 占用

- `ActorLane` 的重叠判定区分硬段和软段。新计划与已有计划的**硬段**相交时拒绝；普通计划的起点可以落在已有反应的软段内，其余部分照常校验。
- 接受反应时只用硬段做冲突检查。原有的"Dodge 允许覆盖其自身将失效的移动族"容忍规则保留，并改为基于硬段判定。
- 预览与提交使用同一判定，不得两处分别实现。

## 原子性与边界

- Guard 额度扣减与该 Tick 的伤害聚合在同一提交边界内完成；额度不得为负，同一 Tick 多次接触只扣一次。
- Block/Dodge 的生效、肾上腺素消费、计划终止和成功奖励事实在同一 Tick 提交；失败路径（落点复核失败）同样只消费一次。
- 探测只读取本 Tick 已冻结的 Intent 与空间快照，不得用动画、`UnitState` 或上一 Tick 的结果推断。
- 输入排列不变性：同 Tick 多个攻击、多个反应、多个 Guard 的任意输入顺序，必须得到相同的生效 Tick、终止原因、额度余量、事件和哈希。
- 对软段的让出判定与普通计划的启动门禁在同一阶段内完成，不得让同一 Tick 内反应和普通计划同时处于 Running。

## 禁止事项

- 不得把"生效一次"实现成持续区间无敌，也不得用 `UnitState.Blocking/Dodging` 代替生效判定。
- 不得只让来源攻击触发反应。
- 不得在探测阶段修改任何状态；探测结果只在既定阶段提交。
- 不得让生产者通过 `StartTick` 以外的字段影响生效时刻。
- 不得在本包改变肾上腺素可见性（属于 12C）或窗口规则（属于 12A）。
